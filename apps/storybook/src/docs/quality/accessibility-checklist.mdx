# 접근성 체크리스트

이 문서는 story로 검증할 수 없는 서술형 기준만 모은다. 실행 가능한 계약은
해당 primitive story의 play test가 소유한다(`Components/UI/Field`,
`Components/UI/Progress`, `Components/UI/Tabs`).

## 오류 필드

오류 상태는 라벨, `aria-invalid`, `aria-describedby`를 함께 제공한다.

```tsx
<Field data-invalid>
  <FieldLabel htmlFor="title">제목</FieldLabel>
  <Input aria-describedby="title-error" aria-invalid="true" id="title" />
  <FieldError id="title-error">제목을 입력해야 한다.</FieldError>
</Field>
```

아래는 피해야 하는 형태다. placeholder는 접근 이름을 대신하지 못하고, 오류 문구가
입력과 연결되지 않아 스크린 리더가 원인을 읽지 못한다. axe의 `label` 규칙은
placeholder를 접근 이름으로 인정하므로 이 형태는 a11y gate로 걸러지지 않는다.
따라서 안티패턴은 story로 렌더하지 않고 문서로만 남긴다.

```tsx
<span>제목</span>
<Input aria-invalid="true" placeholder="오류만 표시" />
<p>제목을 입력해야 한다.</p>
```

## 키보드

| 키       | 동작                                                   |
| -------- | ------------------------------------------------------ |
| `Tab`    | 초점 순서가 시각 순서와 일치해야 한다.                 |
| `Space`  | 토글 버튼은 눌림 상태를 `aria-pressed`로 노출한다.     |
| `Escape` | 취소 가능한 overlay나 임시 상태는 닫을 수 있어야 한다. |
