# 프로젝트 지식 감사

저장소의 권위 소스와 영구 문서가 같은 현재 사실을 설명하는지 감사한다. 저장소는 수정하지 않고 모든 결과를 한국어로 보고한다.

## 실행 원칙

- 메인 에이전트는 문서와 권위 소스를 직접 대량 탐색하지 않는다.
- 반드시 전체 대화 이력을 상속하지 않는 감사 조정 서브에이전트 하나를 생성한다. 지원되는 환경에서는 `fork_turns: "none"`을 사용한다.
- 조정 에이전트에는 저장소 절대 경로, 이 `SKILL.md` 절대 경로, 사용자가 지정한 감사 범위만 전달한다.
- 조정 에이전트가 최대 3개의 하위 에이전트를 병렬로 사용하게 한다. 메인 에이전트가 하위 감사를 직접 분배하지 않는다.
- 전체 감사의 목표 시간은 5분, 하위 감사의 목표 시간은 각각 3분으로 제한한다. 시간이 지나면 추가 탐색을 중단하고 이미 확보한 증거만 종합한다.
- 각 하위 에이전트는 먼저 `rg`로 후보를 좁힌 뒤 권위 소스와 충돌 문장의 필요한 부분만 읽는다. 문서 전체를 순차적으로 정독하지 않는다.
- 서브에이전트를 사용할 수 없으면 메인 컨텍스트에서 대신 감사하지 말고 제약을 보고한다.
- 검증된 사실과 추론을 분리하고, 확정한 문제마다 권위 소스와 충돌 문서의 파일 및 라인을 제시한다.
- 감사 중 파일 생성, 수정, 이동, 삭제와 서버·감시 프로세스 실행을 하지 않는다. 읽기 전용 명령만 사용한다.

## 감사 절차

1. 조정 에이전트가 `AGENTS.md`, 이 `SKILL.md`, `docs/authority-map.md`를 먼저 읽게 한다.
2. `docs/authority-map.md`가 지정한 소유자에서 현재 사실을 확인하게 한다. 소유자가 없거나 모호하면 독립 문제로 보고하고 추측으로 확정하지 않는다.
3. 다음 범위를 최대 3개의 하위 에이전트에 병렬로 분배하게 한다.
   - 런타임과 배포: workspace, 앱, service, image, port, Compose, Caddy, release workflow
   - api 통일: 코드, 환경변수, 설정, 문서의 단일 `api` 명명과 제거된 별도 관리자 API 흔적
   - 지식 구조: root Markdown, 문서 index와 링크, 권위 소유권, 영구 문서와 한시 문서의 경계
4. 각 하위 에이전트가 담당 범위의 권위 소스와 관련 문서를 직접 비교하게 한다. 중간 결과를 메인 에이전트에 보내지 않는다.
5. 조정 에이전트가 중복을 제거하고 심각도와 영향에 따라 정렬한 최종 요약만 메인 에이전트에 반환하게 한다.

## 현재 사실 판정

다음 우선순위를 적용한다.

1. `docs/authority-map.md`가 지목한 권위 소스
2. 실제 manifest, configuration, code
3. 현재 유효한 영구 문서

`docs/work`는 진행 중인 계획과 조사 기록, `docs/archive`는 종료된 기록, `docs/engineering/adr`는 결정 당시의 근거로만 다룬다. 이들을 현재 구현 상태의 권위 소스로 사용하지 않는다. 다만 영구 문서가 이 문서들을 현재 사실의 근거로 잘못 인용하면 충돌로 보고한다.

`admin-api`, `ADMIN_API`, `adminApi`처럼 별도 관리자 API 실행 단위를 전제하는 이름을 찾는다. 관리자 기능의 `/admin` route와 `apps/admin` 프런트엔드는 단일 `api` 명명 위반으로 오인하지 않는다.

## 결과 형식

조정 에이전트의 반환을 다음 형식으로 제한한다.

- 감사 범위와 확인한 권위 소스
- 심각도별 문제 건수
- 최대 10개의 핵심 문제
  - 심각도
  - 검증된 현재 사실
  - 충돌하거나 근거가 부족한 주장
  - 양쪽의 파일 및 라인
  - 예상 영향
  - 최소 수정 권고
- 추론과 미확인 사항
- 문제가 없었던 감사 범위

10개를 초과한 문제는 심각도별 건수와 파일 목록으로 압축한다. 메인 에이전트는 원문을 다시 읽지 않고 이 요약을 사용자에게 전달한다.
