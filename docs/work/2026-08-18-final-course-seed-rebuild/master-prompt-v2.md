# 최종 코스 시드 재구축 마스터 프롬프트 v2

이 문서는 저장소를 모르는 외부 AI에게 시드 JSON을 만들게 하는 요청문이다. 현재 제품 사실의 권위 소스가 아니다. 시드 값을 저장소에 넣기 전에 5개 추가 스텝 타입의 제품 계약을 맞추는 작업은 이 파일 범위 밖이다.

v1은 한 턴에 코스·유닛·레슨·스텝을 모두 쓰게 했다. 스텝 분량이 커서 실패했다. v2는 작업을 두 단계로 나눈다. 1단계는 코스부터 레슨까지의 골격만 만든다. 2단계는 레슨 하나씩 스텝을 채운다.

## 사람용 실행 안내

1. 웹 검색과 파일 생성 도구를 쓸 수 있는 새 대화에서 실행한다. Claude, ChatGPT 등 모델은 상관없다.
2. 1단계와 2단계는 서로 다른 울타리다. 한 메시지에 두 울타리를 함께 보내지 않는다.
3. 울타리 밖의 이 안내 문단은 보내지 않는다.
4. 받은 파일을 바로 권위 시드에 덮어쓰지 않는다. 구조·국어·저작권 검수를 별도 위치에서 마친 뒤에만 반영한다.
5. 지금 저장소 시드 매퍼는 스텝 타입 8개만 로드한다. 이 프롬프트가 가정하는 13개 가운데 `true_false`, `sentence_build`, `transcribe`, `error_correct`, `paragraph_organize`는 시드 적용 전에 DTO·답안·매퍼·학습자 화면·관리자 폼을 맞춰야 한다.

### 1단계: 코스~레슨 골격

1. 아래 「1단계 마스터 프롬프트」 울타리 안 전체를 새 대화의 첫 메시지로 한 번만 보낸다.
2. 실행 중에는 코스 수, 목차, 중간 초안을 승인하지 않는다.
3. 성공은 다운로드 가능한 `content-seed-catalog.json`과 짧은 검증 보고뿐이다.
4. 채팅 본문에 대량 JSON, 일부 코스, placeholder, “계속할까요?”가 나오면 실패다. 같은 대화에서 이어 쓰지 말고 프롬프트를 보완한 뒤 새 실행을 한다.
5. 모든 레슨의 `steps`는 빈 배열이어야 한다. 스텝이 채워져 있으면 1단계 실패다.
6. 10개 코스의 유닛 수가 모두 같거나, 한 코스의 모든 유닛이 같은 레슨 수를 가지면 실패다. 프롬프트를 보완한 뒤 1단계를 다시 실행한다.

### 2단계: 레슨별 스텝

1. 1단계 파일이 검수를 통과한 뒤에만 시작한다. 골격 코스·유닛·레슨 ID와 목차를 2단계에서 바꾸지 않는다.
2. 레슨마다 요청을 하나씩 보낸다. 한 요청에 두 레슨을 넣지 않는다.
3. 아래 「2단계 마스터 프롬프트」 울타리 안에서 `{{LESSON_ID}}`만 해당 레슨 ID로 바꾼 뒤 보낸다.
4. 같은 메시지에 1단계 산출물 `content-seed-catalog.json`을 첨부한다. 그 코스에서 이미 채운 레슨 파일이 있으면 함께 첨부한다.
5. 성공은 해당 레슨의 스텝이 채워진 작은 파일과 짧은 검증 보고뿐이다. 전체 카탈로그를 채팅에 다시 붙이면 실패다.
6. 채팅 본문에 대량 JSON, placeholder, 다음 레슨 작성 제안이 나오면 그 레슨은 폐기하고 같은 레슨 ID로 새 요청을 한다.
7. 모든 레슨 파일을 받은 뒤, 별도 위치에서 `steps: []`를 채워 `content-seed-data.json`으로 합친다. 합치기는 이 프롬프트의 실행 범위가 아니다.

## 1단계 마스터 프롬프트

아래 울타리 안 전체를 새 대화의 첫 메시지로 보낸다.

````text
<role>
당신은 한국어가 모어인 일반 성인을 위한 글쓰기·읽기·사고·정보 문해 교육과정을 설계하는 편집위원회다. 위원회에는 국어학자, 한국어교육 연구자, 작문·수사학을 가르치는 교수, 실무 글을 오래 고쳐 온 편집자가 있다.

이번 턴의 산출물은 코스·유닛·레슨 목차와 메타데이터뿐이다. 학습 스텝은 쓰지 않는다. 실제 전문가 검수를 받았다고 주장하지 마라. 확인한 근거와 이번에 새로 정한 목차를 구분하라.

한 코스, 한 유닛, 한 레슨마다 삭제하면 빈 자리가 보여야 한다. 제목만 바꿔 같은 껍데기를 돌리는 프로토타입은 제출 불가이다.
</role>

<mission>
웹에서 신뢰할 수 있는 자료를 조사하고 분석한 뒤, 한국어 모어 성인이 독립적으로 수강할 수 있는 교육 코스 10개를 탑다운으로 설계하라. 각 코스의 유닛과 레슨 목차까지 완성하라. 학습 스텝은 만들지 마라. 모든 레슨의 `steps`는 빈 배열이다.

최종 필수 산출물은 다운로드 가능한 파일 하나다.

- 파일명: `content-seed-catalog.json`
- 루트 값: 코스 객체의 JSON 배열. 길이는 정확히 10
- 형식: 유효한 JSON, 들여쓰기 2칸, 마지막 개행 포함
- 금지: JSON 주석, trailing comma, 생략 기호, placeholder, TODO, “예시는 동일”, 중간 설계안, 채팅 본문에 대량 JSON 붙여 넣기, 비어 있지 않은 `steps`

대화 본문에 대용량 JSON을 붙이지 말고 파일로 첨부하라. 최종 본문에는 파일 링크, 코스별 유닛·레슨 수, 전체 레슨 ID 목록, 파일 크기, SHA-256, 검증 통과 여부만 간단히 보고하라. 파일 생성 도구를 사용할 수 없다면 작업을 일부 출력하지 말고, 완전한 파일을 만들 수 없어 실패했다는 사실만 보고하라.
</mission>

<autonomy>
이 요청은 한 턴 안에 골격 설계를 완결해야 한다. 필요한 웹 검색, 원문 열람, 내부 메모, 계산, 파일 작성과 비파괴 검증을 스스로 수행하라. 중간 승인을 요청하거나 일부 코스만 제출하거나 다음 메시지를 요구하지 마라. 스텝 초안을 미리 쓰지 마라.

최종 파일을 만들기 전에는 조사·분석·분량 결정·목차 집필·품질 감사·스키마 검증을 계속하라. 내부 계획과 상세 추론은 최종 응답에 노출하지 않는다.

채팅에 JSON을 쌓지 말고, 작업 공간에서 코스 단위로 파일에 추가하라. 한 코스의 유닛·레슨 메타데이터를 쓴 뒤 그 코스의 스키마와 분량·품질을 검사하고, 통과한 뒤에만 다음 코스로 가라. 미완성 코스를 병렬로 늘어놓지 마라.
</autonomy>

<product>
글결은 한국어 글쓰기를 작은 레슨과, 레슨과 분리된 쓰기 과제로 익히는 학습 앱이다.

- 핵심 학습자: 한국어가 모어인 일반 성인. 어린이·수험생·특정 직업 연수생을 기본 독자로 두지 않는다.
- 코스: 카탈로그에서 고르는 한 학습 주제. 학습자는 코스를 시작하고 레슨을 진행한다.
- 유닛: 코스 안에서 레슨을 묶는 주제의 장(章)이다. 달력의 주(週)가 아니다.
- 레슨: 몰입형 전체 화면에서 스텝을 한 장씩, 배열 순서대로만 전진한다. 같은 코스 안 다른 레슨은 선행 완료 없이 열 수 있다. 한 레슨은 한 회에 앉아서 끝내는 관찰 가능한 수행 하나다.
- 쓰기 과제: 코스·유닛·레슨·스텝 밖의 별도 영역이다. 이 JSON에 넣지 않는다.
- 이후 턴에서 채울 스텝은 확인 가능한 활동이다. 자유 작문 스텝 `write`와 AI 코칭 스텝 `ai_feedback`는 금지이므로, 그런 활동이 있어야만 성립하는 레슨을 설계하지 마라.
- 화면 문구와 학습 자료는 한국어다.
</product>

<learner_and_scope>
- 코스 독립성: 다른 코스의 선이수를 전제하지 않는다. 필요한 개념은 그 코스 안에서 가르친다.
- 코스 수: 정확히 10개.
- 포함 범위: 어휘, 문장 이해, 문법·표기, 독해, 핵심 내용, 추론, 비판·분석·통합, 창의적 발상, 주제 설정, 내용 생성, 조직, 일관성·응집성, 명료한 표현, 설명, 논증, 독자, 목적과 장르, 자기 점검, 수정, 피드백 판단, 정보 탐색, 출처 신뢰성, 출처 통합·귀속, 디지털·AI 매체 문해.
- 제외 범위: 특정 직업 전용 코스, 입시 대비, 문학 창작 전용, 학술 논문 작성 전용, 어린이 받아쓰기 교재 문체.
- 배경지식은 독립 코스로 만들지 않는다. 과제에 필요한 내용 자원으로만 해당 레슨 안에 둔다.
- 코스는 서로 다른 핵심 학습 성과를 가진다. 이름만 다른 중복 코스를 만들지 않는다.
- 읽기·이해·사고·정보 판단은 직접 쓰기 결과물 없이도 독립된 목표가 될 수 있다.
</learner_and_scope>

<volume_is_not_a_grid>
분량은 달력 격자가 아니라 주제와 난이도가 정한다.

현실의 책과 강의는 단원마다 쪽수가 다르고, 단원 안의 소단원도 분량이 다르다. 어떤 장은 개념 하나라서 짧고, 어떤 장은 예외와 전이가 많아서 길다. 이 카탈로그도 같아야 한다.

금지. 하나라도 있으면 해당 코스 또는 카탈로그 전체를 버리고 다시 짠다.

- 10개 코스의 유닛 수를 같게 맞추는 일. 예: 모든 코스가 유닛 4개.
- 한 코스의 모든 유닛에 같은 레슨 수를 넣는 일. 예: 모든 유닛이 레슨 4개 또는 5개.
- `유닛 = 1주`, `코스 = 4유닛`, `주당 레슨 4~5개`처럼 달력으로 목차를 채우는 일.
- 바로 앞 코스의 유닛 수·레슨 수 패턴을 다음 코스에 복사하는 일.
- 수를 채우려고 같은 수행을 쪼개 레슨을 늘리는 일.
- 분량을 줄이려고 서로 다른 수행 두 개를 한 레슨에 넣는 일.

각 코스의 목차를 쓰기 전에 분량을 먼저 결정하라.

1. 이 코스가 가르쳐야 하는 고유 수행을 구분 가능한 국면으로 나눈다. 그 국면 수가 유닛 후보다.
2. 각 국면에서 관찰 가능한 수행이 몇 개인지 센다. 그 수가 그 유닛의 레슨 후보다.
3. 국면마다 필요한 예시 장르·예외·전이 횟수가 다르면 레슨 수도 달라져야 한다.
4. 레슨을 늘려도 새 수행이 없으면 줄인다. 한 레슨에 수행이 두 개면 나눈다.
5. 바로 앞 코스와 유닛 수 또는 레슨 수 패턴이 같으면 이유를 대지 말고 그 코스의 분량을 다시 정한다.

바닥과 천장. 천장을 채우는 것이 목표가 아니다.

- 코스마다 유닛은 2개 이상 8개 이하다.
- 유닛마다 레슨은 1개 이상 10개 이하다.
- 코스마다 레슨 합은 8개 이상이다. 상한은 주제 완결에 필요한 만큼이며, 28개를 넘기면 한 코스에 두 주제가 들어갔는지 먼저 의심한다.
- 레슨 `time`은 `20분`부터 `35분` 사이다. 이후 턴에서 채울 15~20스텝 분량과 맞춘다. 모든 레슨을 같은 분으로 통일하지 않는다.

통과 조건. 기계로 검사한다.

- 10개 코스의 유닛 수 집합에 서로 다른 값이 4개 이상 있다.
- 각 코스 안에서 유닛별 레슨 수 값이 2개 이상 있다. 유닛이 2개여도 레슨 수가 같으면 실패다.
- 10개 코스의 레슨 합 최댓값에서 최솟값을 뺀 값이 6 이상이다.

좋은 분량의 예. 숫자를 그대로 복사하지 말고 원리를 적용하라.

- 규범이 핵심인 코스: 규정 영역이 나뉘므로 유닛이 많고, 어떤 유닛은 짧은 판별 레슨만 둔다.
- 한 인지 절차가 핵심인 코스: 유닛은 적고, 한 유닛 안에서 레슨이 깊게 쌓인다.
- 전이가 핵심인 코스: 기초 유닛은 짧고, 장르별 적용 유닛이 길다.
</volume_is_not_a_grid>

<coverage_competencies>
10개 코스가 아래 24개 수행 공간을 빠짐없이 나누게 하라. 코스 JSON에 역량 ID 필드를 넣지 마라. 내부 설계에서 코스마다 주역량 1~3개를 배정하고, 한 주역량은 한 코스에만 둔다. 보조 역량은 여러 코스가 필요한 범위만 자체 연습한다.

1. 어휘 의미·사용: 문맥에서 뜻·용법·관계를 구별하고 의미를 보존한 단어를 고른다. 어휘량 암기만은 목표가 아니다.
2. 문장 의미 구성: 낱말·통사·지시·논리 관계를 통합해 문장 의미와 모호성을 판단한다.
3. 문법·표기 적용: 현행 규범의 원칙·허용·예외를 문맥에 적용한다. 문체 취향과 섞지 않는다.
4. 읽기 의미 구성: 목적에 따라 낱말·문장·구조·지식을 조정해 글의 표상과 이해를 만들고 점검한다.
5. 근거 기반 추론: 명시되지 않은 관계를 텍스트와 자료로 정당화한다. 자유연상은 제외한다.
6. 비판적 판단: 쟁점·가정·근거·대안을 비교하고 결론을 보류하거나 수정한다. 무조건 의심은 제외한다.
7. 구조적 분석과 통합: 자료를 목적에 맞는 요소와 관계로 분해하고 공통 구조로 통합한다.
8. 창의적 사고: 새롭고 적절한 아이디어를 다양하게 생성·평가·개선한다.
9. 수사적 주제 설정: 목적·독자·제약으로 쓸 문제의 범위를 정한다. 제목 고르기만은 제외한다.

<curriculum_design>
조사 후 다음 순서로 내부 설계를 완료하라.

1. 출처에서 가르칠 개념, 원리, 수행 절차, 흔한 오류, 평가 기준, 적용 한계를 추출한다.
2. 24개 수행의 중복·상하·인접 관계를 분석한다.
3. 코스마다 주역량 1~3개를 배정하는 행렬을 만든다.
4. 독립성, 근거 충분성, 고유 성과, 중복 정도로 10개를 확정한다.
5. 전체 카탈로그의 제목, 설명, 카테고리, 배열 순서, visualKey를 먼저 확정한다. 배열 순서는 선수 관계가 아니다.
6. 코스마다 `<volume_is_not_a_grid>`에 따라 유닛 수와 유닛별 레슨 수를 먼저 정한다. 목차 제목을 쓰기 전에 분량부터 정한다.
7. 각 코스의 유닛·레슨 제목과 관찰 가능한 목표를 확정한다.
8. 반드시 첫 코스의 모든 유닛·레슨 메타데이터를 완성하고 자체 검수한 뒤 두 번째 코스로 넘어간다. 스텝은 쓰지 않는다.
9. 모든 코스가 끝나면 전체 카탈로그의 중복, 누락, 용어, 난이도, 분량 격자를 다시 감사한다.

유닛은 주제의 장이다. 1유닛을 1주로 두지 않는다. 한 코스 안의 유닛 순서는 난이도와 전이가 쌓이게 하라. 아래는 국면의 예이지 4칸 템플릿이 아니다. 코스마다 필요한 국면만 두고, 어떤 국면은 합치고 어떤 국면은 나눈다.

- 그 영역에서 기초 개념과 흔한 오류
- 핵심 절차와 안내된 예시
- 새 장르·맥락으로의 전이
- 통합, 자기점검 기준, 앞선 주의 지연 연습

레슨:
- 한 회에 관찰 가능한 수행 하나
- `title`: 그 수행이 드러나는 한국어 제목
- `desc`: 학습자가 무엇을 하게 되는지. 마케팅 문장 금지
- `time`: `20분`부터 `35분` 사이. 이후 15~20스텝 분량과 맞춘다. 모든 레슨을 같은 분으로 통일하지 않는다
- `summary`: 2~5개의 재사용 판단 기준. 제목 반복 금지. 주제와 무관한 메타 문장 금지. 이후 스텝이 이 기준을 직접 연습할 수 있어야 한다
- `cat`: 넣으면 해당 유닛 제목을 재사용할 수 있다
- `steps`: 반드시 `[]`

이후 스텝을 염두에 두되, 이번 턴에서는 설계만 한다. 레슨은 확인 가능한 활동으로 가르칠 수 있어야 한다. 자유 작문이나 AI 첨삭이 있어야만 성립하는 목표는 쓰지 마라. 허용될 활동 타입은 `reading`, `compare`, `multiple_choice`, `true_false`, `select`, `categorize`, `match`, `order`, `fill_blank`, `sentence_build`, `transcribe`, `error_correct`, `paragraph_organize`이다. 타입을 주제에 고정하지 마라. JSON에 스텝 객체를 넣지 마라.

카테고리는 다음 다섯 값 중 하나만 쓴다. `미분류`는 쓰지 않는다.

- `언어와 읽기`
- `구성과 표현`
- `사고와 발상`
- `독자와 쓰기 과정`
- `정보와 AI 문해`

visualKey는 다음 다섯 값만 쓴다. 여러 코스가 같은 값을 공유할 수 있다.

- `basic-sentence-writing`
- `grammar-complete`
- `essay-writing`
- `creative-writing`
- `expression`
</curriculum_design>

<craft_quality>
품질 바닥선은 이 절이다. 스키마가 맞아도 이 밀도를 못 채우면 해당 코스를 다시 쓴다.

금지하는 프로토타입 패턴. 하나라도 반복되면 그 레슨·유닛·코스를 버리고 다시 쓴다.

- 레슨 제목만 바꿔 같은 `desc`·같은 `summary`를 돌린다.
- `summary`가 제목을 되풀이하거나 “대상을 고정한다 / 근거와 한계를 구분한다 / 결론을 검토한다”처럼 주제와 무관한 메타 문장이다.
- 모든 레슨 `time`이 같다.
- 모든 코스 유닛 수가 같거나, 한 코스 안 모든 유닛의 레슨 수가 같다.
- 유닛 제목이 레슨 제목을 이어 붙인 이름이다.
- 아동용 문장, 존재하지 않는 통계·조항·URL을 목차나 설명에 전제한다.

계층별 공:

- 코스: 한 문장으로 끝나는 고유 테제가 있다. 목차는 주제 나열이 아니라, 그 코스가 정한 유닛 순서에 난이도와 장르가 쌓인다. `desc`는 수강 후 할 수 있는 판단이다.
- 유닛: 그 장의 통과 기준이 있다. 레슨 제목을 이어 붙인 이름이 아니다. 뒤 레슨은 앞 레슨의 구분을 전제로 더 어려운 경계를 다룬다.
- 레슨: 관찰 가능한 수행 하나. `desc`와 `summary`만 읽어도 이후 스텝이 무엇을 묻게 될지 알 수 있다.

국어·작문 밀도:

- 용어는 한국어학·작문교육의 뜻을 지킨다. 지시, 호응, 피수식, 주제와 화제, 응집성과 일관성, 수사적 상황, 장르 관습, 주장–근거–보증–반론을 서로 바꿔 쓰지 않는다.
- 맞춤법·표준어·띄어쓰기는 현행 국립국어원 규정과 허용형을 구분한다. 문체 취향을 규범인 것처럼 쓰지 않는다.

문체:

- 설명은 `-습니다`를 기본으로 한다.
- 성인을 어린이처럼 대하지 않는다.
- 특정 성별·지역·세대·직업·정치 입장을 정상으로 가정하지 않는다.
- 번역투, 과장, 상투적 AI 문체, 부자연스러운 명사 나열을 피한다.
- “전문가 검수 완료”, “과학적으로 증명”, “무조건”, “항상”처럼 근거보다 강한 표현을 쓰지 않는다.
</craft_quality>

<repository_contract>
이 파일은 Bun/TypeScript 학습 앱의 시드 입력 골격이다. 당신은 저장소를 볼 수 없으므로 아래 계약만 권위로 사용하라.

```ts
type Seed = Course[] // 길이 10

type Course = {
  id: string
  title: string
  desc: string
  cat: "언어와 읽기" | "구성과 표현" | "사고와 발상" | "독자와 쓰기 과정" | "정보와 AI 문해"
  visualKey:
    | "basic-sentence-writing"
    | "grammar-complete"
    | "essay-writing"
    | "creative-writing"
    | "expression"
  units: Unit[] // 길이 고정 금지. 코스마다 2~8
}

type Unit = {
  id: string
  title: string
  lessons: Lesson[] // 길이 고정 금지. 유닛마다 1~10
}

type Lesson = {
  id: string
  title: string
  time: `${positiveInteger}분` // 권장 20~35
  cat?: string
  desc?: string
  summary?: string[] // 권장 2~5
  steps: [] // 1단계에서는 반드시 빈 배열
}
```

ID 규칙:
- 코스·유닛·레슨 ID는 비어 있지 않은 ASCII kebab-case다.
- 형식은 `^[A-Za-z0-9][A-Za-z0-9._:-]*$`, 길이 1~200.
- 의미를 드러내는 `course-...`, `unit-...`, `lesson-...` 접두사를 사용한다.
- 코스·유닛·레슨 ID는 계층을 통틀어 전역 중복이 없어야 한다.
- 스텝 객체를 만들지 않으므로 스텝 ID도 만들지 않는다.

추가 불변식:
- 모든 코스에는 유닛이 있고, 모든 유닛에는 레슨이 있다.
- 모든 레슨의 `steps`는 `[]`이다. 스텝 타입 키를 가진 객체를 넣지 않는다.
- `time`은 `20분`처럼 양의 정수와 `분`만 사용한다.
- 빈 문자열, 공백뿐인 문자열을 만들지 않는다.
- `write`, `ai_feedback`, `copy`, `completion`, `annotate`, `summary` 스텝을 설계 전제로 두지 않는다.
</repository_contract>

<construction_process>
파일은 내부 작업 공간에서 점진적으로 작성하라.

1. 전체 코스 카탈로그와 전역 ID 목록을 확정한다.
2. 첫 코스의 분량(유닛 수, 유닛별 레슨 수)을 확정한 뒤 목차를 쓴다.
3. 그 코스의 모든 레슨 메타데이터를 파일에 추가한다. `steps`는 `[]`다.
4. 해당 코스의 교육 품질, 분량 규칙, 스키마를 검수한다.
5. 통과한 코스만 배열에 남기고 다음 코스로 간다. 다음 코스의 분량은 앞 코스와 달라야 한다.
6. 마지막에 전체 파일을 다시 파싱하고 전역 검증한다.

한 코스를 작성할 때:
1. 고유 학습 성과와 근거 묶음을 확인한다.
2. 제목, 설명, 카테고리, 가장 가까운 visualKey를 고른다.
3. 주제·난이도에 맞는 유닛 수와 유닛별 레슨 수를 정한다.
4. 유닛과 레슨의 점진적 흐름을 설계한다.
5. 코스 안의 중복과 빠진 선수 설명을 제거한 뒤 다음 코스로 이동한다.
</construction_process>

<programmatic_validation>
최종 응답 전에 코드로 JSON을 파싱하고 다음을 모두 검사하라. 실패하면 파일을 수정하고 전부 다시 검사한다.

- JSON 파싱 성공과 루트 배열 길이 10
- 코스마다 유닛 2~8, 유닛마다 레슨 1~10, 코스마다 레슨 합 8 이상
- 10개 코스의 유닛 수 집합 크기가 4 이상
- 각 코스 안에서 유닛별 레슨 수 값의 집합 크기가 2 이상
- 코스별 레슨 합의 최댓값 - 최솟값이 6 이상
- 모든 필수 필드의 타입과 허용 enum
- 코스·유닛·레슨의 비어 있지 않은 배열(레슨의 `steps`만 빈 배열)
- 모든 레슨 `steps`가 `[]`이고, 길이가 0이 아닌 `steps`가 하나도 없음
- 전역 course/unit/lesson ID의 kebab-case, 길이, 문자 집합, 유일성
- 레슨 시간 형식과 양의 정수
- 빈 문자열, placeholder, TODO, 생략 기호
- 제목·설명·요약의 완전성
- 한 코스 안에서 모든 레슨 `time`이 동일하지 않음
- 한 코스 안에서 서로 다른 두 레슨의 `summary` 배열이 완전히 같지 않음

검증이 끝난 뒤 JSON을 2칸 들여쓰기로 다시 직렬화하고 마지막 개행을 넣는다. 최종 파일에서 다시 파싱한 뒤 SHA-256과 계층별 개수를 계산한다.
</programmatic_validation>

<final_quality_audit>
기계 검증 뒤 다음 의미 감사를 수행하라. 하나라도 실패하면 해당 코스를 고친 뒤 구조 검증과 의미 감사를 다시 수행하라. 스키마만 맞고 품질이 프로토타입이면 제출하지 마라.

- 24개 수행 공간 중 실질적으로 비어 있는 칸이 없는가?
- 코스 제목만 다르고 같은 설명·목차를 반복하지 않는가?
- 아무 레슨의 `title`·`desc`·`summary`에서 제목만 가렸을 때 주제를 식별할 수 있는가?
- 같은 유닛의 두 레슨을 나란히 두면 목표와 판단 기준이 다른가?
- 공식 규범과 저자의 문체 취향을 혼동하지 않는가?
- 어린이·영어권 연구의 결과를 성인 한국어 효과로 단정하지 않는가?
- 유닛이 달력 주가 아니라 주제의 장으로 읽히는가?
- 10개 코스가 같은 뼈대에 제목만 바꿔 넣힌 격자인가? 그렇다면 실패다.
- 각 레슨이 이후 확인 활동으로 가르칠 수 있는가? 자유 작문이 필요한 목표는 없는가?
- 모든 코스가 선행 코스 없이 이해 가능한가?
</final_quality_audit>

<final_response>
완성된 `content-seed-catalog.json` 파일을 첨부하라. 본문은 다음 정보만 간단히 보고한다.

- 코스 수
- 코스별 표: `course id`, 유닛 수, 각 유닛의 레슨 수, 레슨 합
- 전체 유닛 수, 전체 레슨 수
- 배열 순서대로 모든 레슨 ID 목록
- 파일 크기
- SHA-256
- JSON 파싱·스키마·분량 규칙·의미·품질 감사 통과 여부
- 모든 `steps`가 빈 배열인지 여부

연구 과정, 내부 추론, 코스별 장문 설명과 JSON 본문을 대화 본문에 반복하지 않는다.
</final_response>
````

## 2단계 마스터 프롬프트

아래 울타리 안에서 `{{LESSON_ID}}`만 해당 레슨 ID로 바꾼다. 같은 메시지에 1단계 `content-seed-catalog.json`을 첨부한다. 그 코스에서 이미 채운 레슨 파일이 있으면 함께 첨부한다.

````text
<role>
당신은 한국어가 모어인 일반 성인을 위한 글쓰기·읽기·사고·정보 문해 교육과정을 집필하는 편집위원회다. 위원회에는 국어학자, 한국어교육 연구자, 작문·수사학을 가르치는 교수, 실무 글을 오래 고쳐 온 편집자가 있다.

목표는 첨부된 카탈로그에서 지정한 레슨 하나의 학습 스텝을, 좋은 작문 강의나 단행본을 한 절씩 풀어 활동으로 만든 듯한 밀도로 쓰는 것이다. 실제 전문가 검수를 받았다고 주장하지 마라. 확인한 근거와 이번에 새로 쓴 예문·문항을 구분하라.

한 스텝마다 삭제하면 빈 자리가 보여야 한다. 제목만 바꿔 같은 껍데기를 돌리는 프로토타입은 제출 불가이다.
</role>

<mission>
이번 턴에서 채울 레슨 ID는 정확히 `{{LESSON_ID}}` 하나다. 첨부된 `content-seed-catalog.json`에서 이 레슨과 그 코스·유닛 맥락을 읽어라. 같은 코스에서 이미 채운 레슨 파일이 첨부되어 있으면 예문·오개념·해설을 재사용하지 마라.

이 레슨의 `steps`만 15~20개로 채워라. 코스·유닛·다른 레슨의 ID, 제목, 설명, 분량, 순서를 바꾸지 마라. 이 레슨의 `id`, `title`도 바꾸지 마라. `time`과 `summary`는 실제 스텝 분량과 어긋날 때만 최소로 고친다.

최종 필수 산출물은 다운로드 가능한 파일 하나다.

- 파일명: `lesson-{{LESSON_ID}}.json`
- 루트 값: 해당 레슨 객체 하나. 카탈로그와 같은 필드에 `steps`만 채워져 있다
- 형식: 유효한 JSON, 들여쓰기 2칸, 마지막 개행 포함
- 금지: 카탈로그 전체 재출력, 다른 레슨의 스텝, JSON 주석, trailing comma, 생략 기호, placeholder, TODO, “예시는 동일”, 채팅 본문에 대량 JSON 붙여 넣기

대화 본문에 대용량 JSON을 붙이지 말고 파일로 첨부하라. 최종 본문에는 파일 링크, 레슨 ID, 스텝 수, 타입 구성, 파일 크기, SHA-256, 검증 통과 여부만 간단히 보고하라. 다음 레슨을 쓰겠다고 제안하지 마라. 파일 생성 도구를 사용할 수 없다면 작업을 일부 출력하지 말고, 완전한 파일을 만들 수 없어 실패했다는 사실만 보고하라.
</mission>

<autonomy>
이 요청은 한 턴 안에 지정 레슨의 스텝만 완결해야 한다. 필요한 웹 검색, 원문 열람, 내부 메모, 계산, 파일 작성과 비파괴 검증을 스스로 수행하라. 중간 승인을 요청하거나 일부 스텝만 제출하거나 다음 레슨을 요구하지 마라.

최종 파일을 만들기 전에는 조사·집필·품질 감사·스키마 검증을 계속하라. 내부 계획과 상세 추론은 최종 응답에 노출하지 않는다.

카탈로그 전체를 다시 쓰지 마라. 지정 레슨 객체만 파일로 만들어라.
</autonomy>

<product>
글결은 한국어 글쓰기를 작은 레슨과, 레슨과 분리된 쓰기 과제로 익히는 학습 앱이다.

- 핵심 학습자: 한국어가 모어인 일반 성인. 어린이·수험생·특정 직업 연수생을 기본 독자로 두지 않는다.
- 레슨: 몰입형 전체 화면에서 스텝을 한 장씩, 배열 순서대로만 전진한다.
- 쓰기 과제: 이 JSON에 넣지 않는다. 자유 작문 스텝 `write`와 AI 코칭 스텝 `ai_feedback`는 금지다.
- `transcribe`는 제시된 원문을 그대로 재현하는 받아쓰기이다. 자유 작문이 아니다.
- `READING`과 `COMPARE`는 확인만 하고 채점하지 않는다. 나머지 11개 타입은 서버가 채점한다.
- 화면 문구와 학습 자료는 한국어다.
</product>

<scope>
- 지정 레슨 밖의 계층을 수정하지 않는다.
- 첨부 카탈로그에 없는 레슨 ID면 파일을 만들지 말고, 그 ID가 카탈로그에 없다고만 보고하고 종료하라.
- 지정 레슨의 `steps`가 이미 비어 있지 않으면, 기존 스텝을 이어 쓰지 말고 이번 턴에서 전부 다시 쓴다. 다만 같은 코스의 다른 레슨 파일에 있는 예문은 피한다.
- 레슨당 스텝: 15~20개. 수를 채우려고 같은 활동을 반복하지 않는다.
- 이 레슨의 `title`, `desc`, `summary`가 가리키는 수행 하나만 깊게 연습한다. 유닛 전체를 이 레슨에 넣지 않는다.
</scope>

<research_protocol>
이 레슨 주제에 필요한 범위만 자료를 확인하라. 조사 메모는 최종 파일에 넣지 않는다.

자료 우선순위:
1. 최신 국립국어원 어문 규범·해설·실태 조사·공공언어 자료, 교육부·국가교육과정정보센터의 국어과 교육과정, 한국교육과정평가원 등 공공 연구
2. 동료 심사 학술 논문, 체계적 문헌고찰·메타분석, 대학·연구기관 보고서
3. OECD PIAAC·PISA, UNESCO 매체·정보 문해, 미국 IES/What Works Clearinghouse 작문 지도, ACRL, Civic Online Reasoning 등 공신력 있는 국제 자료
4. 저자와 출판 주체를 확인할 수 있는 국어학·작문교육·수사학 단행본과 공식 강의

채택 규칙:
- 공식 원문, DOI 논문, 저자·기관 저장본을 우선한다.
- 검색 결과 요약만 읽고 원문 전체를 확인한 것처럼 쓰지 않는다.
- 책·유료 논문·강의는 확인 가능한 목차·미리보기·초록·공식 소개의 범위만 사용한다.
- 일반 블로그, 커뮤니티, 익명 자료, SEO 요약문은 근거로 쓰지 않는다.
- 한국어 고유 규범과 실제 사용 판단에는 국내 권위 자료를 반드시 포함한다.
- 존재하지 않는 문헌, DOI, 통계, 페이지, URL을 만들지 않는다. 실제로 연 자료만 인용한다.
- 원문을 길게 전재하지 않는다. 예문·지문·선택지·참조 답안은 원리를 반영해 새로 집필한다.
- `source`에는 실제로 확인한 규범·연구만 넣는다. 자체 예문에는 `source`를 생략한다.
</research_protocol>

<lesson_rhythm>
레슨당 스텝은 15~20개다. 한 목표를 여러 예시로 깊게 연습한다. 유닛 전체를 한 레슨에 넣지 않는다.

설명과 확인이 번갈아 나오게 하라. 주제(맞춤법, 장르, 실무 등)를 특정 스텝 타입에 묶지 마라. 같은 원리를 `reading`으로 펼치고 `compare`로 전후를 보여 주고 `true_false`로 판별하고 `error_correct`로 고치고 `fill_blank`로 한 요소만 채우는 식의 재사용이 바람직하다.

권장 리듬(타입 고정이 아니다):
1. 개념을 펼치는 `reading`: 정의, 경계(무엇이 아닌가), 성인 글에서 왜 실패하는지, 문장 단위로 푼 예문
2. 같은 재료의 대조 또는 첫 확인
3. 예시 A에서 서로 다른 판단 지점을 묻는 확인 여러 개
4. 예외·허용형·전이 조건을 여는 다음 설명
5. 장르·맥락이 다른 예시 B, C로 전이 확인
6. 레슨 `summary`와 같은 말로 닫는 정리

제약:
- 확인 없이 `reading`만 3개 연속하지 않는다.
- 같은 타입을 4개 이상 연속하지 않는다.
- 스텝마다 새 정보, 새 예시, 새 판단 중 하나가 있어야 한다.
- 정답은 스키마가 허용하는 결정적 값이어야 한다.
- 열린 작문처럼 여러 답이 되는 문항을 단일 정답으로 만들지 않는다.
- 15~20개를 채우려고 같은 예문과 같은 오답을 돌리지 않는다.
</lesson_rhythm>

<step_as_mechanism>
13개 타입은 학습 영역이 아니라 조작 메커니즘이다. 수백 개 코스로 확장해도 재사용할 형식이다.

금지:
- `reading` = 개념 전용, `error_correct` = 맞춤법 전용, `order` = 개요 전용처럼 타입을 주제에 고정하는 일
- 아래 7칸 예시를 체크리스트로 돌려 레슨마다 칸을 채우는 일
- 목록에 없다고 목표에 맞는 활용을 버리는 일

스키마가 고정하는 것은 화면 조작뿐이다. 그 위에 올릴 국어·작문 내용은 열려 있다.

아래 활용은 예시의 일부다. 전부도 아니고 의무 목록도 아니다. JSON의 CHOICE는 `multiple_choice`로 적는다.

READING 예시: 어휘·표현·유형학 / 맞춤법·띄어쓰기·문장부호 / 문법·문형·문장 성분 호응 / 문체·수사법·문장 교정 / 문단 구성·논리 구조 / 갈래별 글쓰기 가이드 / 실무·비즈니스·실용 글쓰기

COMPARE 예시: 초고 vs 퇴고 / 아쉬운 예 vs 좋은 예 / 어휘 뉘앙스 / 상황·대상별 어조 / 문단 구조·논리 전개 / 맞춤법·띄어쓰기·문장부호 전후 / 실무 문서·장르 실전 사례

MULTIPLE_CHOICE 예시: 어휘·표현·맞춤법 재인 / 띄어쓰기·문장부호 / 문법·문형·호응 / 문체·수사·교정 최선안 / 문단 흐름·논리·통일성 / 갈래별 선택 / 실무·퇴고·편집 실전

<craft_quality>
품질 바닥선은 이 절과 아래 골드 스탠더드 JSON이다. 스키마가 맞아도 이 밀도를 못 채우면 이 레슨을 다시 쓴다.

금지하는 프로토타입 패턴. 하나라도 반복되면 그 레슨을 버리고 다시 쓴다.

- 레슨 제목만 바꿔 같은 본문·같은 예문·같은 선택지·같은 해설을 돌린다.
- `reading.body`가 “이번 레슨에서는 **[목표 문장]**”으로 시작하고, 모든 레슨에 동일한 3줄 판단 기준을 붙인다.

- 모든 `guide`가 “목표, 근거와 판단의 한계를 구분해 읽어 보세요”다.
- `source`에 “자체 집필”을 기계적으로 넣는다. 규범·연구를 실제로 확인한 `reading`만 `source`를 쓴다. 자체 예문에는 `source`를 생략한다.
- 아동용 문장(“철수는 학교에 갔다”), 번역투 예문, 존재하지 않는 통계·조항·URL.

계층별 공:

- 레슨: 관찰 가능한 수행 하나. 예문 세트 A→B→C는 장르나 함정이 달라야 한다.
- 스텝: 삭제하면 빈 자리가 보여야 한다. `reading`은 정의·대조·푼 예문·흔한 오류·적용 한계가 있는 한 편의 학습 문서다. 확인 스텝의 예문은 직전 설명의 원리를 새 문장에 적용한다. 오답은 교실에서 실제로 나오는 혼동이다.

국어·작문 밀도:

- 용어는 한국어학·작문교육의 뜻을 지킨다. 지시, 호응, 피수식, 주제와 화제, 응집성과 일관성, 수사적 상황, 장르 관습, 주장–근거–보증–반론을 서로 바꿔 쓰지 않는다.
- 맞춤법·표준어·띄어쓰기는 현행 국립국어원 규정과 허용형을 구분한다. 문체 취향을 규범인 것처럼 쓰지 않는다.
- 예문은 성인 생활 글이다. 직장 메일, 공지, 설명문, 후기, 건의, 짧은 칼럼, 안내 문구. 사실처럼 적은 고유명·연도·수치는 검증한다.
- `reading` 안에 나쁜 문장과 고친 문장을 직접 보여 주고, 의미·독자·문법에서 무엇이 달라지는지 문장 성분까지 짚는다.
- 해설은 정답 라벨 반복이 아니라 판단 경로다. 예: “이 구간이 조건절이라 범위가 줄어든다.” “이 유의어는 격식은 맞지만 대상이 사람이 아니라서 탈락한다.”

문체:

- 설명은 `-습니다`, 활동 지시는 `-해 보세요`를 기본으로 한다.
- 성인을 어린이처럼 대하지 않는다.
- 특정 성별·지역·세대·직업·정치 입장을 정상으로 가정하지 않는다.
- 번역투, 과장, 상투적 AI 문체, 부자연스러운 명사 나열을 피한다.
- “전문가 검수 완료”, “과학적으로 증명”, “무조건”, “항상”처럼 근거보다 강한 표현을 쓰지 않는다.

서술형 학습 자료는 `reading.body`의 CommonMark Markdown이다. 제목, 문단, 목록, 인용문을 써서 자립적인 학습 문서가 되게 한다. 원시 HTML과 깨진 Markdown을 쓰지 않는다. 다른 활동 필드에 긴 이론을 숨기지 않는다.

- `fill_blank.template`의 `___` 개수와 `answer` 길이는 같다. 한 토큰은 한 칸에만 쓴다.
- `match`의 왼쪽 표시 텍스트, 오른쪽 표시 텍스트, `leftId`, `rightId`는 각 쪽에서 유일하다. 화면에서 구분할 수 없는 중복 문구를 두지 않는다.
- `categorize.items[].categoryId`는 존재하는 `categories[].id`를 참조한다. 카테고리 ID와 항목 ID에는 서로 다른 접두사를 사용한다.
- `order.correct`는 모든 `itemIds`의 완전 순열이다. 화면은 항목을 섞으므로 JSON 배열 순서에 의존하지 않는다.
- `sentence_build`의 한 타일은 한 번만 쓴다. `tiles`에 오답 타일을 둘 수 있다.
- `transcribe`의 정답은 `source`를 연속 공백 정규화해 대조한다. 창작 문장을 쓰게 하지 않는다.
- `error_correct`는 오류 구간 하나와 수정안 하나를 고른다. 수정안 문구는 서로 달라야 한다.
- `paragraph_organize`는 넣지 않을 카드(방해 문장)를 둘 수 있다. `order`와 달리 정답이 전 항목의 순열이 아닐 수 있다. 카드 문구는 유일해야 한다.
- `true_false`는 O·X만 있다. 선택지 배열을 두지 않는다. 두 해석이 동시에 성립하는 문장은 쓰지 않는다.
- 정답은 문구나 배열 위치가 아니라 안정적인 ID(또는 boolean, 또는 정규화한 원문)를 참조한다.
- 빈 문자열, 공백뿐인 문자열, 중복 선택지, 의미상 복수 정답인데 단일 정답만 허용한 문제를 만들지 않는다.
</repository_contract>

<construction_process>

2. 이 레슨의 고유 수행과 `summary` 판단 기준을 확인한다.
3. 앞뒤 레슨과 이미 채운 같은 코스 레슨의 예문·오개념이 겹치지 않게 재료를 정한다.
4. 목표를 관찰하기 좋은 메커니즘을 고른다. 주제로 타입을 고정하지 않는다.
5. 15~20스텝을 골드 스탠더드 밀도로 쓴다.
6. 활동과 해설을 실제로 풀어 보고 정답의 결정성과 난이도를 확인한다.
7. 레슨 객체만 파일로 저장하고 검증한다.
</construction_process>
````

## 수령 후 후속 작업

이 파일의 범위가 아니다. 받은 JSON을 저장소에 넣기 전에 다음을 별도 작업으로 수행한다.

1. 1단계 보고의 SHA-256과 `content-seed-catalog.json` 해시를 비교한다. 분량 규칙(코스 간 유닛 수 다양성, 코스 안 레슨 수 다양성)을 다시 확인한다.
2. 2단계 각 레슨 파일의 SHA-256과 스키마를 비교한다. 레슨 ID가 카탈로그와 일치하는지 확인한다.
3. 모든 레슨 파일의 `steps`를 카탈로그의 해당 `steps: []`에 넣어 `content-seed-data.json` 후보를 만든다.
4. 후보 파일을 별도 경로에 두고 JSON 파싱과 스키마 감사를 다시 실행한다.
5. `true_false`, `sentence_build`, `transcribe`, `error_correct`, `paragraph_organize`의 DTO, 답안, 시드 매퍼, 학습자 renderer, 관리자 폼을 맞춘다. 맞추기 전에는 권위 시드에 넣지 않는다.
6. 코스별 전수 검수를 한다. 규범, 출처 URL, 정답 결정성, 예문 중복, 저작권 위험을 본다.
7. 승인된 파일만 [`content-seed-data.json`](../../../packages/modules/content/src/infrastructure/persistence/content-seed-data.json)에 반영한다.
8. 시드 수량에 묶인 테스트를 새 기준선에 맞게 고친다.
