# 작성 세션 참조 패널이 본문을 가리는 문제

## 문서 상태

- 상태: 구현 중
- 기준 날짜: 2026-08-14
- 이 문서는 한시 조사다. 현재 제품·화면·데이터 사실의 권위 소스가 아니다.

## 목적

학습자가 과제 조건이나 점검 결과를 보면서 본문을 고칠 수 있게 한다.

해결은 320px 모바일부터 `lg` 이상 데스크톱까지 같은 작업 규칙을 유지해야 한다.

## 권위와의 관계

현재 제품 계약은 열린 서랍이 본문을 가리도록 명시한다.

구현은 그 계약을 따른다. UI만 바꾸면 권위와 코드가 다시 어긋난다.

승인 후 먼저 아래 권위를 고친 뒤 화면을 바꾼다.

| 영역   | 문서                                                                                     | 고칠 문장                                                           |
| ------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 제품   | [`REQ-LRN-11`](../../product/requirements/platform/req-lrn-11-purpose-writing.md)        | `열린 서랍은 본문을 가리고, 닫은 뒤에 다시 쓴다.`                   |
| 제품   | [`US-LRN-12`](../../product/user-stories/platform/us-lrn-12-write-purpose-task.md)       | 조건·점검과 본문을 동시에 보는 인수 기준이 없다.                    |
| 디자인 | [`SCR-009`](../../design/screens/SCR-009-learner-writing-studio.md)                      | `열린 서랍은 본문을 거의 가린다. 열린 동안 본문을 입력하지 않는다.` |
| 디자인 | [`patterns.md`](../../design/patterns.md), [`components.md`](../../design/components.md) | 본문 위 서랍, 본문을 거의 가리는 오버레이                           |

현재 route, breakpoint 값, Sheet API는 코드가 소유한다. 값은 이 문서에 복제하지 않는다.

## 현재 사실

### 제품이 의도한 동작

[`REQ-LRN-11`](../../product/requirements/platform/req-lrn-11-purpose-writing.md)은 브리프와 점검 결과를 한 번에 하나만 연다고 정한다.

같은 문서는 열린 서랍이 본문을 가리고, 학습자가 닫은 뒤에 다시 쓴다고 정한다.

[`SCR-009`](../../design/screens/SCR-009-learner-writing-studio.md)는 기본 상태를 본문 종으로 둔다.

같은 화면 명세는 `lg` 미만에서 하단 시트, `lg` 이상에서 본문을 거의 가리는 오버레이를 요구한다.

2026-08-14 chrome 계획([보관](../../archive/2026-08-14-writing-studio-chrome/plan.md))은 `연 채로 본문 쓰기`, `과제 \| 본문 \| 점검 3열`, `패널 폭 드래그`를 의도적으로 버렸다.

그 결정은 평시 chrome을 줄이려는 몰입 목표에서 나왔다.

그 결정은 점검 뒤 수정 루프의 동시 참조 요구를 제품 규칙으로 남기지 않았다.

### 코드가 만드는 가림

작성 세션 구현은 [`apps/web/src/features/writing/ui/writing-studio.tsx`](../../../apps/web/src/features/writing/ui/writing-studio.tsx)가 소유한다.

공유 블록 [`packages/shared/ui/src/blocks/writing-studio.tsx`](../../../packages/shared/ui/src/blocks/writing-studio.tsx)도 같은 뼈대를 쓴다.

`useStudioDrawerSide`는 `lg` 경계에서 `bottom` 또는 `center`를 고른다.

`SheetContent`는 두 방향 모두 뷰포트 높이의 약 92%를 차지한다.

`center` 패널의 최대 너비는 본문 종이(`max-w-3xl`)와 같다.

`Sheet`는 `@base-ui/react/dialog`다.

UI 문서 계약은 Sheet가 열리면 배경을 inert로 두고 초점을 패널 안에 가둔다고 적는다.

따라서 패널이 열리면 본문은 보이지도 않고 입력도 할 수 없다.

카탈로그 미리보기 Sheet(`SCR-011`)는 이 조사의 대상이 아니다.

그 미리보기는 작성 중 참조가 아니라 시작 전 확인이다.

## 문제의 본질

작성 세션의 핵심 루프는 과제 고르기 → 작성 → 점검 → 수정 반복이다.

수정 단계에서 학습자는 조건 또는 고칠 일을 보면서 본문을 바꿔야 한다.

현재 UI는 그 두 표면을 시간으로 나눈다.

학습자는 패널을 열고, 읽고, 닫고, 기억에 의존해 고치고, 다시 연다.

이 전환은 작업 기억 전환 비용이다.

Kellogg 등의 쓰기 작업기억 종합([`src-0134`](../../research/sources/src-0134-working-memory-written-composition-progress.md))은 계획·문장화·읽기·편집이 제한된 중앙집행기를 두고 경쟁한다고 본다.

같은 출처는 목표와 제약 조건을 외부 표상으로 두면 문장화에 쓸 자원이 남는다고 본다.

현재 서랍은 그 외부 표상을 본문과 동시에 쓰지 못하게 한다.

제품 비전은 과제 조건으로 점검받고 다시 다듬는 학습을 목표로 한다.

범용 문서 편집기를 목표로 하지 않는다.

참조 패널을 도킹하는 일은 편집기 확장이 아니라 학습 루프의 제약 조건을 화면에 고정하는 일이다.

Luma 레이아웃 원칙([`apps/ui/design/COMPONENTS.md`](../../../apps/ui/design/COMPONENTS.md))도 같은 구분을 한다.

지속적으로 참조하는 패널은 dock한다.

일시적 도구만 floating layer로 연다.

작성 세션의 과제·점검은 지속 참조다.

고지 dialog와 나가기 확인만 모달이다.

## 유지할 제약

아래 제약은 이번 해결에서 깨지 않는다.

1. 과제와 점검 결과는 한 번에 하나만 연다.
2. 기본 상태는 닫힌 본문 종이다. 들어올 때 과제를 미리 열지 않는다.
3. 패널 폭 드래그는 비범위로 남긴다.
4. 과제 \| 본문 \| 점검 3열은 두지 않는다.
5. 타이머와 포커스 모드는 두지 않는다.
6. 320px과 텍스트 200% 확대에서 가로 스크롤이 생기면 안 된다.
7. 소프트 키보드는 본문과 주요 행동을 가리면 안 된다.
8. 글로벌 내비게이션은 숨긴 몰입 화면을 유지한다.

## 버린 대안

### A. Sheet를 더 작게 유지한다

`center` 최대 너비를 줄이거나 `right` Sheet로 바꾼다.

데스크톱에서 본문 일부가 보일 수 있다.

모달 Dialog는 배경을 inert로 두므로 보이는 본문을 입력할 수 없다.

모바일 `bottom` 92%는 본문을 거의 남기지 않는다.

이 대안은 가림만 조금 줄이고 동시 수정을 열지 못한다.

### B. `modal={false}` Sheet를 본문 위에 띄운다

Base UI Dialog는 배경 포인터를 허용할 수 있다.

패널이 포털 오버레이로 남으면 본문 글자가 패널 뒤에 가린다.

초점을 가두지 않은 채 본문 위를 덮으면 보조 기술은 두 층을 동시에 만난다.

이 대안은 모달 함정을 레이어 함정으로 바꿀 뿐이다.

### C. 필수 요소 칩만 헤더에 고정한다

시드 과제의 필수 요소는 보통 2–3개 짧은 문장이다.

점검의 고칠 일은 위치, 이유, 부분 수정 예문을 가진다.

칩은 초고 단계의 조건 재확인에는 도움이 된다.

점검 결과를 보면서 고치는 작업은 칩으로 대체할 수 없다.

칩은 도킹 패널의 보조일 수 있다. 단독 해결은 아니다.

### D. 점검 항목을 본문에 인라인 주석으로 붙인다

고칠 일은 `location`을 가진다.

Lexical 캔버스가 도입 중이므로 나중에 위치 표시를 붙일 여지는 있다.

1차 해결은 브리프와 점검 결과 전체를 동시에 보여 주는 일이다.

인라인 주석은 별도 범위로 남긴다.

### E. 떠 있는 작은 창을 드래그한다

320px에서 본문과 창이 겹친다.

키보드와 200% 확대에서 초점이 불안정하다.

패널 폭 드래그 비범위와 같은 종류의 자유 크기 조절이다.

채택하지 않는다.

## 권고

작성 세션의 과제·점검 패널을 Sheet에서 빼 레이아웃 슬롯으로 도킹한다.

패널이 열리면 본문 종이의 남는 공간이 줄어든다.

본문은 가려지지 않고 입력을 유지한다.

Sheet primitive와 카탈로그·어드민 Sheet는 그대로 둔다.

### 공통 규칙

- 패널 상태는 `closed` | `brief` | `feedback`를 유지한다.
- 헤더의 과제·결과 버튼은 `aria-pressed`로 연림을 표시한다. 같은 버튼을 다시 누르면 닫는다.
- 점검 성공 직후 `feedback`을 연다. 과제가 열려 있으면 과제를 닫는다.
- 패널은 `complementary` 랜드마크다. Dialog가 아니므로 본문을 inert로 두지 않는다.
- 패널을 열면 초점을 패널 제목으로 옮긴다. 닫으면 본문으로 되돌린다. 열린 동안 Tab은 본문과 패널과 chrome을 순서대로 지난다.
- Escape는 열린 패널을 닫는다.
- 닫기는 패널 안과 헤더 토글 둘 다 제공한다.
- 폭은 CSS 비율로 고정한다. 드래그 핸들은 두지 않는다.

### 폭별 배치

| 폭        | 패널이 닫힘                         | 패널이 열림                                                                                         |
| --------- | ----------------------------------- | --------------------------------------------------------------------------------------------------- |
| `lg` 미만 | 지금과 같이 본문 종이 한 장         | 세로 분할. 위는 본문, 아래는 패널. 기본 높이는 남은 뷰포트의 약 40%다.                              |
| `lg` 이상 | 지금과 같이 가운데 `max-w-3xl` 종이 | 가로 분할. 왼쪽 본문, 오른쪽 패널. 본문은 줄어든 열 안에서 읽기 폭을 유지하고 패널은 고정 비율이다. |

`lg` 경계는 현재 `useStudioDrawerSide`와 같은 값을 유지한다.

구현 위치는 `WritingStudioShell`이다. 앱과 UI 블록이 같은 슬롯을 쓴다.

### 모바일 키보드

소프트 키보드가 열리면 패널을 한 줄 미리보기로 접는다.

미리보기는 현재 패널의 제목 한 줄만 보여 준다.

키보드가 닫히면 직전 높이로 되돌린다.

학습자가 미리보기를 누르면 키보드가 없는 상태에서 40% 높이로 되돌린다.

본문을 읽을 때만 필요할 때, 패널을 약 85%까지 키우는 읽기 상태를 둘 수 있다.

읽기 상태에서도 본문은 위에 남아 가리지 않는다.

높이 상태는 `peek` | `split` | `read`처럼 이산 값이다.

자유 드래그로 높이를 연속 조절하지 않는다.

### 하지 않는 일

- Sheet에 `modal={false}`만 켜고 오버레이를 남기지 않는다.
- 본문 위에 반투명 막을 두지 않는다.
- 과제와 점검을 동시에 두 열로 열지 않는다.
- 패널 폭 핸들을 두지 않는다.

## 접근성

모달 Sheet는 읽기 전용 확인에 맞다.

동시 작성과 참조에는 맞지 않다.

도킹 패널은 다음을 지킨다.

- 본문 label `본문`과 `role="textbox"`를 유지한다.
- 패널은 보이는 제목 `과제` 또는 `이번 점검`을 가진다.
- 320px과 텍스트 200% 확대에서 본문과 패널이 세로로만 쌓인다.
- 플로팅 헤더와 하단 점검은 패널이 열린 동안에도 가리지 않는다.

고지 dialog와 나가기 확인은 기존 AlertDialog를 유지한다.

## 제품 문장 초안

승인되면 권위 문서에 아래 의미로 반영한다. 아래는 초안이며 현재 사실이 아니다.

- 브리프와 점검 결과는 한 번에 하나만 연다.
- 열린 패널은 본문 옆 또는 아래에 붙는다.
- 열린 동안 본문을 입력할 수 있다.
- 닫으면 본문 종이만 남는다.

`US-LRN-12` 인수 기준 후보:

- 과제 보기 또는 점검 결과 보기를 연 채로 본문을 수정할 수 있다.

## 구현 순서 초안

제품 기준이 이 계약과 어긋난 채로 UI만 바꾸지 않는다.

1. `REQ-LRN-11`, `US-LRN-12`, `SCR-009`, 쓰기 패턴, `WritingStudioShell` 컴포넌트 설명을 고친다.
2. `WritingStudioShell`에 본문 슬롯과 참조 슬롯을 둔다.
3. 앱 `WritingStudio`와 공유 블록에서 Sheet를 제거하고 같은 슬롯에 브리프·점검을 넣는다.
4. `lg` 미만 세로 분할, `lg` 이상 가로 분할, 키보드 시 `peek` 접힘을 맞춘다.
5. 320px, 200% 확대, 키보드 열림, 키보드 탐색, 점검 성공 직후 패널 열림을 확인한다.

## 완료 조건

- 권위 문서가 `열린 동안 본문을 입력할 수 있다`고 같은 말을 한다.
- `lg` 이상에서 과제 또는 점검 패널과 본문이 한 화면에 보이고, 패널이 열린 채로 본문에 글자를 넣을 수 있다.
- `lg` 미만에서 같은 동시 보기·입력이 세로 분할로 가능하다.
- 소프트 키보드가 열린 동안 본문 입력 줄이 패널에 가리지 않는다.
- 과제와 점검은 동시에 열리지 않는다.
- 카탈로그 미리보기 Sheet는 모달로 남는다.
- Markdown 변경은 `bun oxfmt --check`로 확인한다. 코드 변경은 `bun run ci:static`, `bun run ci:tests`, `bun run build`를 통과한다. UI 블록을 바꾸면 UI 문서 검증 티어도 실행한다.

2. 1차 구현을 도킹 분할로 한정하고, 인라인 주석과 패널 폭 드래그는 비범위로 남기는가.
