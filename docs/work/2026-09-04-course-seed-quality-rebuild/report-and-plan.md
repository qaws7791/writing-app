레슨 전체에서 확인한 사실:

- 원리를 제시하는 스텝(`Rd`, `Cp`)이 0개다.
- 위치를 고르는 스텝 6개의 정답이 모두 마지막 구간이다.
- 12스텝에 서로 다른 장면 10개가 등장한다(프로젝트 목적, 비용 공유, 팀장 당부, 신규 기능, 보고서 일정, 소통, 서버 안정성, 성장 바람, 배포 일정, 기획 목적).
- 테제는 "수식어 걷어내기와 거리 좁히기"인데, 12스텝 중 11스텝이 "주어가 추상 명사이면 서술어를 '~것이다'로 맺는다"는 다른 판정을 가르친다. 그 판정은 설계서상 `lesson-sentence-l02`의 테제다.
- 해설 12개 중 11개가 "'X는 ~것이다'로 호응해야 맞습니다"의 변형이다. 이유를 설명하는 해설이 없다.

| P1   | 장면 먼저, 스텝 나중           | 레슨 브리프에 문서 1편 또는 대화 1개(등장인물, 목적, 수신자)를 고정한다. 모든 예문은 그 문서의 문장이다. 앞 스텝에서 고친 문장이 뒤 스텝에 다시 나온다. 마지막 스텝은 그 문서의 최종 문장을 완성한다                                                                                                                |
| P2   | 원리 앵커가 첫 스텝            | 첫 스텝은 `compare` 또는 `reading`이다. `compare`를 기본으로 하고, 두 판본의 `mark`가 판정 축을 가리켜야 한다. 두 번째 스텝은 그 판정 공식을 한 번 적용하는 Lv 1 문항이다                                                                                                                                           |
| P3   | 판정 지식이 필요한 오답만      | 오답은 (1) 문법적으로 성립하고 (2) 실무에서 실제로 관찰되며 (3) 레슨의 판정 축 하나만 위반한다. 자체 비문, 존재하지 않는 표현, 유치한 오답은 금지한다. 검토 질문: "이 레슨을 안 배운 성인이 상식으로 거를 수 있는가?" 그렇다면 폐기한다. 반대로 오답이 실전에서 허용되는 표현이면 정답이 확정되지 않으므로 폐기한다 |
| P4   | 위치가 정답을 말하지 않는다    | `select`는 구간 4개 이상. 서술어를 다루는 레슨은 서술어가 둘 이상인 문장을 쓰거나 오류 위치를 주어·조사·부사어로 분산한다. `error_correct`는 교정안 3개 이상이며 원문을 교정안에 넣지 않는다. `multiple_choice`는 3개 이상이며 2지선다는 `compare`로 대체한다                                                       |
| P5   | 실전 문장을 그대로             | 선택지·판정 문장·구간에 조사와 목적어를 남긴다. 상한을 상향한다(제안: `optionText` 15→40, `statement` 40→60, `explanation` 40→70, `segmentText` 20→30, `tileText` 10→14, `readingBody` 150→220). 상향 폭은 UI 렌더 확인 후 확정한다                                                                                 |
| P6   | 참·거짓은 문장 판정만          | `statement`는 실제 문장 1개다. 규칙 진술, 의견 진술, 두 명제 결합을 금지한다. 지시문은 "이 문장을 그대로 보내도 되나요?"처럼 행동 판정으로 쓴다                                                                                                                                                                     |
| P7   | 해설은 공식 + 이유             | 해설은 [판정 공식 적용] + [왜 그 결과인가]를 담는다. 정답을 다시 말하는 해설("'~것이다'가 맞습니다")은 금지한다. 같은 레슨에서 해설 첫 8자가 3회 이상 같으면 실패다                                                                                                                                                 |
| P8   | 어투 하나                      | 제품 전체가 한 화자로 말한다. 톤은 8장에서 결정한다. 어느 쪽이든 `lesson-author.md`의 유아어 금지 목록('~랍니다', '참 잘했어요')은 유지한다                                                                                                                                                                         |
| P9   | 브랜드명 0                     | 실제 서비스명을 쓰지 않는다. '팀 메신저', '단체 대화방', '협업 도구', '결재 시스템'으로 쓴다                                                                                                                                                                                                                        |
| P10  | 레슨 정체성 단일 소스          | 코스별 `work-orders.json`이 레슨의 `title`, `thesis`, `judgementAxis`, `scene`, `contrastPairs`, `forbidden`을 소유한다. 설계서 둘의 충돌은 `full-curriculum-units-and-lessons.md`를 기준으로 정리한 뒤 시드 `title`·`desc`와 일치시킨다                                                                            |
| P11  | 템플릿은 순서 강제가 아닌 제약 | 검증기는 유형 순서 대신 (1) 첫 스텝 앵커, (2) 마지막 스텝 능동 조작, (3) 유형별 상한, (4) 인지 등급 오름차순, (5) 유닛 내 동일 배치 금지를 강제한다. 60개 템플릿은 집필자가 고르는 권장 배치로 남긴다. 이 원칙은 `lesson-step-templates.md`의 권위를 바꾸므로 ADR을 남긴다                                          |
| P12  | ID 고정                        | 코스·유닛·레슨 ID는 바꾸지 않는다. 학습 진행 데이터, E2E 시더, 관리자 화면이 ID를 참조한다                                                                                                                                                                                                                          |

### 7.4 레슨 브리프 스키마

`work-orders.json`의 `orders[]` 항목에 아래 필드를 추가한다. 집필 에이전트는 브리프만 받고 형제 레슨 파일은 읽지 않는다.

| 필드              | 내용                                                         | 예(`lesson-sentence-l01`)                                                                        |
| ----------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `thesis`          | 1줄 테제. 시드 `desc`와 같다                                 | 주어와 서술어 사이의 수식어를 걷어내고 짝을 확인해 호응을 맞춘다                                 |
| `judgementAxis`   | 학습자가 내리는 판정 1개                                     | 수식어를 괄호로 묶은 뒤 남는 주어와 서술어가 짝이 되는가                                         |
| `scene`           | 문서 1편 또는 대화 1개. 화자, 수신자, 목적                   | 신규 기능 출시를 앞둔 팀의 주간 보고 초안. 작성자는 기획자, 독자는 팀장. 문장 6개                |
| `contrastPairs`   | 어색한 판본과 바른 판본 6~8쌍. 각 쌍은 판정 축 하나만 다르다 | "이번 개편의 목적은 … 편의를 높이고자 합니다" / "이번 개편의 목적은 … 편의를 높이는 데 있습니다" |
| `distractorRules` | 이 레슨에서 허용하는 오답 유형과 금지 유형                   | 허용: 주어 생략형, 서술어 시제 불일치형. 금지: 조사 오탈자, 맞춤법 오류                          |
| `forbidden`       | 형제 레슨이 쓰는 판정·낱말·장면                              | '~것이다' 종결 공식(`l02`), 목적어 생략(`l03`), 호응 부사어(`l04`)                               |
| `anchor`          | 첫 `compare`의 두 판본과 `mark`                              | 위 `contrastPairs[0]`, mark = "높이고자 합니다" / "높이는 데 있습니다"                           |
| `closing`         | 마지막 스텝이 완성하는 문장                                  | 보고 초안의 마지막 문장을 `sentence_build`로 조립                                                |

### 7.5 리뷰 루브릭

리뷰어와 사람 검토자는 레슨마다 10항목을 예·아니오로 판정한다. 하나라도 아니오면 반려한다.

| 번호 | 질문                                                           |
| ---- | -------------------------------------------------------------- |
| Q1   | 첫 스텝이 판정 축을 보여 주는가                                |
| Q2   | 모든 예문이 브리프의 장면 하나에서 나왔는가                    |
| Q3   | 모든 스텝이 브리프의 판정 축 하나만 묻는가                     |
| Q4   | 레슨을 배우지 않은 성인이 상식으로 거를 수 있는 오답이 0개인가 |
| Q5   | 실전에서 허용되는 표현이 오답으로 놓인 스텝이 0개인가          |
| Q6   | 정답 위치나 지시문이 답을 노출하는 스텝이 0개인가              |
| Q7   | 정답·오답이 조사와 맥락을 갖춘 실전 문장인가                   |
| Q8   | 해설마다 판정 공식과 이유가 있고 결론 재진술이 없는가          |
| Q9   | 마지막 스텝이 장면의 문장을 능동으로 완성하는가                |
| Q10  | 어투가 결정된 톤 하나이고 브랜드명이 없는가                    |

### 7.6 2·3단계 운영 방식

- 집필 단위는 유닛(레슨 4~6개)이다. 한 서브에이전트 세션이 유닛의 레슨을 순서대로 집필한다. 유닛 안의 장면·판정 중복은 이 세션이 막는다.
- 병렬 상한은 유닛 4개다. 이전 작업에서 레슨 6개 병렬을 넘기면 실행이 실패했다.
- 순서: 브리프 작성(0-6 스키마) → 집필 → `content:validate -- lesson` → 리뷰어 → 반려 시 재집필(최대 2회) → 사람 표본 검토 → `content:merge` → `content:validate -- seed --course=<id>` → `bun oxfmt`.
- 사람 표본은 유닛마다 레슨 1개다. 표본이 반려되면 그 유닛 전체를 재검토한다.
- 코스 02 유닛 1처럼 D10이 확인된 유닛은 브리프 작성 전에 0-7의 제목 정리 결과를 먼저 반영한다.
- 종합 유닛(각 코스의 마지막 유닛)은 앞 유닛을 모두 병합한 뒤 집필한다.
