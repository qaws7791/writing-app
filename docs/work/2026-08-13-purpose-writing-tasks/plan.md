# 목적이 정해진 글쓰기 활동

## 목적

집중형 쓰기를 폐기하고, 과제 선택 → 작성 → AI 점검 → 수정 반복으로 쓰기 탭을 교체한다. 이 문서는 grill-me로 닫은 기획 합의이며 현재 제품 사실의 권위 소스가 아니다.

## 범위

- 포함: 학습자 쓰기 홈·카탈로그·작성 세션 UI 문서 블록, 어드민 과제 목록·편집 UI 문서 블록
- 제외: `apps/web`·`apps/admin` 제품 라우트, API·영속화, 권위 화면 문서(`SCR-008` 이후) 갱신

제품 화면에 올리기 전에 유저 스토리·요구사항·화면 명세·개인정보 문서를 같은 변경에서 갱신한다.

## 합의

- 쓰기 탭이 이 기능의 자리다. 레슨 `WRITE`는 되돌리지 않는다.
- 지금 집중형 쓰기(방식 선택, 빈 화면, 자기 점검)와 그 데이터는 물리 삭제한다.
- 루프는 과제 고르기 → 작성 → AI 점검 → 수정 반복이다. 성공 점검 1회 뒤에 `마치기`가 가능하다. 마친 뒤 본문을 고치면 다시 작성 중이다.
- AI 비중은 과제가 정한다. 결과는 잘된 점 1–2개, 과제 미충족(있으면), 고칠 일 최대 3개다. 각 고칠 일은 위치·이유·부분 수정 예문을 가진다.
- 본문이 바뀌면 점검은 무효다. `점검하기` 한도는 과제 최소 글자 수와 학습자 하루 성공 횟수다. 첫 `점검하기` 직전에 외부 AI 전달을 고지한다.
- 홈은 `작성 중` / `완료` 탭과 카탈로그 경로다. 같은 과제 초고를 여러 편 둘 수 있다. 카탈로그 `시작하기`는 새 글이다. 이어쓰기는 홈에서만 한다. 글은 확인 후 삭제한다.
- 카탈로그는 라우트 하나다. 상단 도메인 칩, 그 아래 유형 칩, 과제 카드다. 카드는 미리보기 오버레이를 연다. 빈 도메인·유형은 숨긴다.
- 도메인 10개는 제품 enum이다. 유형 이름은 관리자가 과제에 붙인다.
- 작성은 몰입형이다. 브리프는 읽고 → 접고 → 필요할 때만 연다. 점검은 같은 세션에 붙는다. 타이머·포커스 모드·패널 폭 드래그는 1차에 없다.
- 과제는 owner가 코스와 나란히 편집한다. 글은 시작 시점 발행본에 고정된다.

### 도메인

1. 일상·실용문
2. 학업·논술문
3. 업무·비즈니스 문서
4. 창작·문학
5. 설득·의견문
6. 정보전달·설명문
7. 자기서사·기록
8. 관계·소통 문서
9. 공적·행정 문서
10. 디지털·뉴미디어

난이도는 입문 / 기본 / 심화다.

## 블록

| 탭   | slug                  | 화면                                     |

| 학습 | `writing-home`        | 작성 중 / 완료, 카탈로그 경로            |

## 완료 조건

- 위 다섯 블록이 `학습`·`운영` 탭에 등록되고 미리보기에서 합의 IA를 보여 준다.
- `bun --filter @workspace/ui-docs docs:validate`가 통과한다.
- 제품 권위로 승격할 때는 관련 `docs/product`·`docs/design`·개인정보 문서를 갱신한 뒤 이 작업 단위를 archive로 옮긴다.
