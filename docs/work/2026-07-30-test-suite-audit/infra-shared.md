# packages/infra · shared · config 테스트 감사

## 요약

- 검토 파일 수: 49/49 (infra 27 · shared/contracts 14 · shared/ui 6 · config/env 2)
- 삭제 권고 24건 · 수정 권고 39건 · 문제 없음 8건
- 가장 시급한 3가지
  1. `packages/infra/db/src/destructive-operation-guard.test.ts:22-25`가 모듈 최상위에서 저장소 실제 `data/` 디렉터리를 만들고 그 안에 임시 DB·junction symlink를 생성한다. 개발자 데이터 디렉터리를 테스트가 공유 자원으로 쓰므로 중단 시 저장소가 오염되고 실행 순서·단독 실행 결과가 달라진다(C-2, C-7, `docs/engineering/testing.md` "개발자 데이터·설정·실행 중 process를 재사용하거나 삭제하지 않는다"). `destructive-operation-guard.ts:44-47`이 이미 `dataDirectory` 인자를 주입받으므로 테스트가 이를 쓰지 않는 것은 선택 문제다.
  2. Better Auth runtime 설정 객체 shape를 단정하는 `packages/infra/auth/src/learner/server.test.ts:50-119`와 `packages/infra/auth/src/admin/server.test.ts:39-70`은 동작이 아닌 설정을 검증하며(D-2, D-6, D-7), 같은 정책의 관찰 가능한 결과는 이미 통합 테스트가 전부 덮는다. `learner/server.ts:42-110`의 리터럴을 그대로 복사한 형태라 Better Auth 옵션 이름이 바뀔 때마다 동작 변화 없이 깨진다.
  3. 상수·타입·생성물 자체를 계약으로 삼은 tautological 테스트가 계약 패키지 전반에 퍼져 있다. `msw-fixtures.test.ts:81-84`, `status.test.ts:10-26`, `learner-read-model.test.ts:11-15`, `content.test.ts:170-190`, `learner-api.test.ts:120-124`, `identity/admin-ids.test.ts:13-14`, `private-no-store.test.ts:24-26`이 모두 D-1·D-8·D-9에 해당하며, 실패할 수 없거나 프로덕션 파생식을 재실행해 자기 자신과 비교한다.
