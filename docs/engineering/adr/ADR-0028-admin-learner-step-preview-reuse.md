# ADR-0028: 어드민 학습자 미리보기의 렌더러 재사용 경계

## 상태

채택됨

## 날짜

2026-07-31

## 맥락

`req-adm-3`과 `SCR-104`는 발행 전 학습자 화면을 확인하는 미리보기를 요구했으나 구현이 없었다. 계획 단계에서는 학습자 step renderer가 `apps/web`에만 있다고 보고 공유 패키지 추출이 필요하다고 판단했다.

구현 착수 시 확인한 사실은 다르다. 10개 스텝 타입의 시각 렌더러는 이미 전부 `@workspace/ui/components/lesson/`에 있고 학습자 앱이 이를 소비한다. `apps/web`에 남은 것은 학습 세션 view model과 답안 payload를 그 컴포넌트 props로 옮기는 얇은 adapter 3개(`MATCH`, `WRITE`, `AI_FEEDBACK`)다. 즉 추출할 렌더러가 없다.

`@workspace/ui`는 `@workspace/contracts`에 의존하지 않는다. 각 앱이 자기 타입을 UI props로 변환하는 구조이며, 이 경계는 UI 패키지를 계약 변경에서 분리해 준다.

## 결정

- 새 공유 패키지를 만들지 않는다. 어드민 미리보기는 학습자 앱과 같은 `@workspace/ui/components/lesson/*` 컴포넌트를 직접 사용한다.
- 어드민의 editor step DTO를 그 컴포넌트 props로 옮기는 adapter를 어드민이 소유한다.
- `@workspace/ui`에 `@workspace/contracts` 의존을 추가하지 않는다. 계약 타입 변환은 소비하는 앱에 남긴다.
- 미리보기는 읽기 전용이다. 답안 handler, 채점 상태와 AI 호출을 넘기지 않는다. 발행 전 검토 대상은 학습자가 보게 될 콘텐츠 배치이며 채점 동작이 아니다.

## 대안과 트레이드오프

- **학습자 renderer를 공유 패키지로 추출**: 계획의 원안이다. 추출할 대상이 이미 공유돼 있어 실익이 없고, 학습 세션 상태에 묶인 adapter까지 옮기면 공유 패키지가 학습자 런타임 관심사를 흡수한다.
- **`@workspace/ui`에 계약 의존 추가 후 어댑터를 UI에 배치**: 두 앱의 변환 중복은 사라지지만 UI 패키지가 계약 변경에 묶인다. 지금의 얇은 변환 중복보다 비용이 크다.
- **학습자 origin에 인증된 draft preview 경로 추가**: 실제 학습자 런타임을 그대로 쓰지만 API와 보안 경계를 넓힌다. 발행 전 검토 목적에는 과하다.

## 결과

어드민과 학습자가 같은 시각 컴포넌트를 쓰므로 미리보기와 실제 화면이 갈라지지 않는다. 두 앱이 각자 변환을 소유하는 중복은 남으며, 미리보기에 채점 상태나 상호작용이 필요해지면 변환을 공유 위치로 올리는 판단을 다시 한다.
