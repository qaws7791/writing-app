# ADR-0038: 점검 고칠 일의 1차 표면은 본문 인라인 마크다

## 상태

채택됨

## 날짜

2026-08-15

## 맥락

작성 세션의 핵심 루프는 점검 뒤 본문을 고치는 일이다. 2026-08-14 도킹 패널은 과제·점검 개요를 본문과 동시에 보게 했지만, 소프트 키보드가 뜨면 패널이 접혀 고칠 문장과 피드백이 한 화면에 남지 않는다. 당시 조사는 인라인 주석을 비범위로 두었다. Lexical `ComposeCanvas`가 도입된 뒤에는 저장 형식을 바꾸지 않고 구절에 마크를 붙일 수 있다.

## 결정

- 고칠 일의 1차 표면은 본문 인용 구절의 `MarkNode` 형광펜이다. 클릭하면 이유와 부분 수정 예문을 비모달 팝오버로 보여 준다. `제거`는 화면 세션에서만 마크를 걷는다.
- 점검 결과 패널은 잘된 점, 과제 미충족, 남은 고칠 일을 한 번에 훑는 개요다. 점검 성공 직후 패널을 자동으로 열지 않는다.
- 잘된 점과 과제 미충족은 위치가 없거나 없는 내용을 가리키므로 패널에만 둔다.
- 각 고칠 일은 본문에서 복사한 `quote`를 가진다. `quote`가 본문에 없으면 그 항목은 패널에만 나온다.
- 마크는 에디터 오버레이다. 본문 저장 형식은 일반 텍스트를 유지한다.
- 사용자가 직접 댓글을 달거나 협업 스레드를 두지 않는다.

## 고려한 대안

### 대안 1. 도킹 패널만 유지한다

- 장점: 화면 계약을 바꾸지 않는다.
- 단점: 키보드가 열린 동안 고칠 문장과 피드백을 동시에 볼 수 없다.

### 대안 2. 마크를 본문 JSON으로 저장한다

- 장점: 새로고침 뒤에도 제거 상태가 남는다.
- 단점: 평문 저장 계약과 글자 수·점검 입력을 바꾼다.

### 대안 3. 사용자가 선택 구간에 댓글을 직접 단다

- 장점: Lexical Playground Comment와 같다.
- 단점: AI 점검 결과를 문장에 붙이는 제품 루프가 아니다.

## 선택 근거

형광펜은 문장이 보이는 동안 키보드와 관계없이 어디를 고칠지 남긴다. 팝오버는 이유와 예문을 읽을 때만 연다. 패널은 전체 개요를 맡을 때 연다. 평문 저장을 지키면 점검·글자 수 계약을 건드리지 않는다.

## 결과

- 작성 세션과 writing-studio block은 `ComposeFeedbackMarksPlugin`으로 고칠 일을 본문에 붙인다.
- ADR-0037의 등록 노드에 `MarkNode`를 허용한다.
