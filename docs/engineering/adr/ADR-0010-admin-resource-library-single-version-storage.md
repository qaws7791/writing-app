# ADR-0010: 관리자 자료실 단일 버전 저장

## 상태

채택됨 — ADR-0004와 ADR-0005의 공동 편집·동기화 결정을 대체함

## 날짜

2026-07-16

## 맥락

자료실은 운영자가 프로젝트 소유 문서를 작성하고 관리자 AI가 활성 문서를 검색·조회하기 위해 필요하다. 기존 구현은 Yjs snapshot과 update log, HTTP transaction receipt, Markdown projection worker, 작업 공간 WebSocket과 client queue를 사용해 여러 관리자의 동시 편집을 병합했다.

제품 검토 결과 같은 문서의 실시간 공동 편집은 필수 요구가 아니다. 필요한 동시성은 한 관리자가 여러 탭이나 기기에서 같은 문서를 열었을 때 다른 저장을 조용히 덮어쓰지 않는 수준이다. 운영 데이터가 없으므로 구형 동기화 상태를 변환하거나 호환할 필요도 없다.

## 결정

- Markdown을 자료 본문의 유일한 영속 원본으로 둔다.
- Lexical은 GFM으로 손실 없이 표현되는 고정 블록을 편집하는 클라이언트 표현이다.
- 문서에는 충돌 감지용 단일 정수 `version`만 저장한다.
- 문서 조회는 현재 버전에 대응하는 강한 ETag를 반환한다.
- 저장은 `PUT /resources/documents/{documentId}`와 `If-Match`를 사용한다.
- 서버는 제목, Markdown, 검색 색인, 수정자·시각과 버전 증가를 하나의 SQLite transaction에서 갱신한다.
- 조건이 맞지 않으면 저장하지 않고 `412 Precondition Failed`와 최신 문서를 반환한다.
- 자동 병합, 강제 덮어쓰기와 사용자용 버전 기록을 제공하지 않는다.
- 트리는 전체 조회하고 탭 포커스 복귀와 화면 재진입 때 재검증한다.
- Yjs, collaboration 영속 상태, HTTP transaction sync, projection worker와 작업 공간 WebSocket을 제거한다.
- 활성 문서 제목·본문 SQLite FTS를 관리자 UI와 AI 읽기 도구가 공유한다.
- R2 이미지는 문서 종속 자산이며 AI는 필수 대체 텍스트만 읽는다.

## 고려한 대안

### 대안 1. 기존 Yjs 공동 편집 유지

- 장점: 동시 입력과 재연결 병합을 유지한다.
- 단점: 검증되지 않은 제품 가치 때문에 별도 동기화 런타임, 영속 상태와 실패 모드를 계속 유지해야 한다.

### 대안 2. 마지막 저장 우선

- 장점: API와 UI가 가장 단순하다.
- 단점: 오래 열린 탭이 최신 변경을 조용히 덮어써 내부 지식 원본을 손실할 수 있다.

### 대안 3. 사용자용 문서 버전 기록

- 장점: 과거 저장본을 비교하고 복원할 수 있다.
- 단점: 현재 요구인 충돌 방지보다 넓은 보존·조회·복원 제품을 추가한다. 초기 범위에서는 DB 백업과 휴지통으로 전체 장애와 삭제를 다룬다.

## 결과

- 자료실 본문 저장의 영속 상태는 Markdown과 단일 버전으로 축소된다.
- 다중 탭과 기기의 충돌은 숨기지 않고 사용자에게 명시적으로 해결을 요청한다.
- 다른 탭의 변경은 실시간으로 보이지 않을 수 있지만 포커스 복귀 시 최신 상태를 확인한다.
- AI는 저장이 성공한 활성 문서만 읽으므로 미저장 편집 내용이 지식 원본에 섞이지 않는다.
- 공동 편집 수렴·재연결·snapshot quota·transaction receipt·WebSocket backpressure 검증은 삭제 대상이 된다.
- R2와 SQLite는 단일 transaction을 공유할 수 없으므로 자산 삭제 실패를 구조화 로그로 관측하고 고아 객체 정리 경계를 별도로 검증해야 한다.

## 검증

- 같은 ETag를 가진 두 저장 중 하나만 성공하는 repository와 HTTP route 통합 테스트를 둔다.
- 충돌 응답이 최신 문서와 ETag를 제공하고 클라이언트가 로컬 편집을 유지하는지 확인한다.
- 제목·본문·검색 색인·버전 증가가 하나의 transaction에서 rollback되는지 확인한다.
- 지원 Lexical 상태의 Markdown 왕복 의미 보존을 검증한다.
- 공동 편집과 실시간 연결 코드, 테이블, 의존성과 실행 명령이 남지 않는지 정적 검사한다.

## 구현 상태

2026-07-16에 단일 버전 저장, 전체 트리, SQLite FTS, 재귀 휴지통, R2 자산 경계와 AI 읽기 도구를 구현했다. lint, typecheck, 전체 테스트, 관리자 앱과 관리자 API 빌드를 통과했고 실제 브라우저에서 다중 탭 충돌과 핵심 자료실 흐름을 확인했다. 운영 Cloudflare R2 자격 증명을 사용한 업로드·공개 조회·삭제 확인은 배포 환경에서 추가로 수행해야 한다.
