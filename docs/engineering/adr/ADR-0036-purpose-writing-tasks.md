# ADR-0036: 쓰기 탭을 목적 과제와 AI 점검으로 교체

## 상태

채택됨

## 날짜

2026-08-13

## 맥락

쓰기 탭은 방식 선택, 빈 화면, 자기 점검으로 동작했다. 학습자는 무엇부터 써야 하는지 알기 어렵고, 과제 조건에 맞춘 점검을 받을 수 없었다. ADR-0029는 레슨 `WRITE`·`AI_FEEDBACK`을 제거하고 당시 집중형 쓰기를 유지했다. 이번 결정은 그 집중형 흐름을 폐기하고 쓰기 탭을 과제 선택 → 작성 → AI 점검 → 수정 반복으로 교체한다. 레슨 `WRITE`는 되돌리지 않는다.

## 결정

- 집중형 쓰기 데이터와 자기 점검 API를 물리 삭제한다. 기존 글 행은 이전하지 않는다.
- 쓰기 과제는 `@workspace/writing`이 소유한다. content module의 코스 계층에 넣지 않는다.
- 학습자 글은 시작 시점 발행본에 고정한다.
- 점검은 서버가 저장한 본문을 OpenAI에 전달하고 구조화 결과만 저장한다. 원문은 event·log·감사에 넣지 않는다.
- 관리자 MCP writing-task Tool은 1차에 두지 않는다.

## 고려한 대안

### 대안 1. 집중형 쓰기 유지

- 장점: 변경 범위가 작다.
- 단점: 빈 화면과 자기 점검이 기획 합의와 어긋난다.

### 대안 2. 과제를 content module에 넣기

- 장점: 코스 발행 모델과 같은 모듈에 모인다.
- 단점: 코스·유닛·레슨·스텝 계층과 수명주기가 다르다.

### 대안 3. 레슨 `WRITE`를 복원해 과제를 스텝으로 흡수

- 장점: 레슨 진행 모델만 확장한다.
- 단점: ADR-0029가 제거한 중복과 개인정보 경계가 돌아온다.

## 선택 근거

쓰기 탭이 이미 독립 글의 자리다. 과제와 글, 점검을 한 module에 두면 발행 고정과 학습자 삭제를 한 경계에서 지킬 수 있다. OpenAI는 쓰기 점검에만 다시 연결하고 레슨 코칭 모듈은 복구하지 않는다.

## 결과

- 학습자 앱은 홈, 카탈로그, 작성 세션을 제공한다.
- 어드민은 코스 옆에 과제 목록과 편집을 제공한다.
- 개인정보 문서는 점검 목적의 외부 AI 전달과 첫 점검 고지를 포함한다.
