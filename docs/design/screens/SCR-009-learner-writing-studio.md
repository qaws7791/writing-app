# SCR-009 작성 세션

## 구현 탐색

현재 route는 [학습자 앱 route source](../../../apps/web/src/app)에서 확인한다.

## 목적

학습자가 고정된 과제 브리프를 보고 본문을 쓴 뒤, 같은 화면에서 AI 점검을 받고 고친다.

## 주요 사용자

- 글을 작성하는 학습자

## 정보 구조

- 쓰기 홈으로 돌아가기
- 과제 제목
- 과제 서랍 열기
- 최근 점검이 있으면 결과 서랍 열기
- 예외 저장 상태
- 본문 입력
- 글자 수
- `점검하기`
- 과제 브리프
- 점검 결과: 잘된 점, 과제 미충족(있으면), 고칠 일
- 첫 점검 전 외부 AI 전달 고지 dialog

## UI 기준

- `AppShell`을 사용하지 않는 몰입 화면이다.
- 기본 상태는 본문 종이다. 과제와 점검 결과는 한 번에 하나만 연다.
- 본문은 캔버스 위의 editorial 종이 표면이다. `bg-card`, `rounded-4xl`/`rounded-5xl`, 낮은 대비 `border`를 사용한다. 입력 중 포커스는 control `ring-3`이 아니라 캐럿과 종이 경계 변화로 전달한다.
- 본문은 Luma `ComposeEditor`에 일반 텍스트만 입력한다.
- 브리프는 Luma `WritingBrief` anatomy를 사용한다. 서랍 안을 카드로 다시 감싸지 않는다.
- 점검 결과는 Luma `FeedbackSummary`와 `Insight`를 사용한다.
- 평시 헤더는 나가기, 과제 제목, 과제 아이콘이다. 제목은 누르지 않는다. 난이도, 목표 글자 수, 평시 저장됨은 헤더에 두지 않는다.
- 저장 중·실패·충돌·오프라인만 제목 옆 짧은 상태로 바꾼다. 실패·충돌·오프라인은 본문 위 `Insight`와 `role="alert"`로 커진다. 평시 저장 완료는 시각 chrome 없이 `role="status"`로만 전달한다.
- 글자 수는 `ComposeMeter`로 현재 자를 표시한다. 최소 미달일 때만 최소 기준을 붙인다. 목표·최대는 과제 서랍 안에만 둔다.
- `점검하기`는 보이는 한국어 동사를 가진 채운 주요 버튼이다.
- 들어올 때 과제는 닫혀 있다. 과제와 결과 트리거는 아이콘 버튼이며 접근성 이름은 한국어다.
- 열린 서랍은 본문을 거의 가린다. 열린 동안 본문을 입력하지 않는다. 닫기는 서랍 안에 둔다. 플로팅 chrome은 서랍 뒤에 남는다.
- `lg` 미만은 상단 플로팅과 하단 플로팅을 나눈다. 과제는 하단 시트다. 소프트 키보드가 열려도 상·하단 chrome을 유지하고, 하단만 키보드 위로 올린다.
- `lg` 이상은 하단 없이 상단 한 줄이다. 왼쪽은 나가기·제목, 가운데는 과제·결과·글자 수, 오른쪽은 `점검하기`다. 서랍은 본문을 거의 가리는 오버레이다.
- 점검 성공 직후 결과 서랍을 연다. 과제가 열려 있으면 닫는다.
- 최근 성공 점검이 있으면 결과 아이콘으로 다시 연다. `점검하기`는 현재 본문으로 새 점검을 요청한다.
- 저장하지 않은 입력이 있으면 쓰기 홈 이동 전에 저장을 시도한다.

## 상태

- 작성 중
- 저장 중
- 저장됨
- 점검 중
- 점검 결과 있음
- 오프라인·저장 실패
- version 충돌
- 글 조회 실패
- 고지 확인 전

## 접근성

- 뒤로 가기, 본문, 과제 보기, 결과 보기, 점검은 키보드로 실행할 수 있어야 한다.
- 저장 중과 저장 완료, 점검 중은 `role="status"`로 전달한다.
- 저장 실패, version 충돌, 점검 실패는 `role="alert"`로 전달한다.
- 고지 dialog는 제목과 설명을 제공한다.
- 320px 화면과 텍스트 200% 확대에서 가로 스크롤이 생기지 않아야 한다.
