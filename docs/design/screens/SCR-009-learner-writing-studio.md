# SCR-009 작성 세션

## 구현 탐색

현재 route는 [학습자 앱 route source](../../../apps/web/src/app)에서 확인한다.

## 목적

학습자가 고정된 과제 브리프를 보고 본문을 쓴 뒤, 같은 화면에서 AI 점검과 마치기를 한다.

## 주요 사용자

- 글을 작성하는 학습자

## 정보 구조

- 쓰기 홈으로 돌아가기
- 과제 제목과 난이도·목표 글자 수
- 저장 상태
- 접을 수 있는 과제 브리프
- 본문 입력
- 글자 수
- 점검 결과: 잘된 점, 과제 미충족(있으면), 고칠 일
- `점검하기`와 `마치기`
- 첫 점검 전 외부 AI 전달 고지 dialog

## UI 기준

- `AppShell`을 사용하지 않는 몰입 화면이다.
- 본문은 Luma `ComposeEditor`에 일반 텍스트만 입력한다.
- 브리프는 Luma `WritingBrief` anatomy를 사용한다.
- 점검 결과는 Luma `FeedbackSummary`와 `Insight`를 사용한다.
- 저장 상태는 `Badge` 또는 `role="status"`로 표시한다.
- 글자 수는 `ComposeMeter`로 최소·목표 글자 수를 함께 표시한다.
- 저장 충돌과 실패, 점검 실패는 Luma `Insight`로 표시한다.
- 데스크톱에서 브리프는 접을 수 있는 옆 열이다. 좁은 화면에서는 하단 `Sheet`로 연다.
- 하단 주요 행동은 모바일 safe area와 소프트 키보드를 가리지 않아야 한다.
- 저장하지 않은 입력이 있으면 쓰기 홈 이동 전에 저장을 시도한다.

## 상태

- 작성 중
- 저장 중
- 저장됨
- 점검 중
- 점검 결과 있음
- 완료
- 오프라인·저장 실패
- version 충돌
- 글 조회 실패
- 고지 확인 전

## 접근성

- 뒤로 가기, 본문, 과제 보기, 점검, 마치기는 키보드로 실행할 수 있어야 한다.
- 저장 중과 저장 완료, 점검 중은 `role="status"`로 전달한다.
- 저장 실패, version 충돌, 점검 실패는 `role="alert"`로 전달한다.
- 고지 dialog는 제목과 설명을 제공한다.
- 320px 화면과 텍스트 200% 확대에서 가로 스크롤이 생기지 않아야 한다.
