# SCR-103 콘텐츠 관리

## 구현 탐색

현재 route는 [관리자 앱 route source](../../../apps/admin/src/app)에서 확인한다.

## 목적

관리자가 코스를 필터링하고 생성하거나 보관한다.

## 주요 사용자

- 소유자 관리자

## 정보 구조

- `PageHeader`와 새 코스 생성 행동
- 강의명 검색과 카테고리·상태 필터, 결과 개수
- 처리 상태 메시지
- 코스 목록 table: 강의명, 카테고리, 유닛 수, 레슨 수, 행 작업
- 페이지 크기 선택과 페이지 이동
- `AlertDialog` 코스 보관 확인

## UI 기준

- 필터는 `GET` form으로 제출하고 검색어·카테고리·상태·페이지 크기를 query string에 보존한다.
- 검색 입력은 제출 버튼과 함께 두고 접근 가능한 한국어 이름을 가진다.
- 행 썸네일은 업로드한 코스 표지를 우선 사용하고 없으면 기본 이미지를 사용한다.
- 카테고리 선택지는 코스 카테고리 계약이 소유한다. 화면에 값 목록을 따로 두지 않는다.
- 보관 행동은 포인터 hover에 의존하지 않고 항상 확인할 수 있어야 한다.
- 보관된 코스의 행 작업은 보관 대신 보관 해제를 제공한다. 보관은 확인 dialog와 위험 작업 표현을 쓰고 보관 해제는 쓰지 않는다.
- 새 코스 생성은 `PageHeader`의 행동 영역에 둔다.

## 상태

- 목록 조회 성공
- 목록 조회 실패
- 생성 진행 중
- 보관 확인
- 보관 진행 중
- 보관 해제 진행 중
- 처리 완료 또는 실패 메시지

## 접근성

- 필터 폼은 `aria-label="코스 필터"`를 제공한다.
- table header는 `scope="col"`을 사용하며 행 작업 열도 접근 가능한 이름을 가진다.
- 행 작업 버튼은 대상 코스를 구분할 수 있는 접근성 이름을 가진다.
- 확인 dialog는 `AlertDialog`를 사용하며 `role="alertdialog"` 의미와 제목/설명 관계를 제공한다.
