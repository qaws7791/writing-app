# SCR-109 스텝 디버그

## 라우트

- `apps/admin`: `/debug/steps`

## 목적

관리자가 어드민 내부 QA 도구에서 확정 스텝 타입의 렌더링, 샘플 data, schema 검증 상태를 확인한다.

## 주요 사용자

- 콘텐츠 관리자
- 개발과 QA를 겸하는 소유자 관리자

## 정보 구조

- `AdminHeader`
- 스텝 타입 선택
- 렌더러 미리보기
- 샘플 data JSON
- schema 요약
- validation 결과
- 복사 행동

## UI 기준

- 화면 제목은 `스텝 디버그`다.
- 학습자 앱에는 `/tour` 또는 디버그 전용 페이지를 만들지 않는다.
- 주요 사이드바 메뉴에는 노출하지 않는 내부 QA 화면이다.
- 스텝 타입 선택은 확정 스텝 타입 10개를 기준으로 한다.
- 렌더러 미리보기는 학습자 레슨 화면과 같은 렌더링 규칙을 사용한다.
- 샘플 data와 schema 요약은 별도 패널로 분리한다.
- 복사 행동은 schema 또는 샘플 data를 클립보드에 복사하는 보조 행동이다.
- 샘플 data 편집이 필요하면 검증 결과만 갱신하고 실제 콘텐츠 저장은 수행하지 않는다.

## 상태

- 스텝 타입 선택 전
- 샘플 data 유효
- 샘플 data 검증 실패
- schema 또는 샘플 data 복사 성공
- schema 또는 샘플 data 복사 실패

## 접근성

- 스텝 타입 선택 control은 한국어 label을 가진다.
- validation 결과는 `role="status"`로 알린다.
- 검증 실패는 `role="alert"`로 표시한다.
- 복사 버튼은 복사 대상이 schema인지 샘플 data인지 명확히 말한다.
