# SCR-002 학습자 로그인

## 구현 탐색

현재 route는 [학습자 앱 route source](../../../apps/web/src/app)에서 확인한다.

## 목적

학습자가 이메일 또는 Google 인증으로 학습 앱에 진입한다.

## 주요 사용자

- 로그인하지 않은 학습자

## 정보 구조

- 제품명
- Google 로그인 버튼
- 이메일 로그인·가입 전환
- 이름, 이메일, 비밀번호 입력
- 가입 완료 화면: 보낸 주소, 확인 안내, 로그인 복귀, 확인 메일 재전송
- 확인 전 로그인: 같은 메일 확인 화면
- 가입·확인·재전송·오류 안내
- 비밀번호 재설정 요청 전환

## UI 기준

- 화면은 Luma semantic token과 `login-social` 조합을 따른다.
- 기본 화면은 Google 로그인을 이메일 입력보다 먼저 제공하고, Google을 주 버튼으로 둔다. 이메일 제출은 낮은 대비의 보조 버튼이다.
- Google 버튼 문구는 `Google로 로그인`을 쓰고, 로고는 왼쪽 20px, 라벨은 남은 영역의 중앙, 왼쪽과 같은 폭의 빈 칸을 오른쪽에 둔다. 제품 radius와 서체는 유지한다.
- 이메일 로그인과 가입은 `Tabs`, `Field`, `Input`, `Button` 조합을 사용한다.
- Google 로그인과 이메일 입력은 `FieldSeparator`로 구분한다.
- 가입이 끝나거나 확인 전 로그인을 시도하면 Google, 탭, 입력 폼을 숨기고 같은 메일 확인 화면으로 바꾼다. 화면은 확인 마크, 보낸 주소, 로그인 복귀를 제공한다. 성공 사실은 제목과 보낸 주소로 표시하고 도움말 회색 문단으로 두지 않는다.
- 가입 비밀번호 규칙은 미충족일 때만 도움말로 보이고, 충족되면 짧은 확인으로 바뀐다.
- 로그인 제목은 `글결에 로그인`처럼 문장으로 쓴다. 브랜드 마침표는 조사 앞에 두지 않는다.
- 가입 제목은 `글결. 시작하기` 로크업을 유지한다.
- 실패 메시지는 사용자가 다시 시도할 수 있게 한국어로 표시한다.
- 재설정 요청 완료와 이메일 확인 완료는 제목 또는 부제로 표시한다.
- 가입 완료 안내는 중복 계정 여부를 드러내지 않는다.
- 재설정 요청 완료 안내는 계정 존재 여부를 드러내지 않는다.
- 재설정 링크 화면은 새 비밀번호와 확인 입력을 제공하고 만료·사용 완료 상태에서는 변경 행동을 비활성화한다.

## 상태

- 기본
- 인증 요청 중
- 가입 완료 전용 화면과 확인 메일 재전송
- 이메일 확인 성공·실패
- 확인 전 로그인 차단. 같은 메일 확인 화면으로 전환
- 비밀번호 재설정 요청, token 유효·무효, 변경 완료
- Google 계정 연결 실패의 일반화된 안내
- 인증 실패
- 안전한 `next` 경로 확인 후 이동

## 접근성

- 로그인·가입 전환과 모든 행동 버튼은 키보드로 실행 가능해야 한다.
- 메일 확인 화면으로 바뀌면 제목으로 포커스를 옮긴다.
- 입력에는 보이는 한국어 label과 적절한 `autocomplete`를 제공한다.
- 오류는 `role="alert"`로 노출한다.
- 외부 OAuth 동작을 설명하는 텍스트는 한국어로 제공한다.
