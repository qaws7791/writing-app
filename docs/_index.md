# 문서 인덱스

## 목적

이 문서는 `docs` 전체의 단일 진입점이다. 먼저 사실별 권위 소유자를 확인하고 제품, 디자인, 엔지니어링의 현재 문서로 이동한다. 진행 중 작업과 보관 기록은 현재 사실과 분리해서 탐색한다.

파일 목록에서 가장 먼저 보이도록 파일 이름에 언더바를 사용한다.

## 탐색 순서

1. 사실의 최종 소유자를 판단할 때는 `docs/authority-map.md`를 확인한다.
2. 제품의 문제, 목표, 범위, 사용자 흐름은 `docs/product/_index.md`에서 시작한다.
3. 화면 구조, 시각 기준, 컴포넌트, 접근성은 `docs/design/_index.md`에서 시작한다.
4. 시스템 구조, API, 데이터, 인증, 운영 기준은 `docs/engineering/_index.md`에서 시작한다.
5. 현재 진행 중인 작업의 범위가 필요할 때만 `docs/work/_index.md`를 확인한다.
6. `docs/archive`는 과거 증거나 회고가 필요한 경우에만 확인하며 현재 사실 판정에는 사용하지 않는다.

## 디렉토리 지도

| 경로                | 목적                                                                           |
| ------------------- | ------------------------------------------------------------------------------ |
| `docs/`             | 프로젝트 문서 전체의 루트이다. 이 인덱스는 문서 탐색의 첫 진입점이다.          |
| `docs/product/`     | 제품 문제, 비전, 유저 스토리, 요구사항, 콘텐츠, 운영 기준을 기록한다.          |
| `docs/design/`      | 정보 구조, 화면 명세, 디자인 토큰, UI 패턴, 접근성, 에셋 기준을 기록한다.      |
| `docs/engineering/` | 시스템 구조, 기술 스택, API와 데이터 계약, 보안, 테스트, 운영 기준을 기록한다. |
| `docs/work/`        | 진행 중인 계획, 조사와 감사 같은 한시 문서를 작업 단위로 기록한다.             |
| `docs/archive/`     | 완료되거나 폐기된 작업 기록을 보관하며 현재 사실의 근거에서는 제외한다.        |

## 파일 지도

| 파일                         | 목적                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| `docs/_index.md`             | 문서 전체의 진입점과 최상위 탐색 지도를 제공한다.                     |
| `docs/authority-map.md`      | 사실별 권위 소유자와 설명 문서의 관계를 정의한다.                     |
| `docs/glossary.md`           | 제품과 아키텍처에서 공통으로 사용하는 용어를 정의한다.                |
| `docs/product/_index.md`     | 제품 문서의 목적, 읽는 순서, 파일별 책임을 안내한다.                  |
| `docs/design/_index.md`      | 디자인 문서의 목적, 화면 명세 위치, 파일별 책임을 안내한다.           |
| `docs/engineering/_index.md` | 엔지니어링 문서의 목적, 하위 계약과 ADR 위치, 파일별 책임을 안내한다. |
| `docs/work/_index.md`        | 진행 중인 한시 작업과 문서 생명주기를 안내한다.                       |
| `docs/archive/_index.md`     | 완료·폐기된 작업 기록과 보관 원칙을 안내한다.                         |

## 관리 기준

문서를 추가, 이동, 삭제할 때는 해당 디렉토리의 `_index.md`를 함께 갱신한다. 여러 영역에 걸친 변경이라면 권위 지도를 따라 제품 기준을 먼저 정리하고, 디자인과 엔지니어링 문서가 그 기준을 어떻게 구현하는지 연결한다. 새 한시 문서는 `docs/work/<yyyy-mm-dd-name>/`에 만들고 완료 시 같은 작업 단위를 `docs/archive/<yyyy-mm-dd-name>/`로 이동한다. 파일별 문서 유형 metadata는 두지 않으며 디렉터리가 수명과 탐색 범위를 표현한다.
