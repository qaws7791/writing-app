# 문서 인덱스

## 목적

이 문서는 `docs` 전체의 진입점이다. 제품, 디자인, 엔지니어링 문서의 책임 범위를 먼저 확인하고 필요한 하위 인덱스로 이동하기 위해 사용한다.

파일 목록에서 가장 먼저 보이도록 파일 이름에 언더바를 사용한다.

## 탐색 순서

1. 제품의 문제, 목표, 범위, 사용자 흐름을 확인할 때는 `docs/product/_index.md`에서 시작한다.
2. 화면 구조, 시각 기준, 컴포넌트, 접근성을 확인할 때는 `docs/design/_index.md`에서 시작한다.
3. 시스템 구조, API, 데이터, 인증, 운영 기준을 확인할 때는 `docs/engineering/_index.md`에서 시작한다.

## 디렉토리 지도

| 경로                | 목적                                                                           |
| ------------------- | ------------------------------------------------------------------------------ |
| `docs/`             | 프로젝트 문서 전체의 루트이다. 이 인덱스는 문서 탐색의 첫 진입점이다.          |
| `docs/product/`     | 제품 문제, 비전, 유저 스토리, 요구사항, 콘텐츠, 운영 기준을 기록한다.          |
| `docs/design/`      | 정보 구조, 화면 명세, 디자인 토큰, UI 패턴, 접근성, 에셋 기준을 기록한다.      |
| `docs/engineering/` | 시스템 구조, 기술 스택, API와 데이터 계약, 보안, 테스트, 운영 기준을 기록한다. |

## 파일 지도

| 파일                         | 목적                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| `docs/_index.md`             | 문서 전체의 진입점과 최상위 탐색 지도를 제공한다.                     |
| `docs/product/_index.md`     | 제품 문서의 목적, 읽는 순서, 파일별 책임을 안내한다.                  |
| `docs/design/_index.md`      | 디자인 문서의 목적, 화면 명세 위치, 파일별 책임을 안내한다.           |
| `docs/engineering/_index.md` | 엔지니어링 문서의 목적, 하위 계약과 ADR 위치, 파일별 책임을 안내한다. |

## 관리 기준

문서를 추가, 이동, 삭제할 때는 해당 디렉토리의 `_index.md`를 함께 갱신한다. 여러 영역에 걸친 변경이라면 제품 기준을 먼저 정리하고, 디자인과 엔지니어링 문서가 그 기준을 어떻게 구현하는지 연결한다. 계속 증가하는 제품 문서는 개별 파일로 관리하고 상위 인덱스에서 추적한다.
