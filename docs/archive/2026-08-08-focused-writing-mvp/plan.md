# 초기 쓰기 기능 작업 계획

## 문서 상태

- 상태: 구현 완료, 검증 제한 기록
- 작업일: 2026-08-08
- 작업 단위: 학습자 앱의 주요 기능으로 `쓰기` 추가
- 권위 경계: 이 문서는 구현 전 계획이다. 현재 제품 사실과 구현 계약은 관련 제품·디자인·엔지니어링 권위 문서와 코드가 소유한다.

## 결정

- 기존 레슨의 `AI_FEEDBACK` 제거는 이번 작업에서 다루지 않는다.
- 초기 쓰기 기능은 AI를 호출하지 않는다.
- `쓰기`는 `배우기`와 나란한 학습자 앱의 주요 진입점으로 둔다.
- 초기 쓰기 기능은 일반 텍스트 작성과 자기 점검에 집중한다.
- 초기 쓰기 기능은 문서 편집 프로그램을 모방하지 않는다.

## 제품 가설

학습자는 복잡한 편집 도구보다 집중할 수 있는 작성 공간이 필요하다. 글결은 빈 메모장 대신 짧은 쓰기 방향과 자기 점검을 제공해야 한다. 자기 점검 뒤 다시 다듬는 행동이 초기 쓰기 기능의 교육적 가치다.

## 초기 사용자 가치

1. 사용자는 주요 내비게이션에서 `쓰기`를 선택한다.
2. 사용자는 한 번의 선택으로 쓰기 방식을 정한다.
3. 사용자는 방해 요소가 없는 화면에서 제목과 본문을 작성한다.
4. 시스템은 작성 내용을 자동 저장한다.
5. 사용자는 세 가지 질문으로 자신의 글을 점검한다.
6. 사용자는 글을 다시 다듬거나 점검을 마친다.
7. 사용자는 저장한 글을 쓰기 홈에서 다시 연다.

## 제품 개념

| 개념         | 의미                                                       |
| ------------ | ---------------------------------------------------------- |
| 쓰기         | 학습자 앱의 최상위 작성 영역                               |
| 글           | 학습자가 소유하는 제목과 일반 텍스트 본문                  |
| 쓰기 방식    | `자유롭게 쓰기`, `설명하기`, `주장하기` 중 하나            |
| 자기 점검    | 쓰기 방식에 맞는 세 질문으로 글을 다시 읽는 단계           |
| 점검 완료 글 | 자기 점검을 마친 글. 본문을 수정하면 다시 작성 중으로 바뀜 |

`글`은 레슨의 `WRITE` 답안과 다른 수명주기를 가진다. `글`은 curriculum revision에 속하지 않으며 학습자가 독립적으로 작성하고 다시 연다.

## 초기 범위

### 쓰기 홈

- 주요 행동은 `새 글 쓰기` 하나다.
- 저장한 글은 제목, 쓰기 방식, 최근 수정 시각과 상태만 표시한다.
- 빈 상태는 새 글을 시작하는 행동만 제공한다.
- 글 삭제는 확인 절차를 거친다.

### 쓰기 시작

사용자는 다음 세 방식 중 하나만 선택한다.

| 쓰기 방식     | 작성 전 안내                                            |
| ------------- | ------------------------------------------------------- |
| 자유롭게 쓰기 | 지금 떠오르는 장면이나 생각 한 가지에서 시작한다.       |
| 설명하기      | 처음 읽는 사람에게 무엇을 어떤 순서로 알려줄지 정한다.  |
| 주장하기      | 전하고 싶은 주장과 그 주장을 받치는 이유를 먼저 정한다. |

선택 뒤 추가 설문이나 설정 없이 편집 화면으로 이동한다.

### 집중형 편집 화면

- 편집 화면은 글로벌 내비게이션을 숨긴다.
- 본문은 한 열로 표시한다.
- 화면에는 뒤로 가기, 제목, 본문, 저장 상태와 `글 점검하기`만 둔다.
- 본문은 일반 텍스트만 지원한다.
- 입력이 800ms 동안 멈추면 저장을 요청한다.
- 입력 영역을 벗어나거나 화면을 나갈 때 대기 중인 저장을 즉시 요청한다.
- 저장 상태는 `저장 중`, `저장됨`, `저장하지 못함`으로 표시한다.
- 글자 수는 보조 정보로만 표시한다.
- 목표 글자 수와 작성 시간은 성취 기준으로 사용하지 않는다.

네트워크 오류는 작성 내용을 잃게 할 수 있다. 시스템은 미전송 본문을 화면 상태에 유지해야 한다. 저장되지 않은 본문이 남아 있으면 화면을 나가기 전에 사용자에게 알려야 한다.

### 자기 점검

자기 점검은 편집 화면 위에 패널을 겹치지 않고 별도 집중 단계로 연다. 사용자는 자신의 글과 세 질문만 확인한다.

| 쓰기 방식     | 자기 점검 질문                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------- |
| 자유롭게 쓰기 | 한 가지 중심이 보이는가? 문단마다 한 내용만 담았는가? 없어도 의미가 같은 문장을 덜어낼 수 있는가? |
| 설명하기      | 처음 읽는 사람이 대상을 알 수 있는가? 정보 순서가 자연스러운가? 이해를 돕는 예시가 있는가?        |
| 주장하기      | 주장이 한 문장으로 드러나는가? 주장을 받치는 이유가 있는가? 다른 관점에서 생길 질문을 고려했는가? |

- 자기 점검은 점수를 만들지 않는다.
- 자기 점검은 정답을 판정하지 않는다.
- 사용자는 `다시 다듬기` 또는 `점검 마치기`를 선택한다.
- `다시 다듬기`는 기존 본문을 유지한 채 편집 화면으로 돌아간다.
- `점검 마치기`는 글 상태와 점검 완료 시각을 저장한다.

## UI·UX 제한

다음 요소는 초기 범위에 추가하지 않는다.

- 리치 텍스트와 마크다운 서식
- 글꼴, 글자 크기, 정렬, 색상과 문단 스타일 도구
- 리본, 도구 모음, 사이드바, 속성 패널과 다중 패널
- 페이지 크기, 여백, 머리말, 꼬리말과 인쇄 레이아웃
- 표, 이미지, 도형, 각주, 수식과 파일 첨부
- 블록 편집, 드래그 재배치와 명령 팔레트
- 폴더, 태그, 검색과 정렬 설정
- 실시간 협업, 댓글, 공유와 공개 발행
- 가져오기, 내보내기와 PDF 생성
- 수정 이력, 변경 비교와 복원
- AI 생성, AI 피드백과 자동 교정

편집 화면은 중첩 카드와 반복 애니메이션을 사용하지 않는다. 주요 행동은 화면마다 하나만 둔다. 교육 안내는 작성 영역을 가리거나 작성 중에 반복 노출하지 않는다.

## 데이터와 책임 경계

- 새 `writing` 모듈이 글의 생성, 조회, 저장, 점검 완료와 삭제를 소유한다.
- 글은 학습자, 쓰기 방식, 제목, 본문, 상태, 저장 version과 생성·수정·점검 완료 시각을 가진다.
- 저장은 version 비교로 충돌을 확인한다.
- 충돌한 저장은 서버 글을 조용히 덮어쓰지 않는다.
- 충돌이 발생하면 화면은 미전송 본문을 보존하고 다시 불러오기 또는 재시도 행동을 제공한다.
- 글 원문은 분석 event, 일반 log와 오류 payload에 포함하지 않는다.
- 학습자 삭제 수명주기는 글 원문도 함께 삭제해야 한다.
- 운영 지표는 글 원문을 사용하지 않는다.

초기 범위는 오프라인 작성을 지원하지 않는다. 네트워크가 끊기면 현재 화면의 입력을 보존하고 재연결 뒤 저장을 다시 시도한다.

## 상태와 오류

- 쓰기 홈: 로딩, 글 있음, 빈 상태, 조회 실패
- 편집 화면: 작성 중, 저장 중, 저장됨, 저장 실패, version 충돌
- 자기 점검: 점검 전, 다시 다듬기, 점검 완료 저장 중, 저장 실패
- 삭제: 확인 전, 삭제 중, 삭제 완료, 삭제 실패

오류 메시지는 작성 내용이 보존되었는지 먼저 알려야 한다. 내부 예외와 provider 원문은 화면에 표시하지 않는다.

## 접근성

- 제목과 본문에는 보이는 한국어 label을 제공한다.
- 모든 행동은 키보드로 실행할 수 있어야 한다.
- 저장 상태는 `role="status"`, 저장 실패는 `role="alert"`로 전달한다.
- 모바일 소프트 키보드는 본문과 주요 행동을 가리지 않아야 한다.
- 320px 화면에서 가로 스크롤 없이 작성과 자기 점검을 완료할 수 있어야 한다.
- 텍스트를 200% 확대해도 제목, 본문과 주요 행동이 잘리지 않아야 한다.

## 초기 측정

다음 event만 수집한다.

- 글 생성
- 자기 점검 시작
- 자기 점검 뒤 본문 수정
- 자기 점검 완료
- 글 삭제

초기 성공 지표는 `자기 점검 시작률`과 `자기 점검 뒤 수정률`이다. 글자 수, 체류 시간과 생성한 글 수는 교육 효과 지표로 사용하지 않는다.

## 구현 순서

1. 제품 범위, 유저 스토리와 요구사항에 초기 쓰기 기능을 승인한다.
2. 정보 구조와 쓰기 홈·편집·자기 점검 화면 계약을 승인한다.
3. `writing` 모듈의 글 저장 계약과 학습자 삭제 경계를 구현한다.
4. 쓰기 홈과 주요 내비게이션 진입점을 구현한다.
5. 집중형 편집 화면과 자동 저장을 구현한다.
6. 쓰기 방식별 자기 점검을 구현한다.
7. 접근성, 저장 실패, 충돌과 삭제 흐름을 검증한다.
8. 원문 없는 최소 event와 운영 조회를 구현한다.

## 완료 기준

- 사용자는 `쓰기` 화면에 진입한 뒤 두 번 이하의 행동으로 본문 작성을 시작한다.
- 사용자는 제목과 본문 외의 설정 없이 초고를 작성한다.
- 작성 중에는 서식 도구, 사이드바와 다중 패널이 보이지 않는다.
- 저장 성공, 실패와 충돌 상태가 입력 가까이에 표시된다.
- 사용자는 세 질문으로 자기 점검을 마치거나 다시 다듬는다.
- 자기 점검 뒤 본문 수정 여부를 원문 없이 측정한다.
- 글 원문은 학습자 삭제 경계에서 제거된다.
- 관련 정적 검사, 단위 테스트, Storybook 검증, E2E와 build가 통과한다.

## 구현 결과

- 제품·디자인·엔지니어링 권위 문서에 초기 쓰기 기능 계약을 반영했다.
- `writing` 모듈과 SQLite 저장소, HTTP API, 삭제 수명주기를 구현했다.
- 쓰기 홈, 집중형 편집 화면, 800ms 자동 저장과 자기 점검 화면을 구현했다.
- 원문 없는 자기 점검 시작률과 자기 점검 뒤 수정률을 운영 대시보드에 추가했다.
