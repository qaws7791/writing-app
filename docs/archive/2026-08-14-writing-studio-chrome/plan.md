# 작성 세션 chrome과 마치기 제거

## 문서 상태

- 상태: 구현·검증 완료
- 기준 날짜: 2026-08-14
- 이 문서는 한시 계획이다. 현재 제품·화면·데이터 사실의 권위 소스가 아니다.

## 목적

작성 세션의 기본 상태를 본문 종이로 둔다.

과제와 점검은 필요할 때만 본문 위를 덮는 서랍으로 연다.

글에서 `마치기`와 `작성 중`/`완료` 구분을 제거한다.

점검은 현재 본문으로 새 결과를 만들고, 최근 성공 1건은 본문이 바뀌어도 다시 볼 수 있게 한다.

## 고정 계약

### 제품

1. 글에 `마치기`를 두지 않는다. 학습자에게 `작성 중`/`완료` 상태를 보이지 않는다.
2. 쓰기 홈은 탭 없는 단일 목록이다. 모든 글은 이어쓰기 대상이다.
3. `점검하기`는 지금 저장한 본문을 기준으로 새 결과를 만든다.
4. 최근 성공 점검 1건만 둔다. 새 성공 점검이 이전 결과를 바꾼다.
5. 본문을 고친 뒤에도 결과 아이콘으로 최근 1건을 다시 연다. 이전 본문 기준임을 따로 알리지 않는다.
6. 최소 글자와 하루 성공 한도는 유지한다. 다시 점검도 한 번을 쓴다.
7. 첫 `점검하기` 직전 외부 AI 전달 고지는 유지한다.
8. 글 완료 event는 더 이상 기록하지 않는다. 글 생성, 점검 성공, 점검 뒤 본문 수정, 글 삭제는 유지한다.

### 작성 세션 chrome

1. 화면의 기본 상태는 본문 종이다. `AppShell`은 쓰지 않는다.
2. 과제와 점검 결과는 한 번에 하나만 연다.
3. 열린 서랍은 본문을 거의 가린다. 열린 동안 본문을 입력하지 않는다.
4. 작성 화면에 들어올 때 과제는 닫혀 있다.
5. 평시 헤더는 나가기, 과제 제목, 과제 아이콘이다. 제목은 누르지 않는다.
6. 난이도, 목표 글자 수, 평시 `저장됨`은 헤더에 두지 않는다.
7. 저장 중·실패·충돌·오프라인만 제목 옆 짧은 상태로 바꾼다. 실패·충돌·오프라인은 본문 위 `Insight`로 커진다.
8. 글자 수는 현재 자만 보인다. 최소 미달일 때만 최소 기준을 붙인다. 목표·최대는 과제 서랍 안에만 둔다.
9. `점검하기`는 보이는 한국어 동사를 유지하는 채운 주요 버튼이다. 결과가 있어도 무게를 바꾸지 않는다.
10. 점검 성공 직후 결과 서랍을 연다. 과제가 열려 있으면 닫는다.
11. 성공 결과가 있는 동안 상단에 결과 아이콘을 둔다. 이 아이콘은 최근 1건을 다시 연다. `점검하기`는 새 점검을 요청한다.
12. 서랍이 열리면 플로팅 chrome은 뒤에 남고, 닫기는 서랍 안에만 둔다.
13. 과제와 결과 트리거는 아이콘 버튼이다. 접근성 이름은 한국어다.
14. 시각은 현재 종이 표면 언어를 유지한다. iOS 블러를 흉내 내지 않는다.

### 폭

| 폭        | chrome                                                                                                                                               | 과제·점검                          |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `lg` 미만 | 상단 플로팅: 나가기, 제목, 예외 저장 상태, 과제, 결과(있을 때). 하단 플로팅: 글자 수, `점검하기`. 키보드는 둘 다 유지하고 하단만 키보드 위로 올린다. | 아래에서 거의 끝까지 올라오는 시트 |
| `lg` 이상 | 하단 없음. 왼쪽 나가기·제목, 가운데 과제·결과·글자 수, 오른쪽 `점검하기`                                                                             | 본문을 거의 가리는 오버레이        |

### 의도적으로 버린 것

- 과제 \| 본문 \| 점검 3열
- 본문 아래 점검 적재
- 빈 본문에서 과제를 미리 열어 두기
- 연 채로 본문 쓰기
- 점검 이력 목록
- 포커스 모드, 타이머, 패널 폭 드래그

## 범위

### 포함

- 위 권위 문서 갱신
- 글 상태와 마치기 HTTP·도메인·영속화 제거
- 최근 성공 점검 1건을 본문 version과 달라도 조회하는 규칙
- 기존 `complete` 글 행을 단일 글 목록에 맞게 맞추는 migration
- 쓰기 홈 단일 목록
- 작성 세션 shell·chrome
- Luma `writing-studio`, `writing-home` 블록과 UI 문서 미러
- 글 완료에 묶인 학습자·모듈 테스트

### 제외

- 레슨 `WRITE` 스텝과 레슨 AI 코칭
- 리치 텍스트, 첨부, 공유
- 점검 프롬프트·결과 스키마 변경
- 하루 한도 값 변경. 한도 값은 환경 설정이 소유한다.
- 관리자 과제 편집 화면의 정보 구조 변경

## 구현 순서

제품 기준이 이 계약과 어긋난 채로 UI만 바꾸지 않는다.

1. `US-LRN-12`, `REQ-LRN-11`, 용어집, 학습자 여정, 지표를 이 계약으로 고친다.
2. `SCR-008`, `SCR-009`, 쓰기 패턴, 접근성을 고친다.
3. 데이터 모델과 엔지니어링 검증 문장을 고친다.
4. writing module에서 마치기 전이, `canComplete`, 글 완료 event, 본문 변경 시 점검 삭제·무효를 제거한다. 최근 성공 점검 1건을 글에 남긴다.
5. 학습자 HTTP 계약과 홈 목록 조회에서 완료 필터를 제거한다.
6. 작성 세션 shell을 플로팅 chrome과 단일 서랍으로 바꾼다. 쓰기 홈 탭을 제거한다.
7. 공유 UI 블록과 `apps/ui` 예제를 같은 뼈대로 맞춘다.
8. 정의된 검증을 실행한다.

현재 코드 탐색은 다음에서 시작한다.

- 작성 세션: `apps/web/src/features/writing/ui/`
- 쓰기 홈: `apps/web/src/features/writing/ui/writing-home-page.tsx`
- 도메인: `packages/modules/writing/src/domain/`
- HTTP 계약: `packages/shared/contracts/src/writing/`
- 블록: `packages/shared/ui/src/blocks/writing-studio.tsx`, `writing-home.tsx`

## 완료 조건

- 권위 문서가 이 계약과 같은 말을 한다. 마치기와 완료 글이 현재 사실로 남아 있지 않다.
- 학습자는 글을 마치고 완료 탭으로 나눌 수 없다.
- 작성 세션 평시 화면은 본문과 축소 chrome만 보인다.
- `점검하기`는 현재 본문으로 새 결과를 만들고 결과 서랍을 연다.
- 결과 아이콘은 최근 1건을 본문 변경 뒤에도 다시 연다.
- `lg` 미만은 상·하 플로팅, `lg` 이상은 상단 한 줄이다.
- 기존 `complete` 글은 단일 목록에서 이어 쓸 수 있다.
- Markdown 변경은 `bun oxfmt --check`로 확인한다. 코드 변경은 `bun run ci:static`, `bun run ci:tests`, `bun run build`를 통과한다. UI 블록을 바꾸면 UI 문서 검증 티어도 실행한다.
