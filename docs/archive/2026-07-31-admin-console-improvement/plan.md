## 확정된 결정

2026-07-31 승인. 각 결정의 대안과 판단 근거는 이 문서의 이전 revision에 있다.

### D1 = C. 관리자 계정 화면을 만들지 않는다

`req-adm-6`의 "관리자 계정 관리 메뉴" 비범위를 유지한다. 비밀번호 회전은 [release runbook](../../engineering/release-runbook.md)의 운영 절차로 계속 처리하고, `POST /api/admin/auth/change-password`는 호출 화면 없이 남긴다. P2에서 비밀번호 변경 화면을 제외한다.

### D2 = A. 학습자 renderer를 공유 패키지로 추출한다

미리보기는 실제 학습자 렌더러를 재사용한다. `apps/web/src/features/lesson-session/ui/`의 step renderer를 공유 패키지로 옮기고 학습자 앱과 어드민이 같은 구현을 쓴다. 패키지 경계 변경이므로 ADR을 함께 작성한다.

### D3 = A. 레슨 예상 시간을 표시로 확정한다

초안의 전제 두 개가 틀렸음을 확인한 뒤 2026-07-31에 A로 확정했다.

정정 1. 시드에 값이 있다. 321개 레슨 전부에 예상 시간이 있다(`12분` 183개, `8분` 135개, `16분` 3개). 초안의 "값이 비어 있다"는 서술은 시드 필드 이름을 `est`로 잘못 읽은 결과다.

정정 2. 학습자가 값을 보고 있다. 초안의 "학습자 화면이 표시하지 않는다"는 레슨 시작 화면(`SCR-006`)에만 해당한다. 코스 상세 커리큘럼의 레슨 행과 학습 홈의 다음 학습 레슨 CTA가 값을 노출한다.

확정 내용은 다음과 같다.

- 학습자 표시는 현재 동작을 유지한다. 코스 상세와 학습 홈은 표시하고, 레슨 시작 화면은 표시하지 않는다. 세 기준을 각 화면 문서에 명시한다.
- 어드민에 예상 시간 편집을 추가한다. 계약·schema·migration은 건드리지 않는다.
- 예상 시간을 시작 화면 정보로 서술한 `patterns.md`의 레슨 몰입 화면 항목을 `SCR-006`과 맞춘다.

따라서 D3은 제거가 아니라 편집 추가 작업이며, P1의 레슨 필드 편집 항목과 하나로 합친다.

### D4 = A. 감사 조회 요구사항과 화면을 신설한다

`REQ-ADM-7`·`US-ADM-7`·`SCR-108`을 신설한다. `REQ-ADM-5`는 보관된 운영 설정·콘텐츠 초기화 요구사항이 쓰던 번호이므로 재사용하지 않는다.

## 단계 계획

### P0. 결함 수정 (승인 불필요)

목표: 사용자 영향이 있고 요구사항을 바꾸지 않는 결함을 먼저 없앤다.

- 코스 카테고리 입력을 자유 텍스트에서 승인된 값 선택으로 바꾼다. 현재 `course-info-tab.tsx`가 `Input`이라 오타가 학습자 코스 목록의 카테고리 탭(`SCR-004`)을 오염시킨다.
- 어드민 세션 만료를 사용자에게 알린다. 지금은 `(admin)/layout.tsx`가 401·403에서 조용히 로그인으로 redirect해 코스 편집 중 미저장 draft가 사라진다. `SCR-104` 상태 목록에 세션 만료를 추가한다.
- 어드민 인증 클라이언트가 429를 학습자 클라이언트와 같은 방식으로 매핑하고, 관리자 로그인에 sign-in 경로 요청 제한을 적용한다. 계정 단위 잠금은 도입하지 않는다. owner가 단일 계정이고 D1 = C로 자기 잠금 해제 화면이 없어, 계정 잠금은 이메일만 아는 외부인이 유일한 운영자를 잠글 수 있는 경로가 된다.
- 코스 목록의 보관 버튼을 행 호버 전용에서 상시 노출 또는 행 메뉴로 바꾼다.
- 어드민 코스 목록 썸네일의 업로드 표지 반영은 2026-07-31 승인으로 P4로 이관했다. 계약·port 타입·repository 조회·asset URL 해석·mapper·OpenAPI 재생성·화면 7개 지점을 함께 바꿔야 하고, 필요한 asset 해석 배관이 P4의 asset 목록·삭제와 같다. owner는 코스 편집 화면에서 업로드한 표지를 이미 확인할 수 있다.

문서 변경: `SCR-103`, `SCR-104`. `SCR-103`은 같은 변경에서 다른 화면 문서 수준으로 낮추고 구현 세부 서술을 뺀다.

완료 판정: 카테고리 오타로 학습자 카테고리 탭이 늘지 않고, 편집 중 세션 만료 시 안내가 보이며, 로그인 실패 제한과 429 안내가 동작한다.

### P1. 명세 이행 (승인 불필요, 이미 요구된 범위)

목표: `req-adm-2`·`req-adm-3`이 이미 요구하는데 구현되지 않은 항목을 채운다.

- 레슨 편집에 카테고리·설명·예상 시간·요약을 추가한다(D3 = A 포함). 현재 `course-editor-reducer.ts`에는 `lesson-title-changed`만 있다.
- 레슨 순서 변경(`lesson-moved`)을 추가한다. 저장 시 `sortOrder`를 1부터 재계산하는 기존 규칙을 따르므로 계약 변경 없이 클라이언트 범위에서 가능하다.
- 분석 화면에 AI 서비스 품질 집계를 추가한다. `GET /api/admin/analytics/ai-feedback`이 이미 요청·성공·실패 code·latency·token·retry를 반환하고 호출자만 없다. 응답에 답안·prompt·피드백 원문이 없음을 테스트로 고정한다.

문서 변경: `SCR-104`(레슨 작업대를 조회에서 편집으로), `SCR-107`(AI 품질 집계를 정보 구조에 추가).

완료 판정: 어드민에서 레슨 요약과 설명을 저장·발행할 수 있고, 분석 화면에서 기간별 AI 실패 code와 token을 확인할 수 있다.

### P2. 학습자 미리보기 (D2 = A)

목표: 발행 전에 학습자가 볼 화면을 실제 렌더러로 확인할 수 있게 한다.

착수 시 D2의 전제가 틀렸음을 확인했다. 10개 스텝의 시각 렌더러는 이미 전부 `@workspace/ui/components/lesson/`에 있고 학습자 앱이 이를 소비한다. `apps/web`에 남은 것은 학습 세션 view model을 그 컴포넌트 props로 옮기는 adapter 3개뿐이라 추출할 렌더러가 없었다. 또한 `@workspace/ui`는 `@workspace/contracts`에 의존하지 않으며 이 경계는 유지할 값이 있다.

따라서 새 패키지를 만들지 않고 어드민이 같은 컴포넌트를 직접 소비하는 얇은 adapter를 소유한다. 판단 근거는 [ADR-0028](../../engineering/adr/ADR-0028-admin-learner-step-preview-reuse.md)에 남겼다.

- 어드민 `LearnerStepPreview`가 editor step DTO를 학습자와 같은 렌더러 props로 옮긴다.
- 미리보기는 스텝 편집 영역 안에서 접고 펼 수 있고 읽기 전용이다. 답안 handler·채점 상태·AI 호출·예상 시간을 넘기지 않는다.

문서 변경: `SCR-104`, `req-adm-3`, `ADR-0028`, 엔지니어링 인덱스.

완료 판정: 어드민 미리보기와 학습자 화면이 같은 렌더러를 사용하고 `check:architecture`가 통과한다. 10개 타입 전부 렌더링과 채점 상태 비노출을 테스트로 고정했다.

### P3. 운영 가시성 (D4 = A)

목표: 개인정보 취급과 고위험 변경을 추적할 수 있게 한다.

- 감사 이벤트 조회 화면(`SCR-108`)을 추가했다. 계약(`adminAuditEventsQuerySchema`)이 `limit`만 지원하므로 최근 50건 목록으로 만들었다. 기간·category·actor 필터와 페이지 이동은 계약 변경이 필요하므로 후속 과제로 분리했다.
- 작업·대상·결과를 한국어로 옮기고 요청 식별자만 노출한다. actor·target 식별자는 화면에 표시하지 않아 조사 목적에 필요한 최소 정보만 남긴다.
- 종결되지 않은 `started`는 성공과 다른 톤으로 구분해 조사 신호로 보이게 했다.
- 비밀번호 변경 화면은 만들지 않았다(D1 = C).

문서 변경: `REQ-ADM-7`·`US-ADM-7`·`SCR-108` 신설, 요구사항·유저 스토리·디자인 인덱스, `ia-spec.md`, `req-adm-6` 사이드바 메뉴, `admin-operations.md` 읽기 권한.

완료 판정: owner가 개인정보 조회·상태 변경·발행·보관 이력을 화면에서 확인할 수 있다. 한국어 변환·빈 상태·조회 실패·원문 비노출을 테스트로 고정했다.

### P4. 콘텐츠 제작 도구 (승인 후)

목표: 어드민만으로 코스를 만들고 고칠 수 있게 한다. [제품 경험 검토](../../work/2026-07-31-product-experience-review/report.md)가 제안한 "한 코스 12레슨 재작성"의 선행 조건이다.

- 레슨·스텝 복제와 유닛 간 레슨 이동을 추가했다. 레슨 사본은 스텝 ID를 새로 발급하므로 AI 코칭 target을 사본 안의 대응 스텝으로 다시 매핑한다. 재매핑하지 않으면 사본의 AI 스텝이 원본 레슨 스텝을 가리켜 저장 검증에서 거절된다.
- 코스 보관 되돌리기를 추가했다. 도메인 판정, use case, 계약, `POST /courses/{courseId}/restore` route와 어드민 행동을 함께 만들고 `course.restore` 감사 action을 표준 보존 class로 등록했다.
- 강의명 검색을 추가했다. 부분 일치로 좁히고 검색어의 `LIKE` 와일드카드는 문자로 escape해 조건이 넓어지지 않게 했다. 검색어는 필터·페이지 상태와 함께 URL query에 보존한다.
- 어드민 코스 목록 썸네일이 업로드한 코스 표지를 반영하게 했다(P0에서 이관). 목록 DTO에 `cover`를 추가하고 repository가 `coverAssetId`를 반환하며 application이 기존 asset 해석 경로로 URL을 채운다. 표지가 없으면 `visualKey` 기본 이미지로 내려앉는다.
- 발행 이력은 P3의 감사 화면이 `course.publish`와 `course.restore`를 포함하므로 별도 화면을 만들지 않았다.
- asset 목록·삭제 화면은 범위에서 제외했다. 감사 단계의 "잘못 올린 이미지를 지울 수 없다"는 서술이 과했다. 코스 편집의 asset 필드가 이미 이미지 교체와 연결 해제를 제공하고, 참조가 끊긴 asset은 일일 정리 작업이 유예 기간 뒤 삭제한다. 남는 것은 owner가 asset 현황과 정리 대기 수를 볼 수 없다는 가시성 문제이며, 검색·썸네일보다 가치가 낮아 후속 과제로 남긴다.

완료 판정: 시드 JSON을 수정하지 않고 어드민만으로 유닛·레슨·스텝을 재배치하고 발행할 수 있다.

### P5. 축소와 정리

목표: 판단에 쓰이지 않는 표면을 줄인다.

- 어드민 테마 토글과 전용 테스트를 제거했다. `req-adm-*`과 `SCR-10*`에 근거가 없었다. `ThemeProvider`는 남겨 운영체제 설정을 따르게 했다. 제거하면 다크 OS 사용자의 가독성이 나빠지는 변경이 되기 때문이다.
- 대시보드 카드를 6장에서 3장으로 줄였다. 활성화율 카드가 분자·분모로 총 사용자와 첫 레슨 시작을 이미 보여주고, 누적 완료 레슨은 `metrics.md`의 운영 판단 기준에 단독 용도가 없다.
- 이탈률 상위 레슨 표를 제거하고 레슨별 성과 표의 기본 정렬을 이탈률 내림차순으로 바꿨다. 두 표가 같은 값을 보여주고 있었다.
- 사용자 목록 페이지 크기 정책을 코스 목록과 맞췄다. 조사 결과 문서의 "페이지당 12명 고정"이 실제와 달랐다. 구현은 기본 20명이고 `pageSize` query를 받으면서 선택 control과 페이지 이동이 없었다. 선택 control과 이전·다음 이동을 추가하고 문서를 실제에 맞췄다.
- 사용자 목록 row action의 hover 전용 표시를 제거했다. P0에서 코스 목록에 적용한 것과 같은 결함이 남아 있었다.

문서 변경: `req-adm-2`, `req-adm-4`, `us-adm-4`, `admin-operations.md`, `SCR-102`, `SCR-105`, `SCR-107`.

남은 항목: 사용자 상세의 상태 변경·삭제 액션은 넣지 않았다. 목록과 상세가 같은 확인 흐름을 쓰려면 공통 컴포넌트 추출이 필요하고, 이는 표면을 줄이는 P5의 목표와 반대 방향인 추가 작업이다. 별도 작업 단위로 분리한다.

- AI 피드백 원문 조회. 품질 집계는 원문 없이 유지한다.
- 관리자 역할 추가(editor·reviewer). `admin-operations.md`가 owner 단일 역할로 정하고 있어 별도 제품 결정이 필요하다. 검수 워크플로가 필요해지면 제품 검토에서 먼저 다룬다.
- 운영 설정 화면(공지·배너·약관). 보관된 `REQ-ADM-5`가 다뤘고 현재 비범위다. 약관·처리방침 노출은 어드민 기능이 아니라 출시 법적 요건으로 [제품 경험 검토](../../work/2026-07-31-product-experience-review/report.md)에서 다룬다.
- 실시간 알림과 외부 BI 연동. `req-adm-2` 비범위를 유지한다.

### P1 구현 요약

- 레슨 편집: `lesson-title-changed` action을 `LessonFieldChange` 판별 union을 받는 `lesson-changed`로 일반화해 제목·카테고리·예상 시간·설명·요약을 같은 경로로 처리한다. 요약은 한 줄에 한 항목으로 입력받아 빈 줄을 버리고, 카테고리·설명은 공백만 남으면 저장하지 않는 값으로 바꾼다. 입력 해석은 `model/lesson-field-input.ts`가 소유해 렌더링과 분리했다.
- 레슨 순서: `lesson-moved` action을 추가하고 `step-moved`와 중복이던 이동 로직을 `moveByDirection` 하나로 합쳤다. 경계를 벗어나는 이동은 같은 배열 참조를 돌려주어 dirty 전이를 만들지 않는다.
- AI 품질: 분석 route가 추이 차트와 같은 30일 창으로 `getAdminAiFeedbackQuality`를 함께 조회하고, 요청·성공·성공률·실패·평균 지연·재시도·token과 실패 code별 건수를 region으로 표시한다. 조회 실패는 다른 영역을 유지한 채 해당 영역에만 오류를 보여준다.
