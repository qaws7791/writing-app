# apps/api 테스트 감사

## 요약

- 검토 파일 수: 37/37 (`apps/api/vitest.config.ts`의 `include: ["src/**/*.test.ts"]` 대상 전체)
- 삭제 권고 13건 · 수정 권고 48건 · 문제 없음 5건 (중복 커버리지 8건 · 누락 회귀 7건 별도)
- `await new Promise(r => setTimeout(...))`, `vi.useFakeTimers`, `vi.advanceTimers`, 고정 지연은 이 범위에 **한 건도 없다**. C-3 신호는 전수 grep으로 0건을 확인했고, `lifecycle/server-lifecycle.test.ts`는 주입한 fake scheduler로 시간을 격리한다.

가장 시급한 3가지

1. **`observability/admin-audit.integration.test.ts:157-159`의 PII 컬럼 금지 단정이 사실상 비활성 상태다.** `expect(columns).not.toEqual(expect.arrayContaining(["payload","email","name","answer","prompt"]))`는 5개가 _모두_ 존재할 때만 실패한다. `audit_events`에 `payload` 컬럼 하나가 추가되어도 통과한다. 보안 회귀를 막는다고 선언한 단정이 막지 못한다(C-5).
2. **동일한 negated `arrayContaining` 오용이 schema 계약에도 3곳 복제되어 있다.** `db/migrate.test.ts:89-97`, `db/schema-diagnostic.test.ts:42-52`. 게다가 `db/migrate.test.ts:88`이 이미 정확 일치를 단정하므로 뒤따르는 negated 단정은 도달 불가한 죽은 단정이다(C-13).
3. **`adapters/auth/auth-sqlite-database.test.ts` 전체가 mock 전달 자체를 회귀 계약으로 삼는다.** `createSqliteAuthDatabaseAdapter`를 mock으로 대체하고 wrapper가 넘긴 schema map을 단정한다. `docs/engineering/testing.md`가 명시적으로 금지한 패턴이다(D-6, D-8, C-10).
