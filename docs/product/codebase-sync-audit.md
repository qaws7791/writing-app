# 코드베이스 동기화 점검

## 목적

이 문서는 유저 스토리와 요구사항 문서를 현재 코드베이스와 맞추기 위해 역추적한 결과를 기록한다. 제품 문서의 세부 규칙이 코드와 어긋나거나 누락될 때, 어떤 요구사항에 반영해야 하는지 찾는 기준으로 사용한다.

## 점검 기준

- 기준일: 2026-06-20
- 제외 범위: 레거시 실험 디렉터리
- 포함 범위: `apps`, `packages`, `docs`의 정식 문서
- 점검 단위: API 라우트, core 서비스, 도메인 정책, 저장소 구현, web/admin 기능 화면
- 문서 반영 방식: 새 기능을 중복 문서로 만들지 않고 기존 유저 스토리와 요구사항에 하위 규칙을 보강한다.

## 이번 구현 시작 기준

- 시작일: 2026-06-20
- 구현 목표: `docs` 디렉토리를 단일 원천으로 삼아 학습자 플랫폼 서비스와 어드민 서비스를 모두 실행 가능한 상태로 맞춘다.
- 검증 기준: 문서 계약 검사, 타입 검사, 테스트, 빌드, 로컬 실행 확인을 순서대로 수행하고 실패 지점은 문서 기준과 코드 구현 중 어느 쪽을 갱신해야 하는지 명시한다.
- 변경 원칙: 레거시 실험 디렉터리는 제외하고, 화면과 API 계약은 `docs/design`, `docs/product`, `docs/engineering`의 최신 규칙을 우선한다.

## 이번 구현 완료 기준

- 완료일: 2026-06-20
- 반영 내용: 기존 로컬 SQLite DB가 `courses.visual_key`만 누락한 경우 데이터를 보존한 채 baseline migration이 컬럼을 추가하도록 보강했다.
- 반영 내용: 콘텐츠 seed 재실행 시 코스 `visual_key`를 기준 콘텐츠 seed 값으로 갱신하도록 했다.
- 반영 내용: `bun run dev:admin:setup`은 로컬 어드민 seed 계정으로 즉시 로그인할 수 있도록 관리자 credential 비밀번호를 재설정한다.
- 실행 확인: `bun run dev:app:setup`, `bun run dev:admin:setup`, 플랫폼 health, 어드민 health, 어드민 email/password 로그인, 어드민 dashboard API 응답을 확인했다.
- 최종 검증: `bun run lint`, `bun run typecheck`, `bun run test`, `bun run build`가 통과했다.
- 남은 조건: 학습자 실제 로그인은 Google OAuth provider 설정이 필요하므로 로컬 smoke에서는 공개 랜딩, 로그인 화면, 보호 API의 401, 보호 페이지의 로그인 리다이렉트까지 확인했다.

## 브라우저 검증 시작 기준

- 시작일: 2026-06-20
- 검증 목표: 로컬 브라우저에서 학습자 플랫폼과 어드민 서비스를 직접 열고 주요 화면, 인증 상태, 목록 필터, 저장 동작을 확인한다.
- 검증 범위: 학습자 홈, 코스 목록, 코스 상세, 레슨 시작과 완료, 프로필, 어드민 로그인, 대시보드, 코스 목록과 상세, 사용자 목록과 상세, 분석, 설정 저장.
- 발견 기준: 화면에서 조작 가능한 control이 문서의 검색/필터 계약을 실행하지 못하면 UI 구현 결함으로 보고 즉시 수정한다.

## 브라우저 검증 완료 기준

- 완료일: 2026-06-20
- 플랫폼 확인: 로컬 브라우저에서 학습자 홈, 코스 목록, 코스 상세, 레슨 시작, 스텝 진행, 레슨 완료, 프로필 화면을 확인했다.
- 어드민 확인: 로컬 브라우저에서 어드민 로그인, 대시보드, 코스 목록과 상세, 사용자 목록과 상세, 분석, 설정 저장을 확인했다.
- 수정 내용: 코스 목록과 사용자 목록의 필터 toolbar를 `GET` form으로 명시하고 필터 적용 버튼을 추가해 query string 기반 재조회가 실제 조작으로 실행되도록 했다.
- 회귀 확인: 코스 검색어 `문법`은 코스 1개로 필터링되고, 사용자 검색어 `없는사용자`는 0명, `learner@example.com`은 1명으로 필터링됨을 브라우저에서 확인했다.
- 최종 검증: 브라우저 검증 후 개발 서버를 종료하고 `bun run lint`, `bun run format:check`, `bun run typecheck`, `bun run test`, `bun run build` 통과를 확인했다.

## 보강한 누락 항목

- AI 코칭의 최대 완료 시도 수 3회와 제공자 실패 시도 미저장 규칙.
- 매칭 활동의 결정적 오른쪽 선택지 섞기와 1:1 선택 전환 규칙.
- 레슨 완료 재호출 시 완료 수를 중복 증가시키지 않는 활동일 집계 규칙.
- 어드민 대시보드와 분석에서 deleted 학습자를 제외하는 집계 규칙.
- 어드민 사용자 목록의 기본 정렬, 상태 필터 해석, 페이지당 12명 고정 기준.
- 새 코스 생성 시 빈 커리큘럼 코스 생성 규칙과 콘텐츠 초기화 시 seed 외 콘텐츠 보관 규칙.

## 남은 비문서화 대상

현재 점검 기준에서 제품 요구사항으로 승격해야 할 미문서화 비즈니스 로직은 없다. `packages/env`, `packages/http-client`, `packages/ui`, `packages/config`, Storybook과 `apps/api`의 platform·observability 경계는 제품 요구사항이 아니라 런타임, 인프라, UI 기반 구성으로 분류한다.
