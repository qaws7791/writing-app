# REQ-LRN-11 목적 과제 글쓰기

## 문서 정보

- 영역: 플랫폼
- 출처 유저 스토리:
  - `US-LRN-12` 목적 과제 글쓰기
- 관련 화면:
  - `SCR-008` 쓰기 홈
  - `SCR-011` 쓰기 카탈로그
  - `SCR-009` 작성 세션
- 관련 사용자:
  - 학습자
- 상태: 기준

## 목적

학습자가 발행된 쓰기 과제를 고르고 일반 텍스트 본문을 작성한 뒤, 과제 조건으로 AI 점검을 받고 수정할 수 있게 한다.

## 기능 요구사항

- 학습자 앱은 `배우기`와 나란한 `쓰기` 진입점을 제공한다.
- 쓰기 홈은 카탈로그로 가는 경로와 학습자가 저장한 글의 단일 목록을 제공한다.
- 이어쓰기는 홈의 글 목록에서만 한다. 카탈로그 `시작하기`는 항상 새 글을 만든다.
- 같은 과제의 초고를 여러 편 둘 수 있다.
- 새 글은 해당 과제의 시작 시점 최신 발행본에 고정된다. 이후 과제 초안 발행은 이미 시작한 글을 바꾸지 않는다.
- 작성 세션은 과제 브리프, 일반 텍스트 본문, 글자 수, 저장 상태, `점검하기`와 최근 점검 결과를 같은 화면에 제공한다.
- 작성 세션 본문은 문단 간격을 제공한다. 저장 형식은 일반 텍스트를 유지한다.
- 고칠 일의 1차 표면은 본문 인용 구절의 형광펜이다. 학습자는 그 자리에서 본문을 고친다. 형광펜을 누르면 이유와 부분 수정 예문이 비모달 팝오버로 열린다. `제거`는 화면 세션에서만 그 표시를 걷는다.
- 브리프와 점검 개요는 한 번에 하나만 연다. 점검 개요 패널은 잘된 점, 과제 미충족, 남은 고칠 일을 한 번에 훑을 때 연다. 열린 패널은 본문 옆 또는 아래에 붙고, 열린 동안 본문을 입력할 수 있다.
- 점검 성공 직후 개요 패널을 자동으로 열지 않는다. 본문에 남은 고칠 일 형광펜을 바로 표시한다.
- 입력이 800ms 동안 멈추면 저장을 요청한다.
- 입력 영역이 focus를 잃거나 화면이 숨겨지거나 나가기 행동이 실행되면 대기 중인 저장을 즉시 요청한다.
- 저장 실패와 version 충돌에는 작성 중인 본문을 화면 상태에 유지한다.
- `점검하기`는 고정 발행본의 최소 글자 수 이상이고, 학습자의 `Asia/Seoul` 달력일 성공 점검이 5회 미만일 때만 요청한다. 한도 값은 환경 설정이 소유한다.
- 첫 `점검하기` 직전에 본문을 외부 AI로 전달한다는 고지를 보여 주고, 학습자가 확인한 뒤에만 점검을 시작한다. 고지 확인은 학습자당 1회 저장한다.
- 점검 실패는 하루 성공 횟수에 넣지 않는다.
- `점검하기`는 현재 본문으로 새 결과를 만든다. 새 성공 점검이 이전 결과를 바꾼다.
- 최근 성공 점검 1건은 본문이 바뀌어도 조회한다.
- 글 삭제는 확인 절차를 거치고 학습자가 소유한 글만 삭제한다.

## 화면 요구사항

- 쓰기 홈과 카탈로그는 학습자 `AppShell` 안에서 렌더링한다.
- 작성 세션은 글로벌 내비게이션을 숨긴 몰입 화면에서 렌더링한다.
- 본문에는 보이는 한국어 label을 제공한다.
- 저장 중과 저장 완료, 점검 성공으로 본문에 고칠 일을 표시한 사실은 `role="status"`로 전달한다.
- 저장 실패, version 충돌, 점검 실패는 `role="alert"`로 전달한다.
- 카탈로그는 상단 도메인 칩, 그 아래 유형 칩, 과제 카드, 미리보기 오버레이를 제공한다. 빈 도메인과 유형은 숨긴다.
- 카탈로그 카드는 목표 글자 수를 보여 주고, 최소 글자 수는 브리프와 점검 한도에 사용한다.
- 320px 화면과 텍스트 200% 확대에서 가로 스크롤 없이 작성과 점검을 완료할 수 있어야 한다.

## 데이터 요구사항

- 글은 학습자, 고정 발행본, 일반 텍스트 본문, version과 생성·수정 시각을 가진다. 학습자에게 작성 중·완료 상태를 두지 않는다.
- 본문은 일반 텍스트로 저장한다. 학습자 제목과 쓰기 방식은 두지 않는다.
- 저장은 expected version을 현재 version과 비교한다. version이 다르면 서버 글을 변경하지 않는다.
- 최근 성공 점검은 글에 1건만 둔다. 본문 version과 달라도 조회한다.
- 점검 결과는 잘된 점 1–2개, 과제 미충족(있으면), 고칠 일 최대 3개다. 각 고칠 일은 위치, 본문 인용(`quote`), 이유, 부분 수정 예문을 가진다. `quote`는 본문에 있는 연속 구절이다. `quote`가 본문에 없으면 그 항목은 개요 패널에만 나온다.
- event는 글 생성, 점검 성공, 점검 뒤 본문 수정, 글 삭제만 기록한다.
- event, 일반 log, 오류 payload와 운영 조회에는 본문, prompt, 점검 원문을 포함하지 않는다.
- 점검 성공률은 글 생성 event가 있는 글 중 점검 성공 event가 있는 글의 비율이다.
- 점검 뒤 수정률은 점검 성공 event가 있는 글 중 이후 본문 수정 event가 있는 글의 비율이다.

## 권한 / 접근 규칙

- 모든 쓰기 조회와 변경은 로그인한 active 학습자만 수행할 수 있다.
- 학습자는 자신의 글만 조회, 저장, 점검, 삭제할 수 있다.
- 학습자는 발행된 과제만 카탈로그에서 본다.
- 학습자 데이터 정리는 해당 학습자의 글, 점검, 고지 확인, 쓰기 event를 같은 정리 transaction에서 삭제한다. 과제와 발행본은 삭제하지 않는다.

## 예외 / 오류

- 조회 실패는 빈 목록으로 바꾸지 않고 다시 시도 가능한 한국어 오류로 표시한다.
- 저장 실패는 작성 내용이 화면에 남아 있음을 먼저 알린다.
- version 충돌은 로컬 작성 내용을 유지하고 서버 글 불러오기 또는 로컬 내용 재시도를 제공한다.
- 네트워크가 끊기면 현재 화면 입력을 유지하고 재연결 뒤 저장을 다시 시도한다.
- 저장하지 않은 입력이 남아 있으면 browser 화면 이탈 전에 경고한다.
- 최소 글자 미달, 하루 한도 초과, 고지 미확인, 발행본 없음은 점검을 시작하지 않고 한국어 거절로 알린다.
- 외부 AI 실패는 본문을 유지하고 다시 시도할 수 있게 한다.

## 비범위

- 레슨 `WRITE` 답안과의 연결.
- 리치 텍스트, 마크다운, 첨부와 인쇄 레이아웃.
- 폴더, 태그, 검색과 정렬 설정.
- 공유, 공개 발행과 실시간 협업.
- 타이머, 포커스 모드, 패널 폭 드래그.
- 오프라인 영속 저장.
- 점검 결과를 모델 학습 데이터셋으로 전환.

## 확인 방법

- 카탈로그에서 과제를 시작한 뒤 작성 세션이 열리는지 확인한다.
- 입력 정지, blur, 화면 숨김과 나가기에서 저장 요청이 실행되는지 확인한다.
- 저장 실패와 version 충돌에서 로컬 본문이 유지되는지 확인한다.
- 첫 점검 전 고지, 최소 글자, 하루 한도, 새 점검이 최근 1건을 바꾸는 것, 본문 변경 뒤에도 최근 점검을 다시 보는 것을 확인한다.
- 점검 성공 뒤 본문 인용 구절에 형광펜이 생기는지, 개요 패널이 자동으로 열리지 않는지, `제거`가 화면 세션에서만 형광펜을 걷는지 확인한다.
- 삭제 확인과 학습자 데이터 정리에서 글 원문과 점검이 제거되는지 확인한다.
- 운영 조회에 본문과 점검 원문이 포함되지 않는지 확인한다.
