# REQ-ADM-7 자료실 공동 편집

## 문서 정보

- 영역: 어드민
- 출처 유저 스토리:
  - `US-ADM-7` 자료실 공동 편집
- 관련 화면:
  - `SCR-110` 관리자 자료실
- 관련 사용자:
  - 운영자
- 상태: 기준

## 목적

운영자가 폴더 트리에서 자료를 찾고 정리하며, GFM 문서를 최종 결과와 같은 화면에서 여러 관리자와 실시간으로 편집할 수 있게 한다.

## 기능 요구사항

### 폴더와 문서 트리

- 자료실은 폴더와 문서를 구분한다.
- 폴더는 폴더와 문서를 포함할 수 있고 문서는 항상 말단 노드다.
- 루트에는 폴더와 문서를 모두 둘 수 있으며 폴더 중첩 깊이를 제한하지 않는다.
- 폴더는 이름과 계층만 가진 구조적 컨테이너이며 Markdown 본문을 갖지 않는다.
- 폴더와 문서는 드래그 앤 드롭으로 같은 부모 안에서 정렬하거나 다른 폴더로 이동할 수 있다.
- 항목 메뉴는 키보드와 모바일 사용자를 위한 별도 이동 기능을 제공한다.
- 폴더를 자기 자신이나 하위 폴더로 이동할 수 없다.
- 같은 부모 아래에서는 폴더와 문서를 합쳐 정규화된 이름이 고유해야 한다. 이름 비교는 대소문자와 앞뒤 공백을 무시한다.
- 새 문서는 즉시 `제목 없음` 이름과 빈 본문으로 영속 생성하고 편집 화면을 연다.
- 생성 또는 복원 과정의 이름 충돌은 숫자 접미사로 해결한다.
- 새 폴더는 `새 폴더` 이름으로 생성하고 충돌하면 숫자 접미사를 붙인다.
- 수동 이름 변경의 충돌은 거부하고 마지막 정상 이름과 인라인 오류를 표시한다.
- 이름을 비운 채 확정하면 편집 전 이름으로 되돌린다.

### 휴지통

- `보관`과 `삭제`를 별도 개념으로 두지 않고 `휴지통으로 이동`으로 통합한다.
- 폴더를 휴지통으로 이동하면 모든 하위 폴더와 문서를 함께 이동한다.
- 폴더를 복원하면 모든 하위 폴더와 문서를 원래 위치와 순서로 함께 복원한다.
- 휴지통은 직접 이동된 최상위 항목만 목록에 표시하고 폴더를 펼치면 하위 트리를 보여준다.
- 복원 시 원래 위치에 같은 이름이 있으면 복원되는 최상위 항목에 숫자 접미사를 붙인다.
- 휴지통 이동은 대상 종류와 관계없이 항상 확인 대화상자를 거친다.
- 편집 중인 문서나 상위 폴더를 이동할 때는 현재 편집자 수를 추가로 알리고 확인 후 진행한다.
- 휴지통 문서는 읽기 전용으로 열고 복원 후에만 편집할 수 있다.
- 휴지통 항목은 자동 만료하지 않는다.
- 영구 삭제는 제공하지 않는다.

### 문서 편집

- 문서 제목과 본문은 분리한다. 제목은 별도 속성이고 Markdown에는 본문만 저장한다.
- Lexical 편집 영역 자체가 최종 문서처럼 보이는 WYSIWYG 화면이어야 하며 원문과 미리보기를 나눈 분할 화면을 제공하지 않는다.
- 저장 Markdown은 GFM 범위로 제한한다.
- 지원 블록은 기본 텍스트, 제목 1~3, 글머리 목록, 번호 목록, 할 일 목록, 인용, 코드 블록, 구분선, 표, 이미지 URL이다.
- 슬래시 커맨드는 모든 지원 블록을 삽입할 수 있다.
- 블록 시작의 Markdown 입력 단축 문법을 지원한다.
- 블록 왼쪽의 드래그 핸들로 순서를 바꾸고 `+` 행동으로 블록 메뉴를 열 수 있다.
- 키보드 사용자는 메뉴나 단축키로 블록을 위·아래로 이동할 수 있다.
- 텍스트 선택 시 플로팅 툴바에 굵게, 기울임, 취소선, 인라인 코드, 링크를 표시한다.
- 이미지는 HTTPS URL과 대체 텍스트 입력만 지원하고 파일 업로드를 제공하지 않는다.
- 모든 HTTPS 이미지 호스트를 허용하되 외부 요청에 referrer를 보내지 않는다.
- 원시 HTML은 실행하거나 HTML로 렌더링하지 않는다. 블록 HTML은 `html` fenced code, 문장 내부 HTML은 inline code인 리터럴 코드로 표시하고 여러 줄 원문을 보존한다.
- 제목과 본문은 기존 최대 길이 기준인 제목 120자, 본문 200,000자를 유지한다.

### 실시간 공동 편집

- 본문은 Yjs CRDT로 실시간 병합한다.
- 제목은 CRDT에 포함하지 않고 서버가 직렬화한 이름 변경 명령으로 확정한 뒤 모든 접속자에게 브로드캐스트한다.
- 폴더와 문서의 생성, 이름 변경, 이동, 정렬, 휴지통 이동, 복원은 서버 트랜잭션으로 처리하고 결과 이벤트를 브로드캐스트한다.
- 저장 버튼을 제공하지 않는다.
- 문서 상단은 아이콘 애니메이션과 텍스트로 `동기화 중`, `동기화됨`, `오프라인`, `동기화 오류`를 표시한다.
- 여러 사용자의 편집 위치, 선택 영역, 이름, 접속자 목록은 표시하지 않는다.
- 실행 취소와 다시 실행은 현재 사용자가 해당 탭에서 수행한 본문 변경에만 적용한다.
- 일시적인 연결 끊김 동안 현재 탭의 본문 편집을 허용하고 재연결 후 병합한다.
- 오프라인 상태에서는 트리 변경을 허용하지 않는다.
- 브라우저를 닫았다 다시 여는 완전한 오프라인 복구는 제공하지 않는다.

### 탐색과 검색

- 문서 상세 URL은 `/resources/[documentId]`다.
- `/resources`는 문서 선택 안내와 새 문서 생성 행동을 표시한다.
- `/resources/trash`는 휴지통을 표시한다.
- 최근 열어본 문서 목록은 제공하지 않는다.
- 펼친 폴더 ID는 관리자별 브라우저 localStorage에 저장하고 기기 간 동기화하지 않는다.
- 전역 검색은 활성 폴더 이름, 문서 제목, Markdown 본문을 대상으로 한다.
- 휴지통 검색은 활성 자료 검색과 분리한다.
- 검색 결과는 폴더와 문서를 구분하고 전체 경로를 표시한다.
- 문서 검색 결과는 일치한 본문의 문맥을 함께 표시한다.
- 검색 결과를 선택하면 해당 조상 폴더를 자동으로 펼치고 트리 위치를 선택한다.
- 폴더 검색 결과는 편집 중인 문서를 바꾸지 않고 트리의 해당 폴더만 펼치고 선택한다.
- 문서 상단은 전체 폴더 경로 breadcrumb를 표시한다.
- 경로가 길면 가운데 항목을 축약하고 hover 또는 click 팝오버로 숨은 경로를 공개한다.
- 제목 아래에 마지막 수정자와 상대 시간을 표시하고 팝오버에서 생성자, 생성 시각, 정확한 최종 수정 시각을 보여준다.

### 가져오기와 내보내기

- 단일 `.md` 파일 가져오기를 지원한다.
- 첫 번째 H1이 있으면 문서 제목으로 사용하고 본문에서 제거한다.
- 첫 번째 H1이 없으면 파일명을 문서 제목으로 사용한다.
- 여러 파일, 폴더, ZIP 가져오기는 지원하지 않는다.
- 문서별 Markdown 다운로드를 지원한다.
- 다운로드 내용은 `# 제목`과 본문 Markdown을 결합한다.
- 다운로드 전 서버가 최신 공동 편집 상태를 Markdown에 반영한다.

## 화면 요구사항

- 데스크톱은 너비를 조절하고 접을 수 있는 왼쪽 자료 트리와 오른쪽 편집 영역을 표시한다.
- 태블릿과 모바일은 트리를 오버레이 드로어로 표시하고 문서를 선택하면 드로어를 닫는다.
- 트리는 reui Tree의 시각 구조와 키보드 탐색 기준을 따른다.
- 편집기는 Lexical의 공식 Notion 예제에서 블록 핸들, `+` 행동, 슬래시 메뉴 구조를 참고한다.
- 동기화 오류는 재시도와 현재 Markdown 복사 행동을 제공한다.
- 문서가 선택되지 않은 상태, 빈 트리, 검색 결과 없음, 휴지통 비어 있음, 로딩 실패, 연결 끊김을 구분한다.

## 데이터 요구사항

- 문서 본문의 도메인 원본은 데이터베이스의 Markdown 텍스트다.
- Yjs 상태는 동시 변경 병합과 서버 재시작 복구를 위한 별도 동기화 메타데이터로 저장한다.
- Yjs 상태가 없으면 Markdown에서 공동 편집 문서를 다시 생성할 수 있어야 한다.
- 제목, 폴더 이름, 계층, 정렬 순서, 상태, 생성자, 마지막 수정자, 생성·수정 시각을 저장한다.
- 검색은 Markdown에서 추출한 일반 텍스트와 이름을 색인한다.
- 생성, 이름 변경, 이동, 정렬, 휴지통 이동, 복원 이벤트의 행위자와 시각을 감사 기록으로 저장한다.
- 감사 기록 조회 UI와 본문 버전 기록은 제공하지 않는다.
- 폴더와 문서를 합쳐 최대 10,000개를 기준으로 트리를 지연 로딩한다.
- 문서당 동시 편집자 20명을 지원 목표로 한다.
- 기존 Tiptap JSON 자료는 마이그레이션하지 않고 새 구조 전환 시 삭제한다.

## 권한 / 접근 규칙

- 관리자 세션이 있는 모든 운영자는 자료실을 조회하고 공동 관리할 수 있다.
- 모든 운영자는 폴더와 문서를 생성, 편집, 이동, 정렬, 휴지통 이동, 복원할 수 있다.
- WebSocket 연결도 일반 API와 같은 관리자 세션과 허용 origin을 검증한다.
- 휴지통 문서와 비활성 문서 공동 편집 연결은 거부한다.

## 예외 / 오류

- 자기 자신이나 하위 폴더로 이동하는 명령은 거부한다.
- 이름 충돌과 빈 이름은 사용자가 입력한 필드 가까이에 한국어 오류를 표시한다.
- 놓친 트리 이벤트가 있으면 영향받은 부모의 자식 목록을 다시 조회한다.
- 공동 편집 연결이 끊기면 본문을 로컬에 유지하고 오프라인 상태를 표시한다.
- 공동 편집 상태를 Markdown으로 투영하지 못하면 마지막 정상 Markdown을 덮어쓰지 않고 동기화 오류를 표시한다.
- 허용하지 않는 이미지 프로토콜과 링크 프로토콜은 삽입 단계와 서버 검증 단계에서 거부한다.
- 원격 공동 편집 update는 headless 문서에서 node 계층·속성·NodeState를 검증한 뒤에만 화면 편집기에 반영한다. 검증 실패 상태는 화면과 격리하고 사용자에게 동기화 오류로 표시하며, 정상 상태로 회복되면 검증된 전체 상태를 반영한다.
- 링크는 HTTPS, `mailto:`, 앱 내부 상대 경로만 허용하고 새 창 외부 링크에는 `noopener noreferrer`를 적용한다.
- 가져오기 검증이 실패하면 문서를 부분 생성하지 않는다.

## 비범위

- 실시간 공동 커서, 선택 영역, 접속자 목록.
- 사용자용 본문 버전 기록과 시점 복원.
- 감사 기록 조회 화면.
- 이미지와 일반 첨부 파일 업로드.
- 원시 HTML과 GFM 밖의 콜아웃, 토글, 다단 컬럼.
- 폴더 자체의 Markdown 본문.
- 영구 삭제와 휴지통 자동 만료.
- 다중 파일과 폴더 구조 가져오기.
- 브라우저 재시작을 견디는 완전한 오프라인 편집.
- 관리형 공동 편집 서비스.
- 기존 Tiptap JSON 호환과 데이터 이전.

## 확인 방법

- 무제한 중첩 트리에서 생성, 이름 변경, 이동, 정렬과 순환 이동 거부를 확인한다.
- 폴더 전체 휴지통 이동·복원과 이름 충돌 시 접미사 적용을 확인한다.
- 모든 지원 블록의 Markdown → Lexical → Markdown 왕복 결과를 확인한다.
- 두 개 이상의 브라우저 컨텍스트에서 동시 입력, 재연결, 로컬 undo 수렴을 확인한다.
- 서버 재시작 뒤 Yjs 상태와 Markdown이 같은 문서를 복구하는지 확인한다.
- 제목과 트리 명령이 모든 접속자에게 순서대로 반영되는지 확인한다.
- 제목·본문·폴더 검색, 경로 이동, 지연 로딩이 10,000개 fixture에서 동작하는지 확인한다.
- 모바일 트리 드로어, breadcrumb 팝오버, 키보드 트리 탐색과 블록 이동을 확인한다.
- 단일 Markdown 가져오기와 최신 상태 다운로드를 확인한다.
- 로컬 브라우저와 E2E에서는 `ENABLE_TEST_AUTH=true` 로그인을 사용한다.
