# REQ-ADM-7 관리자 자료실

## 문서 정보

- 영역: 어드민
- 출처 유저 스토리: `US-ADM-7 관리자 자료실 운영`
- 관련 화면: `SCR-110 관리자 자료실`
- 관련 사용자: 운영자
- 상태: 기준

## 목적

운영자가 코스 제작에 활용할 글쓰기 방법, 문법, 어휘, 예문과 교육 참고자료를 GFM 문서로 관리하고, 관리자 AI가 활성 학습 자료를 검색·조회해 코스와 자료실 변경안을 작성할 수 있게 한다.

## 기능 요구사항

### 폴더와 문서

- 자료실은 폴더와 문서를 구분하고 문서는 항상 말단 노드다.
- 폴더 중첩은 최대 3단계다.
- 폴더와 문서를 합쳐 최대 1,000개를 지원하고 전체 트리를 한 번에 조회한다.
- 같은 부모 아래에서 폴더와 문서 이름은 대소문자와 앞뒤 공백을 무시해 고유해야 한다.
- 형제 항목은 이름순으로 표시하고 수동 정렬 순서를 저장하지 않는다.
- 드래그 앤 드롭과 항목 메뉴는 항목을 다른 폴더로 이동하는 같은 명령을 사용한다.
- 생성·이동은 최대 깊이, 대상 폴더 상태, 이름 고유성과 순환 여부를 서버 transaction에서 검증한다.
- 문서 제목은 편집 화면에서만 변경하고 폴더 이름은 트리에서 변경한다.

### 휴지통

- 폴더를 휴지통으로 이동하면 모든 하위 폴더와 문서를 함께 이동한다.
- 휴지통은 직접 이동된 최상위 항목만 표시하고 폴더를 펼치면 하위 구조를 보여준다.
- 복원은 전체 하위 구조를 함께 복원한다.
- 원래 위치에 같은 이름이 있으면 복원되는 최상위 항목 이름에 숫자 접미사를 붙인다.
- 휴지통의 최상위 항목은 확인 후 하위 구조와 문서 종속 이미지를 포함해 영구 삭제할 수 있다.
- 자동 만료와 초기 범위의 일괄 휴지통 비우기는 제공하지 않는다.
- 휴지통 문서는 읽기 전용이며 관리자 검색과 AI 검색에서 제외한다.

### 문서 편집과 저장

- 제목과 본문을 분리해 표시하되 한 번의 명시적 저장으로 같은 transaction에서 갱신한다.
- Markdown을 본문의 유일한 영속 원본으로 사용한다.
- Lexical 편집기는 분할 원문 편집 없이 최종 문서 형태의 Notion형 WYSIWYG 경험을 제공한다.
- 슬래시 메뉴, 블록 추가·드래그, 텍스트 선택 플로팅 툴바를 제공한다.
- 지원 블록은 문단, 제목 1~3, 글머리·번호·할 일 목록, 인용, 코드 블록, 구분선, 기본 직사각형 GFM 표, 이미지다.
- 지원 인라인 서식은 링크, 굵게, 기울임, 취소선, 인라인 코드다.
- 표는 행·열 추가와 삭제, 셀 텍스트 편집만 지원하며 병합, 색상, 폭 저장과 중첩 블록을 제공하지 않는다.
- 저장 요청은 문서를 열 때 받은 강한 ETag를 `If-Match`로 보내야 한다.
- 제목·본문·검색 색인·버전 증가는 하나의 SQLite transaction에서 확정한다.
- ETag가 최신 버전과 다르면 `412 Precondition Failed`로 거부하고 최신 문서를 반환한다.
- 충돌한 로컬 본문을 자동 병합하거나 강제로 덮어쓰지 않는다.
- 다른 탭·기기의 변경은 탭 포커스 복귀와 화면 재진입 시 재조회한다.
- 오프라인 저장, 자동 저장, 브라우저 재시작 뒤 미저장 초안 복구와 사용자용 버전 기록은 제공하지 않는다.

### 이미지

- 이미지는 관리자 인증을 거쳐 Cloudflare R2에 문서 종속 자산으로 업로드한다.
- JPEG, PNG, WebP만 허용하고 파일당 최대 5MB로 제한한다.
- 서버는 실제 MIME 형식과 크기를 검증한다.
- 대체 텍스트는 필수다.
- SVG, GIF, 이미지 변환, 썸네일, OCR, 이미지 분석, 이미지 라이브러리와 여러 문서 간 재사용은 제공하지 않는다.
- AI 에이전트에는 이미지 binary 대신 대체 텍스트만 제공한다.

### 검색과 AI

- 관리자 검색과 AI 검색은 활성 문서의 제목과 Markdown 본문만 같은 SQLite FTS 경계에서 검색한다.
- 검색 결과는 문서 제목, 전체 경로와 짧은 본문 발췌를 표시한다.
- AI 검색 대상은 코스 제작용 학습 참고자료로 제한한다.
- AI는 Git, 코드, 프로젝트 문서와 개발·배포 환경을 검색하지 않는다.
- AI는 코드, Git, 아키텍처와 배포에 관한 질문에 자료실 내용을 프로젝트 사실로 사용하거나 답을 추정하지 않는다.
- AI는 자료실을 검색·조회해 변경안을 만들 수 있지만 직접 확정하지 않는다.
- 자료실 변경안은 관리자가 내용을 확인하고 승인한 뒤 현재 권한과 문서 버전을 다시 검증해 반영한다.
- AI는 영구 삭제를 제안하거나 실행하지 않는다.
- 모든 활성 문서는 게시·승인 상태 없이 AI가 읽을 수 있다.
- AI 답변은 실제로 읽은 자료 문서의 관리자 화면 링크를 출처로 표시한다.
- 임베딩과 벡터 데이터베이스는 제공하지 않는다.

### 가져오기와 내보내기

- 단일 `.md` 파일 가져오기를 지원한다.
- 첫 번째 H1이 있으면 제목으로 사용해 본문에서 제거하고, 없으면 파일명을 제목으로 사용한다.
- 문서별 Markdown 다운로드는 `# 제목`과 본문을 결합한다.
- 여러 파일, 폴더, ZIP과 전체 자료실 일괄 입출력은 제공하지 않는다.

## 권한과 기록

- 인증된 모든 관리자는 같은 자료실 조회·편집·구조 변경 권한을 가진다.
- 문서·폴더별 소유권과 ACL을 제공하지 않는다.
- 문서에는 생성자·수정자와 생성·수정 시각을 저장한다.
- 자료실 전용 감사 이력과 조회 UI는 제공하지 않는다.
- 영구 삭제 같은 중요 행동은 일반 구조화 로그에 기록한다.

## 화면 요구사항

- 데스크톱은 왼쪽 자료 트리와 오른쪽 문서 편집 영역을 표시한다.
- 편집기는 문서가 선택된 경우에만 동적 로드한다.
- 작은 화면은 읽기 전용 또는 데스크톱 편집 안내를 제공하고 모바일 편집과 드래그 앤 드롭을 제공하지 않는다.
- 미저장, 저장 중, 저장됨, 충돌과 저장 실패 상태를 구분한다.
- 문서가 선택되지 않음, 빈 트리, 검색 결과 없음, 휴지통 비어 있음과 조회 실패 상태를 구분한다.

## 확인 방법

- 최대 3단계 폴더 생성·이동과 더 깊은 이동 거부를 확인한다.
- 이름순 전체 트리와 드래그 앤 드롭 폴더 이동을 확인한다.
- 폴더 하위 구조의 휴지통 이동·복원·영구 삭제를 확인한다.
- 모든 지원 Lexical 블록의 Markdown 왕복 의미 보존을 확인한다.
- 같은 버전을 연 두 탭 중 먼저 저장한 요청만 성공하고 다른 요청이 `412`로 거부되는지 확인한다.
- 제목·본문·검색 색인·버전 증가가 원자적인지 확인한다.
- 이미지 형식·크기·대체 텍스트 검증과 R2 실패 관측을 확인한다.
- 관리자 검색과 AI 검색이 같은 활성 문서 집합을 반환하는지 확인한다.
- AI가 읽은 문서 링크를 답변에 표시하는지 확인한다.
- AI가 Git, 코드와 프로젝트 문서를 검색하거나 자료실 내용으로 개발 사실을 추정하지 않는지 확인한다.
- AI가 제안한 자료실 변경이 관리자 승인 전에는 반영되지 않고 승인 시 권한과 문서 버전을 다시 검증하는지 확인한다.
- 로컬 브라우저와 E2E에서는 `ENABLE_TEST_AUTH=true` 로그인을 사용한다.

## 비범위

- 실시간 공동 편집, 공동 커서와 작업 공간 WebSocket.
- 자동 저장, 오프라인 편집과 사용자용 버전 기록.
- 수동 트리 정렬과 1,000개 초과 지연 로딩.
- 모바일 편집.
- 이미지 라이브러리, 이미지 처리와 이미지 AI 분석.
- 의미 검색.
- 프로젝트 문서, 팀 위키와 시스템 운영 정책 관리.
- Git, 코드와 개발·배포 환경 검색 및 변경.
- 승인 없는 AI 변경과 AI를 통한 영구 삭제.
- 자료실 전용 감사 이력과 문서별 권한.
- 구형 Yjs 상태와 API의 호환 또는 데이터 이전.
