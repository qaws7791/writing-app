# REQ-ADM-7 감사 이력 조회

## 문서 정보

- 영역: 어드민
- 출처 유저 스토리:
  - `US-ADM-7` 감사 이력 확인
- 관련 화면:
  - `SCR-108` 감사 이력
- 관련 사용자:
  - 소유자 관리자
- 상태: 기준

## 목적

소유자 관리자가 개인정보 조회와 고위험 변경의 영속 감사 이력을 콘솔에서 확인해 운영 사고를 추적할 수 있게 한다.

## 기능 요구사항

- 감사 이력 화면은 이력을 최신순으로 제공한다.
- 조회는 기간과 작업 종류로 좁힐 수 있고 페이지 단위로 이동할 수 있다.
- 기간은 플랫폼 날짜 경계를 따르는 논리 날짜로 지정하며 시작일과 종료일을 모두 포함한다.
- 페이지 크기는 상한을 가지며 요청한 페이지가 전체 범위를 넘으면 마지막 페이지로 수렴한다.
- 각 이력은 실행 시각, 작업, 대상 종류, 결과를 표시한다.
- 작업과 대상 종류는 외부 계약의 식별자를 한국어 표기로 옮겨 표시한다.
- 결과는 `started`, `succeeded`, `failed`를 서로 구분해 표시한다.
- 종결되지 않은 `started` 이력은 조사가 필요한 상태로 구분할 수 있어야 한다.
- 요청 식별자를 함께 표시해 운영 로그와 연결할 수 있게 한다.
- 감사 이력은 어드민 주요 메뉴에서 이동할 수 있다.

## 화면 요구사항

- `PageHeader`, 필터, 감사 이력 table을 제공한다.
- 필터는 시작일, 종료일, 작업 종류를 제공하고 현재 조건을 화면에 남긴다.
- 페이지가 하나면 페이지 이동을 표시하지 않는다.
- 결과는 상태 pill로 표시하고 색상만으로 의미를 전달하지 않는다.
- 이력이 없으면 한국어 빈 상태를 표시하고, 필터 때문에 비었는지 이력 자체가 없는지 구분해 알린다.
- 조회 실패는 한국어 오류로 표시한다.

## 데이터 요구사항

- 감사 이력은 operations가 소유한 영속 감사 원장을 조회한다. 현재 조회 계약은 [감사 계약](../../../../packages/shared/contracts/src/operations/admin-audit.ts)이 소유한다.
- 응답에는 opaque actor·target 식별자만 포함하며 이메일, 이름, 학습 답안, AI 피드백 원문과 prompt를 포함하지 않는다.
- 보존 기한은 작업 종류에 따라 다르며 그 정책은 `docs/engineering/observability.md`를 따른다.
- 이 화면은 감사 이력을 생성·수정·삭제하지 않는다.

## 권한 / 접근 규칙

- 감사 이력 조회는 유효한 소유자 관리자 세션을 요구한다.
- 응답은 private no-store로 제공한다.

## 예외 / 오류

- 조회 실패 시 한국어 오류를 표시하고 다른 화면 요소를 대체하지 않는다.
- 허용 범위를 넘는 페이지 크기 요청은 잘못된 요청으로 처리한다.
- 시작일이 종료일보다 늦은 요청은 빈 결과가 아니라 잘못된 요청으로 처리한다.

## 비범위

- 대상·결과 필터.
- 감사 이력 내보내기와 외부 전송.
- 감사 이력 삭제·수정.
- 학습자 본인 열람.

## 확인 방법

- 사용자 상세를 조회한 뒤 감사 이력에 해당 조회가 남는지 확인한다.
- 코스 발행, 보관, 보관 해제 뒤 해당 이력이 남는지 확인한다.
- 결과가 `started`, `succeeded`, `failed`로 구분되어 표시되는지 확인한다.
- 기간과 작업 종류 필터가 결과를 좁히고, 종료일 당일 이력이 포함되는지 확인한다.
- 페이지를 이동해도 필터 조건이 유지되는지 확인한다.
- 응답과 화면에 이메일·이름·답안·피드백 원문이 없는지 확인한다.
- 이력이 없는 환경에서 빈 상태가 표시되는지 확인한다.
