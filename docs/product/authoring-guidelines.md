# 콘텐츠 집필 지침

## 목적

이 문서는 글쓰기 학습 콘텐츠(코스, 유닛, 레슨, 스텝)를 집필하는 원칙, 집필 페르소나, 분량 상한선, 문항 구성 규칙, 표준 시스템 프롬프트를 정의한다. 사람이 직접 집필하거나 AI 에이전트에게 집필을 지시할 때 이 문서를 단일 권위 기준으로 삼는다.

## 집필 페르소나

- 당신은 언어학, 교육심리학(특히 인지부하 이론, 간격 반복, 능동 회상), 게임 디자인에 정통한 콘텐츠 작가입니다.
- 딱딱한 교과서식 설명이 아니라, 스낵처럼 짧고 자주 씹을 수 있는(microlearning) 콘텐츠를 만듭니다.
- 학습자가 "실수해도 괜찮다"고 느끼게 만들며, 동시에 "조금 더 해보고 싶다"는 마음이 들게 설계합니다.

### 1. 모바일 학습 게임 수석 레벨 디자이너

- **목표**: 90초에서 3분 안에 끝나는 빠른 조작 리듬과 점진적 난이도 곡선을 설계한다.
- **품질 기준**: "빠진 지식이 없는가"가 아니라 "학습자가 손가락 조작을 통해 한 가지 판정을 체득했는가"를 본다.
- **행동 원칙**:
  - 긴 설명문은 화면 이탈을 유발하는 결함으로 취급한다.
  - 이론을 길게 설명하지 않고, 선택지를 누르고 순서를 맞추는 조작 활동으로 개념을 전달한다.
  - 레슨당 단 하나의 핵심 판정만 다루며 여러 개념을 한 세션에 섞지 않는다.

## 마이크로러닝 집필 불변식

모든 레슨과 스텝은 아래 불변식을 반드시 준수한다.

## 핵심 교육 원칙

### 1레슨 1판정 원칙

한 레슨 안에서는 오직 1개의 판정 축만 가르친다. 새로운 이론이나 예외를 추가하지 않고, 동일한 판정 기준을 다양한 일상 예문에 반복 적용하여 숙달하도록 만든다.

### 점진적 난이도

새 개념은 쉬운 인지 → 재인식 → 스스로 생성 순서로 난이도를 높입니다.

### 간격 반복

이전 레슨에서 배운 요소를 새 레슨에 자연스럽게 재등장시켜 복습을 유도합니다.

### 즉각적 피드백

정답/오답 여부를 즉시 알려주고, 오답일 경우 "왜 틀렸는지"를 1문장으로 짧게 설명합니다.

### 실생활 맥락

예문과 문제는 실제로 쓸 법한 상황(주문하기, 인사하기, 길 묻기 등)에서 가져옵니다. 인위적이거나 지나치게 학술적인 예문은 피합니다.

### 1레슨 1세계(상황) 원칙

- 한 레슨에 등장하는 모든 예문은 1개의 일상 상황 맥락 안에서 전개한다.
- 스텝마다 상황이 바뀌면서 발생하는 인지 전환 비용을 제거한다.

### 톤앤매너

- **친근하고 유쾌하게, 그러나 가볍지 않게.** 선생님보다는 재치 있는 친구에 가까운 톤을 사용합니다.
- 격려는 진심 어리게, 과장되거나 공허하게 들리지 않도록 합니다. ("완벽해요! 다음 레벨로 갈 준비가 됐어요" O / "우와아아 천재시네요!!!" X)
- 유머는 가끔, 짧게. 매 문장마다 개그를 치지 않습니다.
- 문화적으로 민감한 소재(정치, 종교, 외모, 신체)는 예문에서 배제합니다.

### 피드백 및 오류 메시지 작성 규칙

- **정답 시**: 짧고 다양한 긍정 표현 사용. 매번 같은 문구 반복 금지. (예: "정확해요", "바로 그거예요", "완벽!")
- **오답 시**:
  1. 정답을 먼저 명확히 보여줍니다.
  2. 왜 틀렸는지 1문장으로 핵심만 짚습니다. (문법 용어 남발 금지)
  3. 필요 시 정답을 다시 한번 자기 손으로 입력하게 유도합니다.
- 절대 학습자를 비난하거나 실망시키는 표현("또 틀렸어요", "이걸 왜 몰라요")을 쓰지 않습니다.

### 절대 하지 말아야 할 것

- 한 문제에 두 가지 이상의 새로운 개념을 동시에 넣지 않습니다.
- 정답이 모호한 문제를 내지 않습니다.
- 한 레슨 안에서 객관식 정답 위치, 빈칸 정답 ID 패턴, 참거짓 참/거짓 값이 한쪽으로 몰리지 않습니다. 임계값과 검사는 [`answer-distribution.ts`](../../packages/shared/contracts/src/content/authoring/answer-distribution.ts)가 소유합니다.
- 학습자 화면에 보이는 보기·낱말·타일 순서는 저작 JSON 순서가 아닙니다. 문장 조립 타일은 정답 문장 순으로 두어도 됩니다.
- 참거짓 정답은 버튼 위치가 아니라 참·거짓 값입니다. 거짓만 반복해서 내지 않습니다.
- `content-seed-data.json`에 넣는 코스는 `content:validate -- seed --course=<코스-id>`로 집필 검사를 통과해야 합니다.
- 지나치게 긴 지문이나 설명(3문장 이상의 문법 해설)을 문제 중간에 넣지 않습니다. 설명은 별도 "팁" 섹션으로 분리합니다.
- 실제 브랜드명, 실존 인물, 민감한 시사 이슈를 예문 소재로 사용하지 않습니다.

### 분량 상한선

최소·최대 글자 수와 스텝 수 상한은 [`authoring-limits.ts`](../../packages/shared/contracts/src/content/authoring/authoring-limits.ts)가 소유한다. 아래 표는 의도 요약이며, 검증 실패 판정은 `lessonStepDtoSchema` 파싱 결과를 따른다.

| 영역                 | 글자 수 (공백 포함) | 필수 규칙                                                      |
| :------------------- | :------------------ | :------------------------------------------------------------- |
| `READING` 본문       | 20~150자            | 레슨당 최대 1개 스텝으로 제한하며, 정의와 핵심 차이 1개만 제시 |
| 문항 지시문          | 4~20자              | 무엇을 골라야 하는지 한눈에 드러나는 간결한 행동 지시          |
| `explanation` (해설) | 4~40자              | 정답 라벨 단순 반복 금지, 선택지를 가른 1줄 직관 이유 제공     |

### 행동 중심 통과 기준

- 메타언어(이론 명칭, 규칙 전문)를 외워서 맞추는 문항을 금지한다.
- 어색한 문장에서 불필요한 단어를 직접 골라내거나 올바른 단어로 교체하는 조작 행동 자체를 통과 기준으로 삼는다.

### 표준 스텝 배치 템플릿 준수

- 모든 레슨은 [레슨 스텝 배치 템플릿](./lesson-step-templates.md)에 정의된 60종의 8~15스텝(기본 12스텝) 표준 배치를 준수한다.
- 레슨 집필 시 템플릿이 지정한 스텝 타입 순서와 인지 난이도 오름차순 곡선을 임의로 변경하지 않는다.
- 중간 `READING` 배치는 엄격히 금지되며, 세션 마무리는 항상 수행 중심 조작 스텝으로 완결한다.
