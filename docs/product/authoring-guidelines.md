# 콘텐츠 집필 지침

## 목적

이 문서는 레슨과 스텝을 집필·리뷰하는 단일 권위 기준이다. 사람과 에이전트(`.agents/agents/lesson-author.md`, `.agents/agents/lesson-reviewer.md`)는 이 문서를 따르고, 이 문서와 어긋나는 규칙을 따로 두지 않는다.

숫자 기준은 코드가 소유한다.

- 글자 수·개수 상한: [`authoring-limits.ts`](../../packages/shared/contracts/src/content/authoring/authoring-limits.ts)
- 의미 품질 기준과 오류·경고 목록: [`lesson-quality-rules.ts`](../../packages/shared/contracts/src/content/authoring/lesson-quality-rules.ts), [`answer-distribution.ts`](../../packages/shared/contracts/src/content/authoring/answer-distribution.ts), [`unit-authoring-rules.ts`](../../packages/shared/contracts/src/content/authoring/unit-authoring-rules.ts)
- 금지 브랜드 목록: [`forbidden-terms.ts`](../../packages/shared/contracts/src/content/authoring/forbidden-terms.ts)
- 레슨 브리프 스키마: [`authoring-work-order.ts`](../../packages/modules/content/src/authoring/authoring-work-order.ts)

## 학습자와 톤

- 학습자는 20~30대 성인이다. 업무 메시지, 보고서, 자기소개서, 블로그 글을 쓸 때 문장이 어색하지 않을까 불안해한다.
- 모든 집필자 문장(지시문, 해설, 비교 분석, 읽기 본문)은 해요체로 쓴다. 합니다체와 해라체는 학습자가 판정하는 예문 안에서만 허용한다.
- 톤은 실무 글쓰기를 코칭하는 동료 에디터다. 유아적 어투(`~해볼까요?`, `참 잘했어요!`, `~랍니다`)와 과장된 칭찬을 쓰지 않는다.
- 문법 용어(어간, 보조사, 관형사형 전성어미)로 설명하지 않는다. 바꿔 읽기 공식('~ 자격으로'로 읽히면 로서)으로 설명한다.

## 레슨 설계 원칙

1. 1레슨 1판정. 한 레슨은 판정 축 하나만 가르친다. 새 이론과 예외를 추가하지 않는다.
2. 1레슨 1세계. 한 레슨의 모든 예문은 한 사람이 쓰는 한 편의 글(메시지·보고서·자기소개서·에세이)에서 나온다. 스텝마다 장면을 바꾸지 않는다.
3. 시나리오 우선. 집필은 장면과 대립쌍(어색한 문장·바른 문장 6~8쌍)을 먼저 정하고, 그 문장을 스텝에 배치한다. 스텝 유형에 맞춰 문장을 새로 만들지 않는다.
4. 앵커 필수. 첫 스텝은 `compare` 또는 `reading`이다. 학습자는 판정 축을 본 뒤에 첫 판정을 한다.
5. 난이도 오름차순. 인식(`compare`, `true_false`)에서 변별(`select`, `fill_blank`, `categorize`, `match`, `order`)로, 다시 생성·교정(`error_correct`, `sentence_build`)으로 올라간다. `error_correct`와 `sentence_build`는 4번째 스텝부터 배치한다.
6. 수행 마무리. 마지막 스텝은 학습자가 문장을 직접 고치거나 완성하는 스텝이다. `multiple_choice`로 끝내지 않는다.
7. 간격 반복. 브리프의 `forbidden` 항목을 지키고, 같은 유닛의 형제 레슨과 판정 축·장면을 겹치지 않는다.
8. 템플릿은 권장 배치다. [레슨 스텝 배치 템플릿](./lesson-step-templates.md)의 60종은 스텝 유형 조합의 출발점이고, 검증기가 강제하는 것은 위 원칙이다.

## 스텝 작성 규칙

### 지시문과 판정 문장

- `question`은 학습자가 지금 무엇을 판정하는지 장면 안에서 말한다. 예: "이 문장을 그대로 올려도 되나요?", "정산 안내 줄에서 조사가 어긋난 자리는?".
- `true_false`의 `statement`는 장면 속 실제 문장 하나다. 규칙 진술("수식어를 걷어내면 호응이 보인다")을 참·거짓으로 묻지 않는다.
- 참·거짓, 선택지 위치, 구간 위치는 한쪽으로 몰리지 않는다.

### 선택지와 오답

- `multiple_choice` 선택지는 3개 이상이다.
- 오답은 브리프 `distractorRules.allowed`에 적은 방식으로만 만든다. 오답은 이 레슨의 판정 축을 몰라야 틀리는 문장이어야 한다. 축과 무관하게 비문인 오답, 억지 띄어쓰기, 존재하지 않는 형태를 오답으로 두지 않는다.
- 두 자리에 모두 허용되는 표현을 오답으로 두지 않는다. 정답이 둘로 읽히는 문항은 결함이다.
- `select` 구간은 4개 이상이다. 문장을 어절 단위로 나눠, 판정 축을 모르면 어느 구간인지 보이지 않게 한다. 뒤 절이나 서술어를 통째로 한 구간에 두지 않는다.
- 판정 축이 문장 끝(서술어·꼬리)을 겨냥하면 `select`·`error_correct`의 정답이 늘 마지막 구간이 된다. 바른 문장을 앞이나 뒤에 이어 붙여 정답 구간이 중간에 오게 하거나, 조사·주어 자리를 고치는 문장을 섞어 위치를 바꾼다.
- `error_correct` 교정안은 3개 이상이고, 원문 구간을 그대로 넣지 않는다. 오답 교정안은 조사·표기를 그대로 둔 채 동사나 수식어만 바꾼 "오진 교정안"으로 만든다. 세 교정안은 구조가 서로 달라야 한다. 부사 하나만 다른 쌍둥이 오답 둘과 홀로 다른 정답 하나는 정답을 드러낸다.
- `sentence_build` 타일은 정답 어순이 하나뿐이어야 한다. 자리를 바꿔도 뜻이 같은 부사구·부사어는 타일 하나로 합친다. 채점은 `correct` 순서와의 완전 일치다.
- 한 문장은 한 방향으로 한 번만 판정한다. 앞 스텝의 정답 문장이나 해설에 나온 교정 문장을 뒤 스텝의 정답으로 다시 묻지 않는다. 해설에 뒤 스텝의 정답 낱말을 미리 쓰지 않는다.
- 지시문에 답을 넣지 않는다. "고친 문장, 보내도 되나요?"처럼 참을 미리 말하는 지시문은 결함이다.
- 첫 스텝의 `title` 또는 `analysis`에서 글쓴이, 글의 종류, 독자를 한 번 밝힌다. 해설에서 글쓴이 이름을 쓰려면 이 소개가 먼저 있어야 한다.

### 해설

- 해설은 "[장면 속 이유] + [바꿔 읽기 공식 또는 판정 결과]" 두 문장 안에서 쓴다. 예: "막내는 지우의 자격이라 '막내 자격으로'로 읽혀요. 수단이 아니니 '막내로서'로 고쳐요."
- 정답 인용만 반복하는 해설("'로서'가 맞아요.")과 같은 앞머리를 세 번 이상 반복하는 해설은 결함이다.

### 소재

- 실제 브랜드·서비스 이름, 실존 인물, 시사 이슈를 쓰지 않는다. "팀 대화방", "메신저", "문서 도구"처럼 일반 명사로 쓴다.
- 정치, 종교, 외모, 신체는 소재로 쓰지 않는다.

## 레슨 브리프

집필 에이전트는 `work-orders.json`의 브리프 하나만 받는다. 브리프는 다음을 담는다.

| 필드              | 내용                                                              |
| :---------------- | :---------------------------------------------------------------- |
| `title`, `thesis` | 시드의 레슨 `title`, `desc`와 같은 문장                           |
| `judgementAxis`   | 학습자가 적용할 판정 공식 한 문장                                 |
| `scene`           | 글쓴이, 글의 종류, 독자, 문장 개수                                |
| `contrastPairs`   | 어색한 문장·바른 문장 6~8쌍. 첫 `compare`와 모든 판정 스텝의 원천 |
| `distractorRules` | 허용 오답 방식과 금지 오답 방식                                   |
| `forbidden`       | 형제 레슨과 겹치는 판정·장면 목록                                 |
| `closing`         | 마지막 스텝이 완성하는 문장과 방식                                |
| `template`        | 권장 배치 ID(선택). 검증기는 강제하지 않는다                      |

## 검증과 리뷰

1. 집필자는 `bun run content:validate -- lesson <레슨-json>`을 실행한다. 오류 0건이어야 리뷰로 넘긴다. 경고는 리뷰어가 판정한다.
2. 리뷰어는 아래 열 문항에 모두 "예"여야 통과시킨다. "아니오"가 하나라도 있으면 스텝 번호와 이유를 적어 반려한다.

| 번호 | 리뷰 문항                                                               |
| :--: | :---------------------------------------------------------------------- |
|  Q1  | 첫 스텝만 보고 학습자가 판정 축을 한 문장으로 말할 수 있는가            |
|  Q2  | 모든 스텝이 브리프의 장면 한 편 안에서 이어지는가                       |
|  Q3  | 모든 문항이 판정 축을 몰라야 틀리는가(축과 무관한 비문 오답이 없는가)   |
|  Q4  | 정답이 둘로 읽히는 문항이 없는가                                        |
|  Q5  | `select`·`error_correct`의 정답 위치가 문장을 읽지 않고는 보이지 않는가 |
|  Q6  | 해설이 정답을 반복하지 않고 장면 속 이유를 말하는가                     |
|  Q7  | 모든 집필자 문장이 해요체이고 유아적 어투가 없는가                      |
|  Q8  | 브랜드·서비스 이름과 사전 배경지식 요구가 없는가                        |
|  Q9  | 시드 `title`·`desc`가 실제로 가르치는 내용과 같은가                     |
| Q10  | 마지막 스텝이 브리프 `closing`의 문장을 학습자 손으로 완성하는가        |

3. 시드에 넣는 코스는 `bun run content:validate -- seed --course=<코스-id>`를 오류 0건으로 통과해야 한다.

## 분량 상한선

상한은 [`authoring-limits.ts`](../../packages/shared/contracts/src/content/authoring/authoring-limits.ts)가 소유한다. 상한의 의도는 다음과 같다.

- 선택지, 판정 문장, 구간, 교정안은 실전 문장을 조각내지 않고 그대로 담을 수 있어야 한다.
- 해설과 비교 분석은 이유 한 문장과 공식 한 문장을 담을 수 있어야 한다.
- `reading` 본문은 판정 축 하나와 예문 한 쌍만 담는다. 레슨당 최대 1개, 첫 스텝에만 둔다.
