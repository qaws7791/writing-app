# 지표

## 핵심 제품 지표

- 첫 레슨 시작: 가입한 학습자가 처음으로 레슨 시작 상태를 서버에 확정한 사건이다. 페이지 조회나 시작 화면 노출은 포함하지 않는다.
- 활성화율: 삭제 상태가 아닌 전체 학습자 중 첫 레슨 시작이 있는 학습자의 비율이다. 분자는 학습자별 `started_at` 최솟값이 있는 수, 분모는 삭제 상태가 아닌 전체 학습자 수다.
- 7일 내 재방문: 첫 레슨 시작의 `Asia/Seoul` 논리 날짜 다음 날부터 7일째까지 인증된 학습 활동을 한 학습자다. 같은 날의 반복 활동과 단순 로그인은 포함하지 않는다.
- 첫 시작과 재방문은 사용자 단위로 중복 제거하며, 운영 화면은 비율과 함께 분자·분모와 집계 기간을 표시한다. 비율은 0부터 100까지의 백분율로 소수 첫째 자리에서 반올림한다.
- 재방문 분모는 보고 기준일 전에 D1부터 D7까지 7개 논리 날짜가 모두 끝난 cohort만 포함한다. 따라서 보고 기준일이 `2026-07-24`이면 `2026-07-16`까지 첫 시작한 cohort가 성숙했다. 첫 시작 날짜는 `started_at`의 최솟값, 재방문은 `learner_activity_days.activity_date`로 계산한다.
- 관리자 계정은 별도 identity table이므로 대상이 아니며, 삭제 상태 학습자는 분자와 분모에서 제외한다. production에는 bot 계정을 만들지 않고 test-auth fixture는 production 집계 DB에 존재하지 않는다.

| 보고 기준일 | 학습자 | 첫 시작    | 이후 활동          | 집계 결과          |
| ----------- | ------ | ---------- | ------------------ | ------------------ |
| 2026-07-24  | A      | 2026-07-10 | 2026-07-11         | 분모·분자 포함     |
| 2026-07-24  | B      | 2026-07-10 | 같은 날만 활동     | 분모만 포함        |
| 2026-07-24  | C      | 2026-07-20 | 2026-07-21         | 아직 분모에서 제외 |
| 2026-07-24  | D      | 2026-07-10 | 2026-07-12, 삭제됨 | 모두 제외          |

위 예시의 성숙 cohort는 2명, 7일 내 재방문은 1명으로 재방문율은 50%다. 모든 날짜 변환은 UTC timestamp에 `Asia/Seoul` 경계를 적용한다.

## 현재 표시 지표

- 대시보드: 삭제 상태를 제외한 총 사용자.
- 대시보드: 보고 기준일과 직전 6개 논리 날짜에 인증된 학습 활동이 있는 최근 7일 활성 사용자.
- 대시보드: 누적 첫 레슨 시작 수와 활성화율의 분자·분모.
- 대시보드: 성숙 cohort의 7일 내 재방문율과 분자·분모. 첫 시작이 없으면 `empty`, 첫 시작은 있지만 성숙 cohort가 없으면 `immature`로 구분한다.
- 대시보드: 삭제 상태를 제외한 누적 완료 레슨.
- 현재 연속 학습일.
- 완료한 레슨 수.
- 전체 진도.

## 현재 분석 지표

- 일별 가입 수는 학습자 가입 날짜에, 첫 시작 수는 학습자별 최초 시작 날짜에 기록한다.
- 일별 완료 수는 레슨 완료 날짜에 기록한다.
- 일별 재방문 수는 첫 시작 cohort 날짜에 귀속한다. D7 관찰 기간이 끝나지 않은 cohort의 값은 `0`이 아니라 `immature`와 `null`로 표현하고, 성숙했지만 cohort가 없으면 `empty`로 표현한다.
- 레슨별 시작 수.
- 레슨별 완료 수.
- 레슨별 완료율.
- 레슨별 이탈률.
- AI 품질은 기간 내 요청·성공·실패, 실패 code, latency, token과 retry만 집계하며 답안과 피드백 원문을 반환하지 않는다. 요청이 없으면 성공률 `0%`와 구분되는 `empty` 상태를 사용한다.
- AI 실패율 상위 레슨은 현재 활성 코스의 최신 published curriculum에 포함된 active 레슨 중 조회 시작일부터 종료일까지의 `Asia/Seoul` 논리 날짜에 실패가 있는 레슨을 최대 8개 제공한다. 요청 수는 삭제 상태가 아닌 학습자의 저장된 attempt 수, 실패 수는 `failed | expired` attempt 수이며 실패율은 실패 수를 요청 수로 나눠 소수 첫째 자리까지 반올림한다.
- 같은 실패율은 실패 수, 요청 수 내림차순 뒤 코스 제목, 레슨 제목, 코스 ID, 레슨 ID 오름차순으로 결정한다. 요청이나 실패가 0인 레슨은 표에 포함하지 않는다.

## AI 서비스 품질 지표

- 요청 수는 집계 기간에 새로 저장된 AI 코칭 attempt 수다. 같은 idempotency key의 재전송으로 새 attempt가 생기지 않으면 중복 계산하지 않는다.
- 성공률은 같은 기간의 `succeeded` attempt 수를 요청 수로 나눈 값이다. 요청이 없는 구간은 성과 0%와 구분하기 위해 `empty` 상태와 `null` 성공률로 표현한다.
- 실패는 정규화한 실패 code별로 집계한다. latency는 값이 기록된 attempt만, token은 사용량이 기록된 provider 응답만 표본에 포함한다.
- 재시도 수는 집계 기간에 생성된 attempt 중 같은 학습자·curriculum version·레슨·스텝의 저장된 시도 번호가 2 이상인 건수다.
- 서비스 품질 집계에는 답안, prompt와 AI 피드백 원문을 포함하지 않는다.
- 사용자별·전체 일일 한도의 설정값은 제품 성공 기준이나 사용자 entitlement가 아니다. 현재 기본값은 비용·남용 방지용 엔지니어링 추론이며, 실제 요청량·성공률·비용을 관찰한 뒤 별도 제품 승인으로 조정한다.

## 운영 판단 기준

- 활성 사용자 대비 완료 레슨이 낮으면 레슨 진입 흐름을 점검한다.
- 시작 수 대비 완료율이 낮은 레슨은 콘텐츠 난이도를 점검한다.
- 연속 학습일 분포가 낮으면 홈과 다음 레슨 흐름을 점검한다.
- 가입은 늘지만 첫 레슨 시작이 낮으면 로그인 후 첫 코스 선택 흐름을 점검한다.
