# 제품 문서 인덱스

## 목적

이 문서는 제품 문서의 진입점이다. 제품이 해결하는 문제, 목표, 사용자, 유저 스토리, 요구사항, 콘텐츠, 운영 기준을 찾기 위해 사용한다.

## 탐색 순서

1. 확정 제품 범위는 `product-scope.md`에서 확인한다.
2. 제품의 이유와 방향은 `problem-definition.md`, `product-vision.md`에서 확인한다.
3. 사용자 기준은 `personas.md`에서 확인한다.
4. 사용자 가치와 인수 기준은 `user-stories/_index.md`에서 시작해 개별 유저 스토리 문서에서 확인한다.
5. 개발자를 위한 제품 규칙은 `requirements/_index.md`에서 시작해 개별 요구사항 문서에서 확인한다.
6. 화면 목적과 UI 기준은 `docs/design/screens/`의 개별 화면 문서에서 확인한다.
7. 학습 상태 책임과 레슨 전이 흐름은 `learner-journey.md`에서 확인한다.
8. 콘텐츠, 운영, 지표 기준은 `content-model.md`, `admin-operations.md`, `metrics.md`에서 확인한다.

## 디렉토리 지도

| 경로                         | 목적                                                           |
| ---------------------------- | -------------------------------------------------------------- |
| `docs/product/`              | 제품 문제, 비전, 사용자, 콘텐츠, 운영 기준을 관리한다.         |
| `docs/product/user-stories/` | 유저 스토리를 플랫폼과 어드민으로 나누어 개별 파일로 관리한다. |
| `docs/product/requirements/` | 요구사항을 플랫폼과 어드민으로 나누어 개별 파일로 관리한다.    |

## 관리 기준

- 제품 요구사항이 바뀌면 관련 유저 스토리, 요구사항, 화면 명세를 함께 확인한다.
- 유저 스토리는 사용자 가치와 인수 기준까지만 책임진다.
- 요구사항은 기능, 화면, 데이터, 권한, 오류, 비범위를 개발자가 구현 판단할 수 있는 수준으로 책임진다.
- 화면 구조와 UI 기준은 `docs/design/screens/`의 개별 화면 문서를 단일 기준으로 삼는다.
- 디자인이나 엔지니어링 문서가 제품 기준과 충돌하면 제품 문서를 먼저 갱신하고 하위 구현 문서를 따라 맞춘다.
- 제품 문서의 진입점은 `_index.md` 하나만 유지한다.
