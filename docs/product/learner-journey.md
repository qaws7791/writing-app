# 학습자 학습 여정

## 권위 범위

학습자는 고정 curriculum revision의 active 레슨을 순서와 관계없이 시작하고, 서버가 가리키는 현재 스텝을 완료한다. 서버는 학습자의 고정 curriculum revision, 현재 스텝, 채점, 다음 스텝 해제, 레슨·코스 완료와 충돌 판정을 소유한다. 클라이언트는 이를 다시 계산하지 않고 서버 전이 결과를 화면 상태로 반영한다.

## 상태 책임

| 소유자     | 책임                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 서버       | revision, 현재 스텝, 답안 검증과 채점, 다음 스텝, 레슨·코스 완료, draft version 충돌      |
| 클라이언트 | loading, editing, saving, checking, advancing, 복구 가능한 오류와 아직 전송하지 않은 입력 |

클라이언트 machine event는 화면 상호작용을 표현하는 내부 계약이고, 서버 transition DTO는 저장된 학습 사실을 표현하는 wire 계약이다. 두 계약을 같은 상태로 취급하거나 클라이언트 event에 서버 비즈니스 결정을 넣지 않는다.

## 레슨 흐름

1. 고정 curriculum revision의 active 레슨을 조회한다.
2. 시작 응답의 현재 스텝과 서버 draft를 복구한다.
3. 상호작용형 스텝은 타입별 draft와 답안을 stable item ID로 저장·제출한다. `READING`과 `COMPARE`는 확인 동작만 전송하고 draft를 만들지 않는다.
4. 오답 여부와 해설은 서버 evaluation만으로 표시한다. 낙관적으로 유지한 입력도 서버 응답이 오면 저장 상태·version·평가를 기준으로 조정한다.
5. `advanced`이면 서버가 준 현재 스텝으로 이동하고, `lesson_completed`이면 서버가 확정한 완료 화면으로 이동한다.

## 동기화 정책

- 시작, draft 저장, 답안 제출 같은 사용자 action은 항상 서버 동기화를 동반한다.
- 창이 다시 focus되거나 네트워크가 reconnect되면 즉시 서버 상태를 확인한다.
- 주기 동기화는 화면이 visible인 동안에만 저빈도로 한 건씩 수행하고, hidden 상태에서는 대기 중인 입력을 flush한다. 같은 스텝의 중복 요청은 만들지 않는다.
- 서버에서 다시 읽은 revision, 현재 스텝, 평가, 완료와 draft version은 로컬의 같은 서버 파생 상태를 대체한다.
- 네트워크 오류나 version 충돌이 발생해도 아직 전송하지 않은 사용자 입력은 지우지 않는다. 최신 서버 draft와 로컬 미전송 값을 함께 제시해 재시도하거나 사용자가 선택해 복구할 수 있게 한다.

## 쓰기 세션

서버는 글의 고정 발행본, 본문 version, 최근 성공 점검, 하루 점검 한도와 고지 확인을 소유한다. 클라이언트는 미전송 본문과 화면 상태만 소유하고 점검 결과를 다시 계산하지 않는다.

1. 카탈로그 `시작하기`는 최신 발행본에 고정된 새 글을 만든다.
2. 홈에서 이어 열면 고정 브리프와 저장된 본문을 복구한다.
3. 본문 저장은 expected version을 비교한다. 본문이 바뀌어도 최근 성공 점검 1건은 남는다.
4. `점검하기`는 서버가 저장한 본문을 외부 AI에 전달한다. 최소 글자, 하루 성공 한도, 고지 확인을 서버가 거절하면 점검을 시작하지 않는다.
5. 새 성공 점검은 최근 1건을 바꾼다. 학습자는 그 결과를 다시 열 수 있다.
