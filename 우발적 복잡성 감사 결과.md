# 우발적 복잡성 감사 결과

완료된 항목은 ID 앞에 ✅를 붙입니다.

## 요약

모듈 경계·의존성 게이트·인증 분리는 대체로 문서 계약과 코드가 맞습니다. 우발적 복잡성의 중심은 **2026-09-01 클라이언트 즉시 채점 전환 이후에도 서버 `completeStep` 경로와 채점 구현이 이중으로 남은 것**, 그리고 **확정 스텝 11종·채점 소유자가 권위 문서와 코드에서 서로 다른 것**입니다. 없애면 안 되는 복잡성은 11종 스텝·발행 고정·역할 분리·쓰기 AI 점검이며, 단기에는 문서 정합·죽은 `completeStep` 표면 제거·관리자 미리보기 3타입 보완이 우선입니다.

## 본질적 복잡성

아래는 글쓰기 학습 플랫폼이라서 **없애면 제품이 성립하지 않는** 복잡성입니다. 구현 습관으로 생긴 레이어와 혼동하지 않습니다.

클라이언트 0ms 채점 자체는 **제품 결정**(커밋 `7a0f0d43`)입니다. 정답 키를 학습자 레슨 DTO에 실어 보내는 것(`presentLearnerStep`)은 그 결정의 대가이지, 실수로 생긴 레이어가 아닙니다. 없앨 대상은 그 결정과 **병행하는 옛 서버 스텝 완료 경로**입니다.

## 구조 요약

- **앱:** `apps/web`(학습자), `apps/admin`(관리자), `apps/api`(HTTP·MCP), `apps/ui`(UI 문서)
- **모듈:** content, learning, writing, identity, operations
- **공유:** contracts, kernel, ui
- **학습자 레슨 흐름:** 웹은 `evaluateStepSubmission` + `completeLesson`만 호출합니다. HTTP `POST .../steps/{stepId}/complete`와 저장소 `completeStep`은 제거했습니다.

순환 의존성은 `dependency-cruiser.config.mjs`의 `no-circular-runtime-dependencies`가 runtime cycle을 error로 둡니다. 이 분석에서 `bun run check:architecture`는 재실행하지 않았습니다.

## 우선순위별 개선 로드맵

### 단기 (문서·죽은 표면, 회귀 낮음)

1. **권위 문서를 코드에 맞춥니다.** product-scope·REQ-ADM-3·frontend-development·learner-journey·lesson-session-state-machine·package-interface(`event-bus`). 채점 소유자와 스텝 11종을 한 세트로 고정합니다.
2. **관리자 `renderStepPreview`에 3타입을 넣고** 학습자 렌더러와 같은 exhaustiveness를 강제합니다.
3. **웹 `completeStep` 어댑터와 `evaluatedByServer`를 제거**합니다. HTTP 경로 삭제는 OpenAPI/Orval 재생성이 따르므로 다음 단계와 묶어도 됩니다.
4. **`listPublishedCourses` 반복 조회를 제거**합니다.

### 중기 (이중 유스케이스 제거)

1. 제품이 클라이언트 채점을 유지하는지 한 문장으로 확정합니다.
2. 유지한다면 **`POST .../steps/{stepId}/complete`와 `planCompleteStep`/`gradeLearnerStep`를 삭제**하고 채점 정본을 `evaluateStepSubmission`(또는 그 후속 한 함수)만 남깁니다.
3. 지표 무결성이 필요하면 **`completeLesson`이 answers를 재채점**하게 하고, 웹이 answers를 보내게 합니다. 불필요하면 schema에서 미사용 필드를 지웁니다.
4. ADR-0025와 content extra export, DTO 별칭 금지를 문서 또는 코드 중 한쪽에 맞춥니다.

### 장기 (큰 파일·카탈로그)

1. content/learning drizzle repository를 유스케이스 파일로 나눕니다. completeStep 삭제 이후에만 합니다.
2. TS6 호환 패키지, 제품 미사용 UI 카탈로그는 도구/디자인 계약이 바뀔 때 제거합니다.
3. OpenAPI `contractOnly` 스텁은 생성 파이프라인을 바꾸지 않는 한 손대지 않습니다.

## 리스크 및 주의사항

- **completeStep HTTP를 외부 클라이언트가 쓰고 있는지** 이 저장소의 웹/E2E만으로는 단정할 수 없습니다. 삭제 전에 OpenAPI 소비자와 로그를 확인합니다. **확인 필요.**
- 정답 키를 클라이언트에 주는 모델을 유지한 채 서버 경로만 지우면, **치팅보다 UX가 우선**이라는 제품 전제가 남습니다. 인증 시험이 되면 AC-1-03을 먼저 고칩니다.
- 문서만 고치고 이중 경로를 남기면 다음 작업자가 서버 채점을 다시 구현할 수 있습니다. **문서와 삭제를 같은 작업 단위로** 둡니다.
- First Principles는 작은 로컬 변경을 선호합니다. content-drizzle 1800줄 분할을 채점 이중화 제거보다 앞에 두지 않습니다.
- 작업 로그는 현재 구조가 아닙니다. archive의 ai-feedback 모듈·event-bus를 현재형으로 인용하지 않았습니다.
- 순환 의존성·knip 미사용 dependency의 **현재 위반 0**은 설정과 CI 존재로만 추론했습니다. 게이트 재실행 결과는 **확인 필요**입니다.
